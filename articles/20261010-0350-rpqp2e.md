個人開発を始めたばかりの頃、毎回同じコマンドを手打ちしていたり、エラーの原因を1から調べたりして時間がかかっていました。決めておくことでこれらの手間を省き、開発に集中できる方法があります。7 つのポイントをご紹介します。

## GitHub CLI で PR が楽になる
Issue を確認した後、手動で `git push origin main` を実行し、GitHub の UI を開いて PR を作成するのを繰り返していました。`gh pr create --title "Fix bug" --body "Description"` と `gh pr list` を使うことで、これらの手順がシェル内で完結します。`gh` をインストールし、認証を設定するだけで、コードレビューがスムーズになります。結果、PR の作成時間が 80% 短縮され、ブランチの切り替えもストレスフリーになりました。

## Hugo でブログがサクサク作成
開発ログを HTML を書きながら更新していたため、レイアウト崩れやリンク切れが頻繁に発生していました。`hugo new post/hello.md` と `hugo server` を使うと、Markdown でコンテンツを作成し、プレビューを即座に確認できます。静的サイトジェネレータにより、サイトの公開準備も一瞬で完了します。更新作業が 90% 短縮され、サイトの安定性も向上しました。

## .env ファイルで設定管理が楽に
API キーやデータベースの接続文字列をコードに直接書いていたため、秘密情報がリポジトリに漏洩するリスクがありました。`.env` ファイルと `dotenv` を組み合わせることで、`require('dotenv').config()` 1 行で環境変数を読み取れます。`.gitignore` に `.env` を追加するだけで、設定が整理され、安全性が向上します。設定の切り替えも簡単になり、開発と本番環境の差異が明確になりました。

## Husky でコミット前にチェック
フォーマットや lint を実行し忘れることがあり、エラー付きのコードがプッシュされることがありました。`npm install --save-dev husky lint-staged` をインストールし、`package.json` に `"husky install"` と `"lint-staged ."` を追加することで、コミット時に `eslint` や `prettier` が自動実行されます。`prepare` スクリプトを設定するだけで、コードの品質が一定に保たれ、後々のリファクタリングが楽になりました。

## AWS CLI でクラウド操作が簡単化
S3 バケットや EC2 インスタンスを管理する際に、AWS コンソールでクリックを繰り返す必要がありましたが、`aws configure` で認証情報を設定し、`aws s3 ls s3://my-bucket` で操作できるようになりました。コマンドラインから同じ操作が可能になり、スクリプト作成も容易です。結果、インフラ操作の時間が 70% 短縮され、バージョン管理も簡単になりました。

## Docker Compose でDBを簡単に起動
ローカル開発環境で MySQL を使う際、手動でインストールして設定を記述し、サービスを起動する必要がありました。`docker-compose.yml` に DB サービスを記述し、`docker-compose up -d` を実行するだけで、データベースが起動します。初期設定が数分で完了し、チームメンバーも同じ環境を即座に再現できます。開発の開始時間が 90% 短縮されました。

## GitHub Actions で自動デプロイ
Vercel へのデプロイを毎回手動で行っており、更新のたびに時間がかかっていました。`.github/workflows/deploy.yml` を作成し、`vercel deploy --prod` を実行するジョブを追加するだけで、コードプッシュごとに自動的に本番環境にデプロイされるようになりました。設定は YAML ファイル1つで完結し、CI/CD パイプラインが構築されました。デプロイ作業はほぼゼロになり、機能追加に集中できるようになりました。

## まとめ
個人開発をスタートさせる前に、これらのツールやワークフローを事前に選んでおくことで、日々の作業が劇的に効率化されます。まずは 1 つ試してみて、快適な開発環境を手に入れましょう。
