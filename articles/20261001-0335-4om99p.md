## エラー事例と対処法

### 1. useEffectの依存配列を忘れる

**問題点**
```jsx
function Counter() {
  const [count, setCount] = useState(0);

  useEffect(() => {
    const timer = setInterval(() => {
      setCount(count + 1);
    }, 1000);
    return () => clearInterval(timer);
  }); // ←依存配列なし
}
```

依存配列を書かないと、**常に再実行**され、無限ループに陥ります。

**対処法**
```jsx
useEffect(() => {
  const timer = setInterval(() => {
    setCount(prev => prev + 1);
  }, 1000);
  return () => clearInterval(timer);
}, []); // ←依存配列を空に
```

状態更新は`prev`を使うことで、依存配列の肥大化を防げます。

---

### 2. 不要な再レンダーが頻発する

**問題点**
```jsx
function Parent() {
  const [data, setData] = useState([]);

  return (
    <Child items={data} onUpdate={() => setData([...data, 'new'])} />
  );
}

function Child({ items, onUpdate }) {
  return <div onClick={onUpdate}>{items.length}</div>;
}
```

`onUpdate`が毎回新しく作られるため、Childは毎回再レンダー対象となります。

**対処法**
```jsx
function Parent() {
  const [data, setData] = useState([]);

  const handleUpdate = useCallback(() => {
    setData(prev => [...prev, 'new']);
  }, []);

  return <Child items={data} onUpdate={handleUpdate} />;
}
```

`useCallback`で関数をメモ化すれば、Childの再レンダーが抑えられます。

---

### 3. キーの付け忘れでリストエラー

**問題点**
```jsx
function TodoList() {
  const [todos, setTodos] = useState(['牛乳を買う', 'お弁当を作る']);

  return (
    <ul>
      {todos.map(todo => <li>{todo}</li>)} {/* ←keyがない */}
    </ul>
  );
}
```

キーがないと、Reactは各要素を一意に識別できず、**不正確な更新**や**入力内容の紛失**が起きます。

**対処法**
```jsx
{todos.map(todo => (
  <li key={todo}>{todo}</li>
))}
```

本物のデータなら一意なIDを使用します。

```jsx
{todos.map(item => (
  <li key={item.id}>{item.text}</li>
))}
```

---

### 4. 依存配列に非永続的な値を入れる

**問題点**
```jsx
function Component() {
  const [count, setCount] = useState(0);
  const handler = () => console.log(count);

  useEffect(() => {
    // 何らかの処理
  }, [handler]); // ←handlerは毎回新しくなる
}
```

`handler`はコンポーネントのたびに新しく作られるため、**毎回useEffectが走る**ことになります。

**対処法**
```jsx
function Component() {
  const [count, setCount] = useState(0);

  const handler = useCallback(() => {
    console.log(count);
  }, [count]);

  useEffect(() => {
    // 何らかの処理
  }, [handler]);
}
```

`useCallback`でメモ化するか、依存配列から除外して`useRef`で参照させます。

---

### 5. 状態更新の競合

**問題点**
```jsx
function Form() {
  const [values, setValues] = useState({ name: '', age: '' });

  const handleChange = e => {
    setValues({ ...values, [e.target.name]: e.target.value });
  };

  return (
    <>
      <input name="name" value={values.name} onChange={handleChange} />
      <input name="age" value={values.age} onChange={handleChange} />
    </>
  );
}
```

`value`が古い状態を参照しているため、**入力が追いつかない**不具合が起きます。

**対処法**
```jsx
const handleChange = e => {
  setValues(prev => ({ ...prev, [e.target.name]: e.target.value }));
};
```

`prev`を使うことで、常に最新の状態を反映できます。

---

### 6. コンポーネントのマウント解除に伴うクリーンアップ漏れ

**問題点**
```jsx
function Timer() {
  useEffect(() => {
    const timer = setInterval(() => {
      console.log('tick');
    }, 1000);
    // ←クリーンアップなし
  });
}
```

コンポーネントがアンマウントされてもタイマーは残り、**メモリリーや未定義動作**が起きます。

**対処法**
```jsx
useEffect(() => {
  const timer = setInterval(() => {
    console.log('tick');
  }, 1000);
  return () => clearInterval(timer);
}, []);
```

必ず`return`でクリーンアップ関数を返しましょう。

---

### 7. 非同期処理の依存配列ミス

**問題点**
```jsx
function DataFetcher({ userId }) {
  const [data, setData] = useState(null);

  useEffect(() => {
    async function fetchData() {
      const res = await fetch(`/api/user/${userId}`);
      const json = await res.json();
      setData(json);
    }
    fetchData();
  }, [userId]); // ←userIdが依存配列にない
}
```

`userId`が変化してもフェッチが走らない可能性があります。

**対処法**
```jsx
useEffect(() => {
  let ignore = false;
  async function fetchData() {
    const res = await fetch(`/api/user/${userId}`);
    const json = await res.json();
    if (!ignore) setData(json);
  }
  fetchData();
  return () => { ignore = true; };
}, [userId]);
```

クリーンアップで**キャンセル処理**を入れることがベストプラクティスです。

---

### 8. オンライン/オフライン判定でのイベントリスナー漏れ

**問題点**
```jsx
function NetworkStatus() {
  const [isOnline, setIsOnline] = useState(navigator.onLine);

  useEffect(() => {
    window.addEventListener('online', () => setIsOnline(true));
    window.addEventListener('offline', () => setIsOnline(false));
    // ←削除処理なし
  }, []);
}
```

**対処法**
```jsx
useEffect(() => {
  const handleOnline = () => setIsOnline(true);
  const handleOffline = () => setIsOnline(false);

  window.addEventListener('online', handleOnline);
  window.addEventListener('offline', handleOffline);

  return () => {
    window.removeEventListener('online', handleOnline);
    window.removeEventListener('offline', handleOffline);
  };
}, []);
```

### 9. Contextの値が頻繁に変化する

**問題点**
```jsx
const ThemeContext = createContext();

function ThemeProvider({ children }) {
  const [theme, setTheme] = useState('light');
  const toggleTheme = () => setTheme(t => (t === 'light' ? 'dark' : 'light'));

  return (
    <ThemeContext.Provider value={{ theme, toggleTheme }}>
      {children}
    </ThemeContext.Provider>
  );
}
```

`value`が毎回新しくなると、**配下の全コンポーネントが再レンダー**されます。

**対処法**
```jsx
const toggleTheme = useCallback(() => {
  setTheme(t => (t === 'light' ? 'dark' : 'light'));
}, []);

return (
  <ThemeContext.Provider value={{ theme, toggleTheme }}>
    {children}
  </ThemeContext.Provider>
);
```

`useCallback`で関数を固定化すれば、不要な再レンダーが防げます。

---

### 10. フラグ状態の初期化忘れ

**問題点**
```jsx
function Modal({ isOpen, onClose }) {
  return (
    isOpen && (
      <div onClick={onClose}>
        <button onClick={onClose}>閉じる</button>
      </div>
    )
  );
}
```

`isOpen`を外側で管理しているが、**初期値が不明瞭**だと不具合の原因になります。

**対処法**
```jsx
function App() {
  const [modalOpen, setModalOpen] = useState(false);

  return (
    <>
      <button onClick={() => setModalOpen(true)}>開く</button>
      <Modal isOpen={modalOpen} onClose={() => setModalOpen(false)} />
    </>
  );
}
```

状態は明示的に持たせ、**一元管理**する設計にします。

## まとめ

Reactで実践的に役立つエラー対処法をまとめると：

1. **useEffectの依存配列は必ず書く**、そして`eslint-plugin-react-hooks`を活用
2. **不必要な再レンダーはuseCallback/useMemoで抑える**
3. **リストのkeyは一意かつ安定した値**を使用
4. **クリーンアップは忘れずに**、特にタイマーやイベントリスナーは
5. **非同期処理はキャンセル処理を入れる**
6. **状態更新はprevを使う**ことで競合を回避

これらのポイントを意識することで、**予測可能性の高いコード**に変わり、バグの減少と開発効率の向上が期待できます。
