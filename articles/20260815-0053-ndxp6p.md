## 1. 開発効率を最大化する「厳選拡張機能」

VS Code の真価は拡張機能（Extensions）にあります。しかし、何でもかんでも入れすぎると動作が重くなる原因になります。まずは、ジャンル別に「これだけは入れておくべき」というものを厳選して紹介します。

### コードの品質と可読性を高める
コードの書き間違いを防ぎ、チーム開発でも通用する綺麗なコードを書くために必須のツールです。

- **Prettier - Code formatter**:
  コードの整形（インデント、セミコロン、改行など）を自動で行います。プロジェクト内でフォーマットのルールが統一されるため、「誰が書いても同じスタイル」にでき、レビュー時のノイズを減らせます。
- **ESLint**:
  JavaScript/TypeScript の静的解析ツールです。構文エラーや、実行時にエラーになりそうな怪しい記述をリアルタイムで指摘してくれます。
- **Error Lens**:
  通常、エラー内容は画面下部の「問題」パネルを見ないと気づきにくいものですが、これは**エラーメッセージをコードの行末に直接表示**してくれます。これがあるだけで、ミスへの気づきが圧倒的に早くなります。

### 生産性を直感的に向上させる
タイピング量や視覚的な情報をコントロールするためのツールです。

- **GitLens — Git supercharged**:
  Git の操作を強力にサポートします。どの行を「いつ、誰が、どのコミットで」変更したのかがエディタ上に薄く表示される（Git Blame 機能）ため、コードの経緯を追うのが非常に楽になります。
- **Auto Close Tag / Auto Rename Tag**:
  HTML/XML 開発において、開始タグを閉じたら自動で閉じタグを補完したり、開始タグを書き換えたら閉じタグも連動して書き換えてくれたりします。些細なことですが、積み重なると大きな差になります。
- **Material Icon Theme**:
  ファイルツリーのアイコンを、拡張子ごとに分かりやすいデザインに変更します。ファイルの種類が視覚的に判別しやすくなり、目的のファイルへのアクセスが速くなります。

## 2. 爆速でコーディングするための「キーバインドと設定」

マウスに手を伸ばす回数を減らすことが、集中力を維持する最大のコツです。

### 基本設定（settings.json）のカスタマイズ

VS Code の設定は、GUI（設定画面）からも行えますが、`settings.json` を直接編集するスタイルに慣れておくと、設定のコピー＆ペーストや管理が非常に楽になります。

例えば、以下のような設定を `settings.json` に記述してみましょう。

```json
{
  // ファイル保存時に自動でフォーマットを適用
  "editor.formatOnSave": true,
  // 保存時に ESLint の修正を自動適用
  "editor.codeActionsOnSave": {
    "source.fixAll.eslint": "explicit"
  },
  // カーソル周辺のコードを薄く表示（コードの構造を把握しやすくする）
  "editor.guides.bracketPairs": true,
  "editor.bracketPairColorization.enabled": true,
  // タブのサイズを標準的な4に設定
  "editor.tabSize": 4,
  // ファイル保存時に末尾の不要な空白を削除
  "files.trimTrailingWhitespace": true,
  // ファイル保存時に末尾に空行を追加（POSIX準拠のため）
  "files.insertFinalNewline": true
}
```

特に `editor.formatOnSave` は必須です。コードを書いて保存するだけで、自動的に整形される体験は一度味わうと元には戻れません。

### キーバインドの重要性

コマンドパレット（`Ctrl + Shift + P` または `Cmd + Shift + P`）は基本中の基本ですが、よく使う操作はショートカットキーに割り当てるか、覚えておく必要があります。

- **`Ctrl + P` (Quick Open)**: ファイル名を入力して瞬時にファイルへ移動。
- **`Ctrl + D` (Add Selection To Next Find Match)**: 同じ単語を一つずつ選択。変数名を一気に書き換えるときに便利。
- **`Alt + Up/Down` (Move Line Up/Down)**: 行を上下に移動。コピペの手間がなくなります。

これらを使いこなせるようになると、コードを書く「リズム」が崩れにくくなります。

## 3. チーム開発を見据えた「設定の共有方法」

実務に入ると、自分一人ではなく「チーム全員で同じ開発環境」を維持することが求められます。そのために VS Code には設定を共有するための仕組みが備わっています。

###.vscode フォルダによるプロジェクト単位の共有

プロジェクトのルートディレクトリに `.vscode` という名前のフォルダを作成し、その中に設定ファイルを配置します。

- `.vscode/settings.json`: そのプロジェクト固有の VS Code 設定（インデント幅や、そのプロジェクト専用の拡張機能の推奨設定など）。
- `.vscode/extensions.json`: そのプロジェクトの開発に必要な拡張機能のリスト。

特に `extensions.json` は強力です。以下のように記述しておくと、プロジェクトを開いた際に「このプロジェクトにはこの拡張機能が必要ですよ」と VS Code が通知してくれます。

```json
{
  "recommendations": [
    "dbaeumer.vscode-eslint",
    "esbenp.prettier-vscode",
    "eamenn.vscode-gitlens"
  ]
}
```

これを Git でリポジトリに含めて共有することで、新しくプロジェクトに参加したメンバーが、即座に開発準備を整えることができます。

### Settings Sync による個人環境の同期

「自宅の PC と会社の PC で設定を合わせたい」という場合は、VS Code 標準の **Settings Sync** 機能を使用しましょう。GitHub アカウントなどでログインするだけで、インストールした拡張機能やキーバインド、設定がクラウド経由で同期されます。

## まとめ

VS Code は、ただのテキストエディタではなく、設定次第で最強の「開発プラットフォーム」へと進化します。

1. **拡張機能**は、コード品質を高めるもの（ESLint/Prettier）と、視覚情報を助けるもの（Error Lens/GitLens）を優先して入れる。
2. **設定（settings.json）**をカスタマイズし、保存時の自動整形などを導入して、マウス操作を減らす。
3. **プロジェクト単位の設定（.vscode）**を活用して、チーム全体の開発体験を揃える。

まずは、今日紹介した拡張機能を一つインストールし、`formatOnSave` を有効にすることから始めてみてください。その小さな一歩が、数ヶ月後のあなたの開発スピードを劇的に変えているはずです。
