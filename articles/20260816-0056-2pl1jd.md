## NetlifyでプレビューURLを自動生成
静的サイトのプレビューを毎回ローカルサーバーで立ち上げて確認していたが、ブランチごとにURLを共有するのが面倒だった。Netlifyにリポジトリを連携すると、プッシュごとに独自のプレビューURLが自動生成され、チーム内でのレビューがスムーズになった。設定はNetlifyにサインインし、「New site from Git」でリポジトリを選び、ビルドコマンドを`npm run build`、公開ディレクトリを`dist`に設定するだけ。

```toml
# netlify.toml例
[build]
  command = "npm run build"
  publish = "dist"
```

これで`https://<site-name>.netlify.app`に常に最新版が反映され、プルリクエストごとにデプロイプレビューが作られるようになった。結果として、確認のためにわざわざローカルサーバーを立ち上げる手間がなくなり、フィードバックまでの時間が短縮された。

## Vercelでサーバーレスデプロイを自動化
Next.jsアプリを本番にデプロイするたびに、サーバーの設定や環境変数の管理を手動で行っていたため、デプロイに失敗することが多かった。Vercelにリポジトリを接続すると、プッシュごとにサーバーレス関数と静的ファイルが自動でビルドされ、環境変数もダッシュボードから簡単に設定できるようになった。使い方はVercelにログインし、「Import Project」でGitリポジトリを選び、フレームワークを自動検出させるだけ。

```json
// vercel.json例
{
  "rewrites": [{ "source": "/api/:path*", "destination": "/api/:path*" }]
}
```

これで`https://<project>.vercel.app`に常に最新コードが反映され、ロールバックもダッシュボードからワンクリックで可能になった。結果として、デプロイの失敗率が激減し、開発サイクルが速くなった。

## Firebase HostingでSSLとカスタムドメインを簡単設定
バックエンドなしのシンプルなウェブアプリでも、SSL証明書の取得やカスタムドメインの設定に毎回手間取っていた。Firebase Hostingを使うと、無料枠でSSLが自動適用され、カスタムドメインもコンソールから数クリックで設定できる。導入はFirebase CLIをインストールし、プロジェクトを初期化した後、`firebase deploy`コマンドで公開するだけ。

```bash
# Firebase CLIのインストールと利用例
npm install -g firebase-tools
firebase login
firebase init hosting   # ホスティングを選択し、公開ディレクトリをpublicに設定
firebase deploy
```

これで`https://<project-id>.web.app`にHTTPS付きでアプリが公開され、カスタムドメインも簡単に結びつけられた。結果として、証明書の更新や手動のファイル転送が不要になり、リリース作業が楽になった。

## Docker Hubでイメージ管理をシンプルに
ローカルでビルドしたDockerイメージを毎回手動でサーバーに転送していて、イメージのバージョン管理があいまいだった。Docker Hubの無料プライベートリポジトリを1つ使うと、pushとpullだけでイメージを共有でき、タグでバージョンを明確に管理できるようになった。使い方はDocker Hubにアカウントを作成し、`docker login`後、イメージにタグを付けてpushする。

```bash
# イメージにバージョンタグを付けてpush
docker build -t myapp:v1.0 .
docker tag myapp:v1.0 username/myapp:v1.0
docker push username/myapp:v1.0
```

これでサーバー側では`docker pull username/myapp:v1.0`だけで最新バージョンを取得できるようになり、環境間の差異が減った。結果として、デプロイの手順がシンプルになり、ロールバックも過去のタグをpullするだけで済むようになった。

## GitHub ActionsでCIをフルマネージド
CI/CDを自前のJenkinsで動かしていたが、サーバーの維持やプラグインのアップデートに時間が取られ、肝心のコードレビューに集中できなかった。GitHub Actionsを使うと、リポジトリに`.github/workflows`ディレクトリを置くだけで、プッシュやプルリクエストごとに自動でテストやビルドが走るようになった。設定例は以下の通り。

```yaml
# .github/workflows/ci.yml
name: CI
on: [push, pull_request]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Setup Node
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm ci
      - run: npm test
```

これでテストが失敗したらすぐに通知が来るし、成功したら自動でデプロイジョブも走らせられるようになった。結果として、サーバー管理の工数がほぼゼロになり、フィードバックループが劇的に速くなった。

## CircleCIで無料枠を効率利用
オープンソースプロジェクトでプライベートリポジトリのビルドにCircleCIを使っていたが、無料枠のクレジットがすぐに尽きてしまい、ビルドが止まることが頻繁にあった。そこでコンテナキャッシュを有効にし、不要なジョブを削減することでクレジット消費を抑えた。設定例は以下のように`.circleci/config.yml`に書く。

```yaml
version: 2.1
jobs:
  build:
    docker:
      - image: cimg/node:18.10
    steps:
      - checkout
      - restore_cache:
          keys: [node-v18-{{ checksum "package-lock.json" }}]
      - run: npm ci
      - save_cache:
          paths: [node_modules]
          key: node-v18-{{ checksum "package-lock.json" }}
      - run: npm test
workflows:
  version: 2
  build_and_test:
    jobs:
      - build
```

これで同じ依存関係はキャッシュから復元され、ビルド時間が30%短縮され、無料枠でも1日あたりのビルド数を維持できるようになった。結果として、クレジット切れによる中断が減り、安定したCIが得られるようになった。

## Renderでスリープしないバックエンド
バックエンドAPIをHerokuの無料ダイノで動かしていたが、スリープによって最初のリクエストに遅延が生じ、開発中のストレスが大きかった。Renderの無料ウェブサービスはスリープしないため、常に即応可能なエンドポイントが得られるようになった。使い方はRenderにアカウントを作成し、「New Web Service」でリポジトリを選び、ビルドコマンドを`npm install`、スタートコマンドを`npm start`に設定するだけ。

```yaml
# render.yaml例
services:
  - type: web
    name: my-api
    env: node
    buildCommand: npm install
    startCommand: npm start
    autoDeploy: true
```

これで`https://my-api.onrender.com`に常に待機状態のAPIが立ち上がり、フロントエンドからの呼び出しが遅延なく行えるようになった。結果として、開発中の待ち時間がほぼゼロになり、ユーザー体験のテストがスムーズになった。

## Supabaseで認証とDBを即座に利用
認証やデータベースを自前で構築していたが、ユーザー管理のテーブル作成やJWTの発行に毎回時間がかかっており、プロトタイプのスピードが出なかった。Supabaseの無料プランはPostgreSQLベースのデータベースと認証APIを即座に提供し、ダッシュボードからテーブル作成やロール設定がGUIでできる。導入はSupabaseプロジェクトを作成し、プロジェクトURLとanonキーを取得してクライアント側に設定するだけ。

```javascript
// Supabaseクライアント初期化例
import { createClient } from '@supabase/supabase-js'
const supabase = createClient(
  process.env.SUPABASE_URL,
  process.env.SUPABASE_ANON_KEY
)

// サインアップ例
async function signUp(email, password) {
  const { user, error } = await supabase.auth.signUp({ email, password })
  if (error) throw error
  return user
}
```

これでユーザー登録やログインが数行のコードで実装でき、バックエンドのサーバー管理を一切気にしなくてもよくなった。結果として、プロトタイプの開発サイクルが数日から数時間に短縮された。

## RailwayでDB付きデプロイをワンクリック
データベースのマイグレーションスクリプトを毎回手動でサーバーにSSHして実行していたため、環境ごとにバージョンがずれてしまい、デプロイ後に不具合が起きることがあった。Railwayの無料プランはGitリポジトリを連携すると、プッシュごとに自動でビルドとデプロイが走り、データベースもサービスとして追加できる。使い方はRailwayにサインインし、「New Project」→「Deploy from GitHub」でリポジトリを選び、プラグインからPostgreSQLを追加するだけ。

```toml
# railway.toml例
[build]
  builder = "nixpacks"

[deploy]
  restartPolicy = "on_failure"
  restartLimit = 3

[[services]]
  name = "postgres"
  plan = "free"
```

これで`git push`するだけでバックエンドとデータベースが同時に更新され、マイグレーションスクリプトもリポジトリに含めておけば自動で実行されるようになった。結果として、環境間の差異がなくなり、デプロイ後のトラブルが劇的に減った。
