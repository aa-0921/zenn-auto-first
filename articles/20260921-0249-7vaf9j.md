## コールバック地獄の問題点

非同期処理を扱う最も原始的な方法がコールバック関数です。処理が完了した際に呼び出される関数を渡すことで、非同期性を担保していました。

```javascript
function fetchUserData(userId, callback) {
  setTimeout(() => {
    callback(null, { id: userId, name: 'Taro' });
  }, 1000);
}

function fetchUserOrders(userId, callback) {
  setTimeout(() => {
    callback(null, [{ id: 1, item: 'Book' }, { id: 2, item: 'Pen' }]);
  }, 1000);
}

// コールバック関数のネスト
fetchUserData(1, (err, user) => {
  if (err) {
    console.error('ユーザー取得失敗:', err);
    return;
  }
  console.log('ユーザー:', user);
  
  fetchUserOrders(user.id, (err, orders) => {
    if (err) {
      console.error('注文取得失敗:', err);
      return;
    }
    console.log('注文:', orders);
    
    // さらにネストが深くなる...
  });
});
```

このようにネストが深くなると「コールバック地獄（Callback Hell）」と呼ばれる状態に陥ります。エラーハンドリングの重複、処理の流れが読みにくい、デバッグが困難などの問題が発生します。

## Promiseによる非同期処理の整理

Promiseは非同期処理をオブジェクトとして扱い、処理の成功・失敗をチェーン的に記述できる仕組みです。`new Promise()`のコンストラクタで非同期処理をラップし、`resolve`（成功）または`reject`（失敗）を呼び出します。

```javascript
function fetchUserData(userId) {
  return new Promise((resolve, reject) => {
    setTimeout(() => {
      if (userId > 0) {
        resolve({ id: userId, name: 'Taro' });
      } else {
        reject(new Error('無効なユーザーIDです'));
      }
    }, 1000);
  });
}

function fetchUserOrders(userId) {
  return new Promise((resolve) => {
    setTimeout(() => {
      resolve([{ id: 1, item: 'Book' }, { id: 2, item: 'Pen' }]);
    }, 1000);
  });
}
```

Promiseを使うと、コールバック地獄を避けた記述が可能になります。

```javascript
fetchUserData(1)
  .then(user => {
    console.log('ユーザー:', user);
    return fetchUserOrders(user.id); // 次の処理に渡す
  })
  .then(orders => {
    console.log('注文:', orders);
  })
  .catch(err => {
    console.error('エラー発生:', err.message);
  });
```

このように `.then()` で処理を連鎖させ、`.catch()` で一箇所にエラーを集約できます。さらに `Promise.all()` を使えば複数の非同期処理を並列実行することも可能です。

```javascript
Promise.all([
  fetchUserData(1),
  fetchUserData(2)
])
.then(([user1, user2]) => {
  console.log('複数ユーザー:', user1, user2);
})
.catch(err => {
  console.error('いずれかの処理が失敗:', err);
});
```

## then と async/await の使い分け

ES2017で導入された `async/await` は、Promiseをより直感的に記述するための構文糖衣です。`async` 関数内で `await` を使うと、非同期処理が完了するまで処理を一時停止し、結果を変数に代入できます。

```javascript
async function displayUserData(userId) {
  try {
    const user = await fetchUserData(userId);
    console.log('ユーザー:', user);
    
    const orders = await fetchUserOrders(user.id);
    console.log('注文:', orders);
    
    return { user, orders };
  } catch (err) {
    console.error('エラー発生:', err.message);
    throw err; // 呼び出し元に再スロー
  }
}

displayUserData(1);
```

### 使い分けのポイント

- **thenチェーンを選ぶ場面**: 複数の非同期処理を並列実行したい場合（`Promise.all`）、または単純な1回の非同期処理だけの場合
- **async/awaitを選ぶ場面**: 処理の流れが直線的で読みやすさを重視したい場合、エラーハンドリングをtry/catchで統一的に扱いたい場合

特にasync/awaitは「処理Aが終わってから処理Bを実行」といった順序的な処理を記述する際に、同期コードに近い読みやすさを実現します。

## エラーハンドリングの基本

非同期処理では、ネットワークエラーやサーバーエラーが発生する可能性が常にあります。適切にエラーを処理しないと、原因不明の不具合につながります。

### Promiseの場合

`.catch()` メソッドでチェーン内の任何のエラーをキャッチできます。

```javascript
fetchUserData(-1) // 無効なID
  .then(user => {
    console.log('ユーザー:', user);
  })
  .catch(err => {
    console.error('取得失敗:', err.message); // 「無効なユーザーIDです」
  });
```

### async/awaitの場合

`try/catch` 文で囲み、`await` 式が reject した場合にエラーをキャッチします。

```javascript
async function getUserDataSafely(userId) {
  try {
    const user = await fetchUserData(userId);
    return user;
  } catch (err) {
    console.error('ユーザー取得エラー:', err.message);
    return null; // エラー時のデフォルト値を返す
  }
}
```

### エラーハンドリングのベストプラクティス

1. **必ずエラーを処理する**: 未処理のrejectは未捕捉の例外となり、アプリケーションをクラッシュさせる可能性があります
2. **エラーの種類を区別する**: カスタムエラクラスを作成し、ネットワークエラーとバリデーションエラーを使い分ける
3. **ログを残す**: 本番環境ではエラー内容とスタックトレースをログに記録してください

```javascript
class NetworkError extends Error {
  constructor(message) {
    super(message);
    this.name = 'NetworkError';
  }
}

async function fetchWithRetry(url, retries = 3) {
  for (let i = 0; i < retries; i++) {
    try {
      const response = await fetch(url);
      if (!response.ok) throw new NetworkError(`HTTP ${response.status}`);
      return await response.json();
    } catch (err) {
      if (i === retries - 1) throw err; // 最後のリトライで再スロー
      console.warn(`リトライ中... (${i + 1}/${retries})`);
    }
  }
}
```

## まとめ

JavaScriptの非同期処理は、コールバック関数からPromiseへ、さらにasync/awaitへと進化することで、コードの可读性と保守性が大幅に向上しました。コールバック地獄に陥らず、Promiseのチェーンまたはasync/awaitを適切に使い分け、エラーハンドリングを確実に行うことが重要です。

実際の開発では、APIクライアントのラッパーやユーティリティ関数をPromiseでラップし、ビジネスロジックではasync/awaitを活用するという組み合わせが多いです。非同期処理の基本をしっかり理解し、堅牢なJavaScriptアプリケーションを構築してください。
