## App Router と Pages Router の違い
Next.js には、主に Pages Router と App Router の 2 つのルーティング方式があります。Pages Router は `pages` ディレクトリ配下にファイルを置く方式で、従来からあるシンプルな構成です。一方、App Router は Next.js 13 から推奨される方式で、`app` ディレクトリ配下に `page.tsx` や `layout.tsx` などの特別なファイルを置きます。

```text
my-app/
  app/
    layout.tsx
    page.tsx
    globals.css
  pages/
    index.tsx
    api/
      hello/
        ts.ts
```

このように、Next.js プロジェクトには `pages` ディレクトリと `app` ディレクトリが併存することもあります。併存している場合は App Router が優先されます。

App Router の主なファイルは次のとおりです。
- `page.tsx`: そのルートに対応する画面コンポーネント
- `layout.tsx`: 親子レイアウトを共有するコンポーネント
- `loading.tsx`: データ取得中のローディング UI
- `error.tsx`: エラーハンドリング UI
- `not-found.tsx`: 404 ページ
- `template.tsx`: レイアウトの再利用やアニメーション用

動的ルートはフォルダ名にブラケットを使います。
```text
app/
  blog/
    [slug]/
      page.tsx
```

これにより `/blog/nextjs-tips` のような URL に対応できます。

## サーバーコンポーネントとクライアントコンポーネント
App Router では、基本的にサーバーコンポーネントとして動作します。サーバーコンポーネントでは、データベースへのアクセスやサーバーでのバリデーション、直接的な `fetch` などが可能です。一方、ユーザー操作が必要なカウンターのようなコンポーネントは、クライアントコンポーネントとして定義します。

```tsx
// app/page.tsx
import { Counter } from './Counter';

export default function Home() {
  return <Counter />;
}
```

```tsx
// app/Counter.tsx
'use client';

import { useState } from 'react';

export function Counter() {
  const [count, setCount] = useState(0);

  return (
    <button onClick={() => setCount(count + 1)}>
      Count: {count}
    </button>
  );
}
```

ポイントは、`'use client'` をファイル先頭に置くことです。これでそのファイルはクライアントコンポーネントとして扱われます。逆に、`'use client'` を置かなければサーバーコンポーネントとして扱われます。

サーバーコンポーネントからクライアントコンポーネントへは、値を受け渡すことはできます。ただし、関数やイベントハンドラーをそのまま Server Component から Client Component に渡すことはできません。その場合は、Client Component 側で関数を定義します。

```tsx
// app/UserSettings.tsx
'use client';

import { useState } from 'react';

export function UserSettings() {
  const [name, setName] = useState('');
  return <input value={name} onChange={(e) => setName(e.target.value)} />;
}
```

## よくあるつまずきポイント
### 1. 初心者が「use client」を多用する
App Router では、サーバーコンポーネントが基本です。最初に `useState` を使いたいからといって、すべてのコンポーネントに `'use client'` を書いてしまうことがあります。これだとサーバーコンポーネントの恩恵が失われるだけでなく、パフォーマンスやバンドルサイズにも影響しやすくなります。

対策としては、必要な最小限のコンポーネントにだけ `'use client'` を置き、親はサーバーコンポーネントのままにすることです。

### 2. Server Action を誤って `'use server'` にする
Server Action を使うときは、そのファイルや関数の先頭に `'use server'` を書きます。

```tsx
// app/actions.ts
'use server';

export async function createPost(formData: FormData) {
  // サーバーで処理
}
```

### 3. Metadata の書き方
App Router では `metadata` オブジェクトを export します。

```tsx
// app/page.tsx
import type { Metadata } from 'next';

export const metadata: Metadata = {
  title: 'トップページ',
};
```

### 4. Loading と Error の扱い
App Router では `loading.tsx` と `error.tsx` を置くことで、Suspense やエラーハンドリングをファイルベースで管理できます。

```tsx
// app/blog/[slug]/page.tsx
import { notFound } from 'next/navigation';

export default async function BlogPost({
  params,
}: {
  params: { slug: string };
}) {
  const post = await getPost(params.slug);

  if (!post) {
    notFound();
  }

  return <article>{post.title}</article>;
}
```

## まとめ
Next.js の App Router は、ファイルベースの規約が直感的で強力ですが、初心者がつまずきやすいポイントが多くあります。Pages Router との違いは、ルーティングのファイル構成とデータ取得の考え方の違いを理解すると整理しやすいです。また、サーバーコンポーネントとクライアントコンポーネントの使い分けは、最初から完璧に理解しようとせず、段階的に慣れていくのがおすすめです。まずはシンプルな `app/page.tsx` と `layout.tsx` から始め、必要になったら `'use client'` や Server Action を追加していくとよいでしょう。Next.js のバージョンによって細かい仕様が変わることもあるので、公式ドキュメントや移行ガイドも併せて確認しながら進めてください。
