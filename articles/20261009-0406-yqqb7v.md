同じコマンドを毎回手で打っていて、タイポやオプション忘れで時間を溶かすことが多かった。特にブランチ操作や履歴整理、デバッグ時の履歴探索では、覚えているつもりでもいざ使うと詰まる。そこで実務で頻繁に使う 10 のコマンドを厳選し、実際の現場でどう役立ったかをまとめた。

## 1. `git switch -c` でブランチ作成と切り替えを一発に
新機能を開発するたびに `git branch` → `git checkout` の二手間を踏んでいた。`git switch -c feature/login` と打てば作成と移動が同時に完了し、タイポリスクも減った。コマンド一発で作業ブランチが立ち上がるため、コンテキストスイッチがスムーズになった。

```bash
git switch -c feature/login
```

## 2. `git commit --amend --no-edit` で直前コミットを修正
コミット後に「ファイルを追加し忘れた」「メッセージを微修正したい」と気づき、毎回 `git commit --amend` → エディタを開く手間があった。`--no-edit` を付けるとメッセージ変更なしでインデックスの内容だけ上書きできる。細かな修正がコミット履歴を汚さず、レビュー依頼前の整理が劇的に速くなった。

```bash
git add forgotten-file.ts
git commit --amend --no-edit
```

## 3. `git rebase -i HEAD~n` で直近コミットを整理
PR 作成前に複数の細かいコミットをまとめたくて、手動で `git reset --soft` → 再コミットしていた。インタラクティブリベースなら `pick`/`squash`/`reword` で一括整理可能。履歴が綺麗になり、レビュアーから「コミット粒度が良い」と言われるようになった。

```bash
git rebase -i HEAD~5
```

## 4. `git stash push -m "msg"` で作業中断をメモ付き保存
急な割り込みタスクで作業を中断する際、無名のスタッシュだと後でどれがどれか分からなくなっていた。メッセージ付きで `git stash push -m "wip: refactor auth"` とすれば、後から `git stash list` で即座に特定できる。コンテキスト復帰が数秒で済むようになった。

```bash
git stash push -m "wip: refactor auth"
```

## 5. `git log --oneline --graph --all` でブランチ構造を可視化
複数ブランチが並行進行しているとき、どのコミットがどこにマージされたか把握しきれず、マージ漏れを起こしていた。このオプションで ASCII グラフが出力され、ブランチ分岐・マージ関係が一目で分かる。マージ前の確認が圧倒的に楽になった。

```bash
git log --oneline --graph --all
```

## 6. `git diff --name-only` で変更ファイル一覧を取得
レビュー前に「どのファイルを触ったか」を毎回 `git status` で目視確認していた。`git diff --name-only main..HEAD` なら変更ファイル名だけが列挙され、CI 設定やスクリプトへの渡しも簡単。漏れなくチェックリストを作れるようになった。

```bash
git diff --name-only main..HEAD
```

## 7. `git bisect` でバグ混入コミットを特定
本番で再現しないバグがどのコミットで入ったか、手動で二分探索していて数時間かかっていた。`git bisect start` → `good`/`bad` を繰り返すだけで自動的に特定コミットまで絞り込める。デバッグ時間が 1/10 以下に短縮された。

```bash
git bisect start
git bisect bad HEAD
git bisect good v1.2.0
# テスト実行後
git bisect good   # または git bisect bad
```

## 8. `git cherry-pick <commit>` で必要な修正だけ取り込み
ホットフィックスブランチの一部コミットだけ本番ブランチに適用したく、手動でパッチを作っていた。`git cherry-pick abc1234` で該当コミットだけ適用でき、コンフリクト時も通常のマージと同じ手順で解決できる。リリース作業が安全かつ迅速になった。

```bash
git cherry-pick abc1234
```

## 9. `git push --force-with-lease` で安全な強制プッシュ
リベース後の履歴書き換えで `git push -f` を使うと、他メンバーの作業を上書きしてしまう恐れがあった。`--force-with-lease` ならリモートが自分基準の状態でない場合に拒否されるため、誤上書きを防げる。チーム全員が安心して履歴整理できるようになった。

```bash
git push --force-with-lease origin feature/login
```

## 10. `git config --global alias.<name> '<command>'` で自分専用ショートカット
長いコマンドを毎回打つのが億劫で、特に `log --oneline --graph --all` を頻繁に使っていた。`git config --global alias.lg "log --oneline --graph --all"` と登録すれば `git lg` だけで呼び出せる。日々のタイプ数が減り、集中力が途切れにくくなった。

```bash
git config --global alias.lg "log --oneline --graph --all"
```
