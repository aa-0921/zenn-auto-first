## 1. インプットとアウトプットのバランスを取る － まずは「1:1」から始めよう
インプット（知識を得る）と不足しているアウトプット（実際に手を動かす）を1:1の比率で行うと、知識を定着させやすくなります。私は最初の3か月を「1日1時間の読書＋1時間のコード実践」で過ごしました。

### 1-1. 読書の枠組み
- **テーマを決める**：例えば「JavaScriptの非同期処理」や「コンテナ原理」
- **1章ずつ読み、メモを取る**：箇条書きで要点を書き、疑問点を残す

### 1-2. コード実践のコツ
- **「小さく書く」**：1行で完結する例を作る
- **テストを書いてみる**：読んだ内容を自分の言葉で実装し、テストが通るか確認

```js
// 例：Promiseの基本
function delay(ms) {
  return new Promise(resolve => setTimeout(resolve, ms));
}

async function test() {
  console.log('start');
  await delay(1000);
  console.log('end');
}
test();
```

> **ポイント**  
> * 実装が終わったら必ず `console.log` で挙動を確認  
> * テストは `Jest` を使い、`expect` で結果を検証

## 2. ドキュメントの読み方とメモ術
公式ドキュメントは「APIのリファレンス」だけでなく、設計思想やベストプラクティスを知る重要な情報源です。読み方のコツは「問題解決志向」と「メモの階層化」です。

### 2-1. 問題解決志向で読む
- **まずは「何ができるか」**：APIの機能を箇条書き  
- **次に「どう使うか」**：サンプルコードを確認  
- **最後に「なぜこの設計か」**：公式ブログやissueをチェック

### 2-2. 階層化メモ
- **タイトル**：API名  
- **概要**：1行で機能説明  
- **使い方**：コード例  
- **注意点**：制限やバグ

```text
# fetch API
概要: HTTPリクエストを送るための標準API
使い方:
  fetch('https://api.example.com').then(res => res.json());
注意点:
  - CORS制限に注意
  - ネットワークエラーは例外として扱われる
```

## 3. 写経と個人開発でスキルを固める
写経は「コードを丸ごとコピーして実行する」だけでなく、実際に手を動かしながら詳細を追うことで理解が深まります。個人開発は「自分の問題を解決する」プロセスで、実務で即戦力になる技術を養います。

### 3-1. 写経の手順
1. **ソースコードを読む**：1行ごとに意味を推測  
2. **自分で書き直す**：変数名を自分好みに変更  
3. **実行して確認**：期待した出力になるか検証  
4. **差分を確認**：元のコードと比較し理解を深める

```python
# オリジナル
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a

# 写経
def fibonacci(num):
    x, y = 0, 1
    for _ in range(num):
        x, y = y, x + y
    return x
```

### 3-2. 個人開発のプロジェクト構成
- **アイデアは小さく**：30分で作れる機能を目標
- **GitHubで公開**：Issue管理で改善点を可視化
- **CI/CDを導入**：GitHub Actionsで自動テスト・デプロイ

```yaml
# .github/workflows/ci.yml
name: CI
on:
  push:
    branches: [ main ]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - uses: actions/setup-node@v3
        with:
          node-version: '18'
      - run: npm ci
      - run: npm test
```

## 4. 実務での活かし方：学習方法をプロダクトに反映
- **コードレビューで学習**：指摘を受けた箇所を再読し、ドキュメントにメモを残す
- **ペアプログラミング**：仲間とコードを共有し、理解を深める
- **デイリースタンドアップで振り返り**：今日学んだことを共有し、アウトプットを増やす

## 5. まとめ
- **インプットとアウトプットを1:1で実行**し、学んだことをすぐに実装で試す
- **ドキュメントは問題解決志向で読む**。メモは階層化し、後から見返せるようにする
- **写経と個人開発**は理解を定着させ、即戦力へとつなげる
- **実務に活かす**ために、学習内容をプロジェクトやレビューで共有し、継続的に改善する

これらのステップを踏むことで、駆け出しエンジニアが短期間で高い技術力を身につけ、実務に直結するスキルを獲得できます。ぜひあなたの学習サイクルに取り入れてみてください。
