## 基本概念とよく使うユーティリティ
### ユーティリティクラスの命名規則
Tailwind のクラス名は「プロパティー-値」の形を基本とし、例えば `p-4` は `padding: 1rem`、`text-lg` は `font-size: 1.125rem; line-height: 1.75rem` を表します。この規則に従えば、クラス名を見ただけでどのスタイルが適用されるか直感的に理解できます。また、バリエーションとして `-` や `:` を用いた modifier が存在し、例えば `hover:` や `focus:` は擬似クラス、`sm:` や `md:` はブレークポイントを表します。

### 代表的なユーティリティ例
以下に実務で頻出するユーティリティを機能別にまとめます。

- **レイアウト**
  ```html
  <div class="flex flex-col items-center justify-between w-full">
    <!-- コンテンツ -->
  </div>
  ```
  `flex`、`flex-col`、`items-center`、`justify-between` でフレックスボックスの基本レイアウトを一行で記述できます。

- **スペーシング**
  ```html
  <div class="p-6 m-4 space-y-3">
    <!-- 子要素間に縦方向のスペース -->
  </div>
  ```
  `p-`（padding）、`m-`（margin）、`space-y-`（子要素間の垂直スペース）は数値が 0.5rem 単位で変化します（デフォルト設定では 1 = 0.25rem）。

- **タイポグラフィ**
  ```html
  <h1 class="text-3xl font-bold tracking-tight">
    タイトル
  </h1>
  <p class="text-gray-600 leading-relaxed">
    本文テキスト…
  </p>
  ```
  `text-` 系でフォントサイズ、`font-` でウェイト、`tracking-` で文字間隔、`leading-` で行高を調整できます。

- **色と背景**
  ```html
  <button class="bg-indigo-600 hover:bg-indigo-700 text-white font-medium py-2 px-4 rounded">
    ボタン
  </button>
  ```
  `bg-`、`text-`、`hover:` modifier を組み合わせることで、状態ごとの色変化を簡単に実装できます。

これらのユーティリティは組み合わせて使うことで、ほとんどのデザイン要素をHTMLのみで記述可能です。クラスが増えてもファイルサイズは PurgeCSS（Tailwind ビルトインの最適化）によって未使用クラスが削除されるため、本番ビルドでは軽量に保たれます。

## レスポンシブデザインの書き方
### ブレークポイントの基本
Tailwind はデフォルトで以下のブレークポイントを提供します（`tailwind.config.js` で変更可能）。

| プレフィックス | 最小幅 |
|----------------|--------|
| `sm:`          | 640px  |
| `md: 768px:`          | 768px  |
| `md:`          | 1024px |
| `lg:`          | 1280px |
| `xl:`          | 1536px |
| `2xl:`         | 1536px（例） |

クラス名にプレフィックスを付けるだけで、そのブレークポイント以上でのスタイルが適用されます。例えば `md:text-center` は 768px 以上でテキストを中央寄せにします。

### 複数ブレークポイントの併用
同じ要素に異なるブレークポイントのクラスを重ねて書くことで、段階的なスタイル変更が可能です。

```html
<div class="text-sm md:text-base lg:text-lg">
  レスポンシブなテキストサイズ
</div>
```

この例では、幅が 640px 未満は `text-sm`（0.875rem）、640px）、768px〜1023px は `text-base`（1rem）、1024px 以上は `text-lg`（1.125rem）となります。

### カスタムブレークポイントの追加
プロジェクト固有のブレークポイントが必要な場合は、`tailwind.config.js` の `theme.screens` を拡張します。

```js
// tailwind.config.js
module.exports = {
  theme: {
    screens: {
      'xs': '480px',
      // デフォルトの sm, md, lg, xl, 2xl はそのまま継承
    },
  },
};
```

これで `xs:` プレフィックスが利用可能になります。カスタムブレークポイントはデフォルトのものと同様に、`hover:xs:` や `focus:xs:` と組み合わせても使えます。

## カスタム設定の入口
### 設定ファイルの構造
Tailwind の振る舞いは `tailwind.config.js` で制御します。主に以下のセクションがあります。

- `theme`：フォントサイズ、色、スペーシングなどのデザイントークンを定義
- `variants`：どの擬似クラス（hover, focus, etc.）にユーティリティを適用するかを設定
- `plugins`：公式またはサードパーティ製のプラグインを追加
- `corePlugins`：コアユーティリティの有効/無効を切り替え

### 色 palette のカスタマイズ例
ブランドカラーをプロジェクトに組み込む場合は、`theme.extend.colors` を使います。

```js
// tailwind.config.js
module.exports = {
  theme: {
    extend: {
      colors: {
        brand: {
          50: '#eff6ff',
          100: '#dbeafe',
          // … 省略 …
          900: '#1e3a8a',
        },
      },
    },
  },
};
```

これにより `bg-brand-600`、`text-brand-900` などのクラスが自動生成されます。`extend` を使うとデフォルトのテーマを壊さずに追加できるため、アップデート時の衝突リスクが低くなります。

### カスタムスペーシングの追加
デフォルトのスペーシングスケール（0.5rem 刻み）に加えて、プロジェクト独自の値を定義できます。

```js
module.exports = {
  theme: {
    extend: {
      spacing: {
        '18': '4.5rem', // 18 * 0.25rem
        '22': '5.5rem',
      },
    },
  },
};
```

これで `p-18` や `mt-22` といったクラスが利用可能になります。デザイナーが指定した余白やギャップをそのままコードに落とし込めるので、デザインと実装のズレを防ぎやすくなります。

### プラグインの活用例
公式の `@tailwindcss/forms` プラグインを入れると、フォーム要素のリセットとデフォルトスタイルが適用され、カスタマイズが楽になります。

```bash
npm install -D @tailwindcss/forms
```

```js
// tailwind.config.js
module.exports = {
  plugins: [
    require('@tailwindcss/forms'),
  ],
};
```

これにより `input`, `textarea`, `select` などがリセットされ、`focus:ring-2 focus:ring-indigo-500` などのフォーカスリングが自動で付与されます。独自のフォームコンポーネントを作る際のベースとして非常に便利です。

## 実務での活用例
### カードコンポーネントの実装
以下は、よくあるカードUIをTailwindだけで組んだ例です。

```html
<div class="max-w-sm rounded-xl shadow-md overflow-hidden bg-white dark:bg-gray-800">
  <img class="w-full h-48 object-cover" src="/images/card.jpg" alt="カード画像">
  <div class="p-6">
    <h2 class="text-2xl font-bold text-gray-900 dark:text-white mb-2">
      カードタイトル
    </h2>
    <p class="text-gray-600 dark:text-gray-300 mb-4">
      ここにカードの説明文が入ります。複数行にわたってもレイアウトが崩れません。
    </p>
    <a href="#" class="inline-block bg-indigo-600 hover:bg-indigo-700 text-white font-medium py-2 px-4 rounded transition">
      詳細を見る
    </a>
  </div>
</div>
```

ポイント：
- `max-w-sm` で最大幅を制御し、`rounded-xl` と `shadow-md` で見た目を調整。
- ダークモード対応として `dark:` バリエーションを使用（`bg-white dark:bg-gray-800` など）。
- 画像は `object-cover` でアスペクト比を保ちつつ枠にフィット。
- ボタンは `transition` を付けることでホバー時の色変化を滑らかに。

### グリッドレイアウトの実装
レスポンシブなグリッドを作る際は `grid` 系ユーティリティが便利です。

```html
<div class="grid gap-6 sm:grid-cols-2 lg:grid-cols-4">
  <!-- カードやアイテムを繰り返し -->
  <div class="bg-gray-50 p-4 rounded">アイテム1</div>
  <div class="bg-gray-50 p-4 rounded">アイテム2</div>
  <!-- ... -->
</div>
```

- `grid` でグリッドコンテナを作成。
- `gap-6` で間隔を統一。
- `sm:grid-cols-2`、`lg:grid-cols-4` でブレークポイントごとに列数を変更。

このように、ブレークポイントプレフィックスを組み合わせるだけで、メディアクエリを書くことなくレスポンシブグリッドを実現できます。

3. カスタム設定の入り口（テーマ拡張、プラグイン活用、カラーパレット・スペーシングの追加）
