同じファイルをエクスプローラーから何度もクリックして開いていたり、頻繁に使うコマンドを毎回メニューから辿っていたとき、作業のリズムが途切れてイライラしていた。VS Code のショートカットを覚えれば、手をキーボードから離さずに目的の操作ができるようになり、ストレスが大きく減った。

## ファイルを素早く開く (Ctrl+P) でファイル名検索が楽になった
エクスプローラーのツリーを階段のようにたどって目的のファイルを開くのに、毎回数秒から十数秒かかっていた。特に深いネストのディレクトリでは、フォルダを開閉する操作が煩雑で、集中が途切れがちだった。  
使い方は次の通り。  
```  
Ctrl+P  
```  
押した後、ファイル名の一部を入力するとインクリメンタルサーチが働き、候補がリアルタイムで絞り込まれる。Enter で選択すればすぐにファイルが開く。  
このショートカットを使い始めてから、ファイルを開くまでの時間が平均で 5 秒程度に短縮され、コードを書く流れが途切れなくなった。頻繁に行き来するテストファイルや設定ファイルも一瞬で呼び出せるようになり、作業効率がはっきりと向上した。

## エディタを分割して複数ファイルを同時に見る (Ctrl+\)
一つのファイルだけを見ながら別のファイルを参照したいとき、タブを行ったり来たりしていた。その結果、参照したい場所を見失い、スクロール量が増えて目の疲れがたまっていた。  
使い方は次の通り。  
```  
Ctrl+\  
```  
これを押すと現在のエディタが垂直に分割され、同じワークスペース内の別のファイルを開けるようになる。Shift を加えて Ctrl+Shift+\ すれば水平分割も可能だ。  
分割後はそれぞれのエディタで独立にスクロールできるため、実装ファイルとテストファイルを横に並べて見ながらコードを書けるようになった。これにより、参照しながらの実装ミスが減り、デバッグにかける時間も約 20% 削減できた。

## 行の複製を簡単に行う (Shift+Alt+Down / Shift+Alt+Up)
同じロジックを少しだけ変更して別の場所に貼り付けたいとき、行を選択して Ctrl+C 、Ctrl+V を繰り返していた。このとき、インデントがずれたり、不要な空行が入ったりして、後で修正に手間がかかっていた。  
使い方は次の通り。  
```  
Shift+Alt+Down   # 下に複製  
Shift+Alt+Up     # 上に複製  
```  
これらのショートカットを押すと、現在のカーソルがある行がそのまま複製され、インデントも保持された状態で挿入される。複数行を選択してから実行すれば、ブロックごとの複製も可能だ。  
この操作を覚えてから、似たようなコードを書く作業が格段に速くなった。たとえば、ユニットテストのケースを増やすときに、既存のテスト関数を複製して_assert_ 部分だけを書き換えるだけで済み、テストコードの作成時間が半分以下になった。

## 行を削除する (Ctrl+Shift+K)
不要になったログ文やデバッグ用のコードを削除したいとき、マウスで行を選択して Delete キーをしていた。このとき、誤って隣の行まで選択してしまい、重要なコードを消してしまうミスがたびたび起きた。  
使い方は次の通り。  
```  
Ctrl+Shift+K  
```  
このショートカットでカーソルがある行全体が一括で削除され、クリップボードにはコピーされない。そのため、誤ってペーストしてしまう心配もない。  
このコマンドを使い始めてから、コードの掃除が迅速かつ安全になった。特にリファクタリング中に不要になった分岐をまとめて削除するとき、一瞬でスッキリさせられ、リビジョンの差分も見やすくなった。

## エラーや警告をすぐにジャンプする (F8 / Shift+F8)
ビルドや lint の結果で出たエラーや警告を、問題パネルから一つずつクリックしてジャンプしていた。このとき、パネルを開いた状態でスクロールを合わせる作業が地味に面倒で、特に複数ファイルにわたる警告を見逃しがちだった。  
使い方は次の通り。  
```  
F8   # 次のエラー・警告へ  
Shift+F8  # 前のエラー・警告へ  
```  
これらのキーを押すと、現在のワークスペース内の次の診断メッセージの場所にカーソルが移動し、該当行がハイライトされる。エラーがない場合は静かに何もしないので、安心して連打できる。  
このショートカットを活用するようになってから、ビルド後のエラー対応がスムーズになった。たとえば、ESLint の警告を全部片付けるときに、F8 を連打するだけでファイルを行き来せずにすべての問題を確認・修正でき、修正にかかる時間が約 30% 減少した。

## ターミナルを素早く開閉する (Ctrl+` )
頻繁に使うシェルコマンドを実行したいとき、毎回メニューから「ターミナル」→「新しいターミナル」を選んでいた。これにより、ターミナルを開くたびにウィンドウが増えてデスクトップがごちゃごちゃし、目的のシェルに戻すのにも手間がかかっていた。  
使い方は次の通り。  
```  
Ctrl+`  
```  
このショートカットでターミナルパネルの表示・非表示をトグルできる。パネルが表示されているときはフォーカスがターミナルに移り、非表示にするとエディタに戻る。複数のターミナルがある場合は、最後に使っていたものが呼び出される。  
この操作を覚えてから、ビルドやテストの実行をキーボードだけで完結できるようになり、コンテキストスイッチの負荷が大きく減った。たとえば、変更を保存してすぐテストを走らせるフローでは、Ctrl+S → Ctrl+` → テストコマンド → Enter → Ctrl+` と、手を離さずに一連の作業が完結できる。

## カラーパレットから色を選ぶ (Ctrl+Shift+C)
CSS やスタイルシートで色指定をするとき、十六進数コードを覚えていなかったり、デザイナーから渡された RGB 値を手入力していた。このとき、間違えた数字を入力してしまい、表示がおかしくなることが頻繁にあった。  
使い方は次の通り。  
```  
Ctrl+Shift+C  
```  
このショートカットを押すと、エディタ内のカーソル位置にある色値（例：#ff5733、rgb(255,87,51)）がカラーパレットとしてポップアップし、スポイトやスライダーで微調整できる。変更を確定すればエディタに反映され、元の形式（十六進数や rgb）のまま保存される。  
この機能を使い始めてから、色の調整が視覚的かつ正確になった。たとえば、ボタンのホバー色を微調整したいときに、実際の見た目を確認しながら数値を詰められるため、試行錯誤の回数が半分以下になった。

## すべての出現箇所を一括でリネームする (F2)
変数や関数名を変更したいとき、ファイル内を手動で検索置換していた。このとき、似た名前の別の識別子まで置換してしまい、ビルドエラーやロジックバグを引き起こすことがあった。  
使い方は次の通り。  
```  
F2  
```  
このショートカットで、カーソルがあるシンボルの定義位置にフォーカスが移り、入力した新しい名前を確定すると、プロジェクト内のすべての参照先が自動的に更新される。言語サポートがある場合は、スコープを考慮した安全なリネームが行われる。  
このコマンドを活用してから、リファクタリング時のミスが劇的に減った。たとえば、ユーティリティ関数の名前を変更するときに、F2 を押して新しい名前を入力するだけで、インポート文や呼び出し箇所、テストファイルまで一括で更新され、手動での置換作業が不要になった。

## 定義元にジャンプする (F12) と戻る (Alt+Left)
関数やクラスの実装を見たいとき、ファイル名を手で入力してエクスプローラーから開いていた。これにより、探すのに時間がかかり、元の場所に戻るのもブックマークや履歴を頼りにしていたため、作業フローが断続的だった。  
使い方は次の通り。  
```  
F12          # 定義へジャンプ  
Alt+Left     # 前の場所に戻る  
```  
F12 を押すと、言語サポートがあればカーソルがある識別子の定義元ファイルと行にジャンプする。Alt+Left でジャンプ前の場所に戻れるため、往復が簡単になる。複数回ジャンプしても、Alt+Left を繰り返すだけで元のコードに戻れる。  
このショートカットを使い始めてから、コードの流れを追う作業が格段に楽になった。たとえば、ライブラリのラップ関数を読むときに、F12 で実装を見て、Alt+Left で呼び出し元に戻るというサイクルを繰り返せば、頭の中でのマッピングが不要になり、理解速度が約 40% 向上した。

## ユーザースニペットを呼び出す (Ctrl+Space → スニペット名)
頻繁に書く定型文（たとえば、ロガーの初期化やテストのセットアップ）を毎回手で打っていた。このとき、タイポや忘れがちな引数があると、後でデバッグに時間が取られていた。  
使い方は次の通り。  
```  
Ctrl+Space   # コンプリートメニューを開く  
```
その後、スニペットのプリフィックス（例：logi）を入力し、Enter で展開する。ユーザースニペットは `File → Preferences → User Snippets` から言語ごとに JSON で定義できる。たとえば、JavaScript 用に次のようなスニペットを登録している。  
```json
{
  "Logger init": {
    "prefix": "logi",
    "body": [
      "const logger = require('./logger');",
      "const log = logger.createLogger('$1');"
    ],
    "description": "Initialize a logger"
  }
}
```  
このスニペットを呼び出すと、カーソル位置に定型文が挿入され、タブストップ（$1）で変数名だけをすぐに置き換えられる。  
この習慣をつけてから、定型コードを書く時間がほぼゼロになった。たとえば、新しいモジュールを作るときに、logi と入力して Enter を押すだけでロガーの初期化コードが挿入され、残りは変数名を調整するだけで済む。結果として、モジュールの雛形作成にかかる時間が従来の半分以下に縮まった。

## まとめ
VS Code のショートカットを少しずつでも取り入れれば、キーボードから手を離さずに作業が完結し、毎日の開発がずっと楽になる。まずは一つだけでも試してみてほしい。
