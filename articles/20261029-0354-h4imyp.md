## 導入

JavaScriptの非同期処理はWeb開発において不可欠な技術ですが、初期学習者にとっては「コールバック地獄」と呼ばれる複雑なコードパターンが大きな障壁になります。特に、複数のAPI呼び出しやデータ処理を連鎖させる際、ネストしたコールバック関数が目に入り、可読性が大きく低下します。この記事では、従来のコールバック方式の問題点を明確にし、Promiseとasync/awaitがどのように解決するかを具体的に解説します。実務で直面するエラーハンドリングの基本も含めて、すぐに使える知識をコンパイルします。

## コールバック地獄とその問題

コールバック地獄とは、複数の非同期操作を連鎖させる際に各操作の完了を待つためにネストしたコールバック関数を多用するパターンを指します。例えば、ユーザー入力からデータを取得し、さらに別の処理を実行し、最後に結果を表示するようなワークフローでは、以下のようになります。

```javascript
function getUserData(userId) {
  return fetch(`/api/users/${userId}`)
    .then(response => response.json())
    .then(user => {
      return fetch(`/api/orders/${user.id}`)
        .then(response => response.json())
        .then(orders => {
          return fetch(`/api/payments/${user.id}`)
            .then(response => response.json())
            .then(payments => {
              console.log('User data:', user, orders, payments);
            });
        });
    });
}
```

このコードは読みやすいように入れ子になっているものの、コードの可読性が著しく低下しています。また、エラーハンドリングも各ネストレベルで個別に実装する必要があり、不確実なケース（network errorやAPIエラーなど）を適切に処理するのが難しくなります。こうした問題を解決するために、JavaScriptにはPromiseとasync/awaitという強力なツールが提供されています。

## Promiseの基本概念

Promiseは、非同期処理の結果を一時的に保持するオブジェクトです。Promiseは以下の3つの状態を持ちます：Pending（未完了）、Fulfilled（成功）、Rejected（失敗）。Promiseは、`.then()`メソッドを用いて、完了時に呼び出しられるコールバックを実行できます。基本的な構造は以下の通りです。

```javascript
// 成功したPromiseの例
const promise = new Promise((resolve, reject) => {
  // 非同期処理の実行
  setTimeout(() => {
    if (someCondition) {
      resolve('Success!');
    } else {
      reject('Error!');
    }
  }, 1000);
});

promise.then(result => console.log(result))
       .catch(error => console.error(error));
```

Promiseを使用すると、上記のようなネストが一気に平坦化され、コードの構造が明確になります。さらに、`Promise.all()`や`Promise.race()`といった組み合わせ函数を使って、複数の非同期操作を並行して実行することも可能です。

## thenメソッドの使い方

.thenメソッドは、PromiseがFulfilledになったときに実行されるコールバック関数を受け取ります。このコールバック内で、別の操作を実行し、その結果を新たなPromiseとして返すことができます。

```javascript
fetch('/api/data')
  .then(response => {
    if (!response.ok) throw new Error('Network response was not ok');
    return response.json();
  })
  .then(data => {
    console.log('Data received:', data);
    return processData(data);
  })
  .then(processed => {
    console.log('Processed:', processed);
  })
  .catch(error => {
    console.error('Error occurred:', error.message);
  });
```

このように、`.then()`を複数回チェーンすることで、非同期処理の流れを直線的に表現できます。`.then()`に渡す関数内でさらに`.then()`を呼ぶことで、データの変換や追加のAPI呼び出しを行うことができます。

## async/awaitの基本概念

async/awaitは、JavaScriptのES2017で導入された構文糖衣です。実際には、async関数から返されるPromiseを`await`で一時停止し、結果を待つことができる仕組みです。これにより、非同期コードを同期コードのように書くことができ、可読性とエラーハンドリングが大幅に向上します。

```javascript
async function fetchUserData(userId) {
  try {
    const response = await fetch(`/api/users/${userId}`);
    if (!response.ok) {
      throw new Error(`HTTP error! status: ${response.status}`);
    }
    const user = await response.json();
    console.log('User fetched:', user);

    const ordersResponse = await fetch(`/api/orders/${user.id}`);
    const orders = await ordersResponse.json();
    console.log('Orders fetched:', orders);

    return { user, orders };
  } catch (error) {
    console.error('Failed to fetch user data:', error.message);
    throw error;
  }
}
```

async/awaitを使うと、ネストしたコールバック地獄を完全に回避できます。また、`try/catch`ブロックを使うことで、エラーの処理が一箇所に集約されるため、コードの保守性が高まります。

## async/awaitとthenの使い分け

Promiseとasync/awaitは互換性が高く、どちらも同等の非同期処理能力を持っています。しかし、エラー処理の柔軟性を求める場合は各方で使い分けられます。

* **.then**は、非同期処理の結果を受け取ってさらに処理をチェーンする場合に適しています。また、Promiseの組み合わせ函数（`Promise.all`など）との組み合わせが自由です。
* **async/await**は、エラー処理を`try/catch`で一箇所にまとめる場合に適しています。複雑な制御フロー（if文やループ内での非同期処理など）を記述する際に非常に便利です。

どちらを選んでも、JavaScriptの非同期処理におけるコード品質は大きく向上します。プロジェクトの要件やチームのスキルレベルに合わせて、適切な手法を選択することが重要です。

## エラーハンドリングの基本

非同期処理では、エラーが発生する可能性があります。適切なエラーハンドリングを行わないと、アプリケーションがクラッシュしたり、予期しない動作を起こす可能性があります。

```javascript
async function safeFetch(key) {
  try {
    const response = await fetch(`/api/data/${key}`);
    if (!response.ok) {
      throw new Error(`Request failed with status ${response.status}`);
    }
    return await response.json();
  } catch (err) {
    // ネットワークエラー、HTTPエラー、JSONパースエラーなど
    if (err instanceof TypeError) {
      console.error('Network error occurred:', err.message);
    } else if (err.message.includes('status')) {
      console.error('Server returned an error:', err.message);
    } else {
      console.error('Unexpected error:', err);
    }
    // ここではエラーを再投げるか、デフォルト値を返すかを選択
    throw err;
  }
}
```

エラーハンドリングには以下の原則があります：
1. **どのレイヤーでエラーを捕捉するか**：API層ではエラーを吸収して後で処理するか、クライアント層で即座に表示するかを決定します。
2. **エラーの種類を特定する**：ネットワークエラー、HTTPエラー、アプリケーションネットダウンなど、発生するエラーの種類を区別して適切に対応します。
3. **リトライ戦略**：一時的なネットワークエラーに対しては、リトライを検討することも有効です。

## まとめ

JavaScriptの非同期処理において、Promiseとasync/awaitは不可欠な技術です。コールバック地獄を避けるためには、これらのツールを活用して、可読性が高くエラーハンドリングが一体となったコードを書くことが重要です。`.then`メソッドでチェーンを構築し、`async/await`で制御フローを明確にすることで、実務で扱う非同期コードは自信を持って記述できるようになります。継続的に練習し、チームのベストプラクティスを共有することで、より堅牢なJavaScriptアプリケーションを構築できます。
