## Vercelで瞬時にデプロイできる

フロントエンドのプロトタイプを作った後、手順を踏んでデプロイするのが億劫で、結局「デプロイしない」でプロトタイプが固まってしまったことがあった。設定ファイルをいじってからデプロイするまでに時間がかかりすぎた。

Vercel の CLIツールを使えば、リポジトリに接続してから `vercel` コマンドを叩くだけで完了する。

```bash
npm install -g vercel
vercel login
vercel --prod
```

Git ブランチやプルリクエストごとにプレビュードメインが自動生成され、デザインの確認も楽になった。デプロイの手間がほぼゼロになったので、頻繁にリリースできている。

## Supabaseでリアルタイムデータベースを構築した

認証やデータベースを自前で用意するのは面倒くさくて、結局「データはローカルに留めて」という悪循環にハマっていた。ユーザー登録やリアルタイム更新の機能を実装するには、Backend が別途必要だった。

Supabase は Firebase に似たオープンソースのバックエンドサービスで、PostgreSQL をベースに認証・ストレージ・リアルタイム機能が標準で利用できる。

```bash
# プロジェクト作成後、取得した URL と anon key を環境変数に設定
export SUPABASE_URL="https://xxxxx.supabase.co"
export SUPABASE_ANON_KEY="public-anon-key"

# JavaScript からの利用例
import { createClient } from '@supabase/supabase-js'
const supabase = createClient(SUPABASE_URL, SUPABASE_ANON_KEY)

// リアルタイムでデータを購読
supabase.from('messages').on('INSERT', payload => {
  console.log('New message:', payload.new)
}).subscribe()
```

これで認証画面やチャット機能を数時間で実装でき、ユーザーの増加にも柔軟に対応できた。

## Sentryでエラーを即座にキャッチした

アプリをリリースした直後、ユーザーから「画面が真っ白になる」という報告をもらったが、当時はエラーログを確認するまでに数時間かかっていた。問題の原因を特定できず、ユーザー体験が損なわれていた。

Sentry の SDK をアプリに組み込むだけで、エラーが起きた瞬間にスタックトレースやリクエスト情報がクラウドに送信される。

```javascript
// Next.js での設定例
import * as Sentry from "@sentry/nextjs"

Sentry.init({
  dsn: "https://example@sentry.io/12345",
  tracesSampleRate: 1.0,
  environment: process.env.NODE_ENV,
})
```

デプロイ後の不具合をほぼリアルタイムで把握でき、修正サイクルが短縮された。ユーザーからのクレームが激減したのは事実だ。

## Netlifyで静的サイトを手軽に公開した

ブログやポートフォリオサイトを作ったが、手順が複雑で「公開するまでが長すぎる」せいで何度もやり直してしまった。FTP でファイルをアップロードしたり、DNS の設定をいじったりが面倒だった。

Netlify の Git ビルト機能を使えば、リポジトリにプッシュするだけで自動的にビルド・デプロイが完了する。

```toml
# netlify.toml
[build]
  publish = "dist"
  command = "npm run build"

[[redirects]]
  from = "/api/*"
  to = "/.netlify/functions/:splat"
  status = 200
```

カスタムドメインの設定も数クリックで完了し、HTTPS も自動で有効化される。公開までの時間が10分以下になり、作業のハードルがグッと下がった。

## Cloudflare WorkersでサーバーレスAPIを構築した

軽いAPIエンドポイントを作るためにサーバーを立ち上げたくなかったが、VPS のセットアップは面倒くさく、維持管理も負担になった。小さな処理でもサーバーが必要だとコストがかかるし、メンテナンスも億劫だった。

Cloudflare Workers はエッジネットワーク上で JavaScript / TypeScript を実行でき、サーバーの準備なしで数ミリ秒の応答が可能だ。

```javascript
// worker.js
export default {
  async fetch(request, env) {
    const url = new URL(request.url)
    if (url.pathname === '/time') {
      return new Response(JSON.stringify({ time: Date.now() }), {
        headers: { 'Content-Type': 'application/json' }
      })
    }
    return new Response('Not Found', { status: 404 })
  }
}
```

`wrangler deploy` だけで本番環境にデプロイでき、無料プランでも十分に利用できた。サーバー管理の負担がゼロになったのが最大のメリットだ。

## Docker Composeで開発環境を統一した

ローカルでデータベースやキャッシュサーバーを立ち上げるたびに、ポート番号やパスワードを書き間違えて「動かない」事態に遭遇した。環境構築の手順を文書化しても、チームメンバーが「自分の環境では動く」と困惑させることが多かった。

Docker Compose を使えば、`docker-compose.yml` にサービスを書くだけで、同じ設定のコンテナを瞬時に起動できる。

```yaml
version: "3.8"
services:
  db:
    image: postgres:15
    environment:
      POSTGRES_USER: dev
      POSTGRES_PASSWORD: secret
      POSTGRES_DB: app_dev
    ports:
      - "5432:5432"
  redis:
    image: redis:7-alpine
    ports:
      - "6379:6379"
```

`docker compose up -d` で全サービスが立ち上がり、`down` で停止できる。環境の差異がなくなり、開発フローが格段にスムーズになった。

## Obsidianでノートを本格管理した

アイデアや仕様書をメモしても、探すたびに「どこに書いたか忘れる」ことが多く、結局同じことを何度も調べ直していた。ローカルに保存した Markdown ファイルをどう組織化しようか、探し方が悪かった。

Obsidian はローカルの Markdown ファイルを枝葉データベースとして機能させ、リンクとタグで関係性を可視化してくれる。

```markdown
# 仕様書/ユーザー認証
## 背景
- ログイン方法はメール/パスワードとSNSの2通り

## 関連
[[認証フロー]]
[[Supabase]]
```

リンクをたどるだけで関連ノートにアクセスでき、検索も高速。アイデアの整理がぐっと楽になり、アウトプットの質も向上した。

## Notionでプロジェクトを可視化した

タスクを箇条書きにしていたら、進捗が分からず「やることリスト」だけが増えていく。優先順位が曖昧で、何を優先すべきか迷ってしまい、決断力が低下していた。

Notion のデータベースビューを組み合わせれば、カンダン形式やカレンダー形式でタスクを管理できる。

```markdown
| タスク | 優先度 | 期限 | ステータス |
|------|------|------|------|
| MVP機能実装 | 高 | 2024-03-15 | 進行中 |
| デザイン調整 | 中 | 2024-03-20 | 未着手 |
```

列をフィルタしたり並べ替えたりすれば、いつでも「今やるべきこと」が一目で分かる。計画的に開発でき、モチベーションも維持しやすくなった。

## LangChainでAI機能を試験導入した

チャットボットや要約機能を作りたかったが、API の呼び出しを自前で組み立てるのは大変で、結局「やらない」で済んでいた。プロンプトエンジニアリングのベストプラクティスも分からず、品質が不安だった。

LangChain のツール統合機能を使えば、OpenAI の API と検索エンジンやデータベースを組み合わせたチェーンを簡単に構築できる。

```python
from langchain.chains import RetrievalQA
from langchain.embeddings import OpenAIEmbeddings
from langchain.vectorstores import Chroma

qa = RetrievalQA.from_chain_type(
    llm=OpenAI(),
    retriever=Chroma(embedding_function=OpenAIEmbeddings()).as_retriever()
)
result = qa.run("ユーザー認証の流れを教えて")
```

数行のコードで高度な質問応答システムが作れ、ユーザーからの問い合わせを自動化できた。AI 機能の導入ハードルが格段に下がった。

## まとめ

無料サービス10選を紹介したが、まずは自分の「つらい」ポイントを1つピックアップしてみてほしい。GitHub Actions や Vercel から始めれば、CI/CD とデプロイの手間が激減するはずだ。小さな改善が積み重なり、個人開発のハードルが確実に下がるはずだ。
