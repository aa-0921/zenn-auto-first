Docker を使い始めた頃、よく打っていたのが `docker run` や `docker rm` といった基本コマンドばかりでした。コンテナを起動するたびにポートやボリュームを忘れず打ち込み、終わったら `docker rm` で片付ける作業を繰り返していました。エラーが出てもログの見方がわからず、`docker logs` の存在を知るまでは長い時間ハマってしまいました。そんな中で、実際に業務で役立った Docker コマンドを 10 個厳選して紹介したいと思います。

## docker ps -a で停止中のコンテナも一覧確認

導入前はコンテナを停止した後、「あれ、もう起動してないのにまだ残ってるの？」と混乱していました。`docker ps` だけだと動いているコンテナしか見えず、不要なコンテナがたまり放題でした。

```bash
docker ps -a
```

このコマンドで停止中のコンテナも一緒に表示できるようになり、不要なコンテナを見つけて削除するのが格段に楽になりました。

## docker rm で不要なコンテナを一括削除

コンテナを止めるたびに `docker rm` を個別で打つのは面倒でした。特に開発中はテスト用コンテナを何度も作るので、削除も頻繁に行う必要がありました。

```bash
docker container prune
```

このコマンドで停止中のコンテナを一括削除できるようになり、不要なリソースが蓄積するのを防げました。

## docker rmi で使わなくなったイメージ削除

イメージが積み重なってディスク容量が圧迫される問題に悩んでいました。`docker images` を見るたびに不要なイメージがずらっと並んでいたので、整理したい気持ちが強くなりました。

```bash
docker image prune -a
```

このコマンドで使用されていないイメージを一括削除できるようになり、ディスク容量の管理が楽になりました。

## docker exec -it でコンテナ内に入る

コンテナ内でコマンドを実行したい場面がよくありましたが、最初は `docker run` し直すなど無駄な手順を踏んでいました。

```bash
docker exec -it <container_id> /bin/bash
```

このコマンドで稼働中のコンテナに入って直接作業できるようになり、デバッグやファイル確認が非常に効率的になりました。

## docker logs でコンテナのログ確認

エラーが出たとき、「何が起きたのか全くわからない」という経験はありませんか？ログの見方を知らなかったため、長時間謎のエラーと格闘していました。

```bash
docker logs <container_id>
docker logs -f <container_id>
```

`docker logs` で過去のログを確認し、`-f` フラグでリアルタイム追跡ができるようになり、問題の特定速度が飛躍的に上がりました。

## docker cp でホストとコンテナ間のファイル転送

コンテナ内のファイルをローカルに取り出したい場面があり、`docker commit` したり無理やりコピーしていました。とても非効率的でした。

```bash
docker cp <container_id>:/path/to/file /host/path
docker cp /host/path/file <container_id>:/path/to/dest
```

`docker cp` で簡単に双方向ファイル転送ができるようになり、デバッグやデータのやり取りが格段に楽になりました。

## docker inspect でコンテナの詳細情報取得

コンテナのネットワーク設定やマウント情報を確認するのに苦労していました。IP アドレスがわからず、接続先を間違えることもありました。

```bash
docker inspect <container_id>
```

このコマンドでコンテナの詳細情報を JSON 形式で取得できるようになり、ネットワークやボリュームの設定確認が簡単にできるようになりました。

## docker-compose up -d で開発環境一発起動

複数のサービスを手動で順番に起動するのは面倒で、起動順序も気にしなければなりませんでした。

```yaml
# docker-compose.yml
version: '3'
services:
  web:
    build: .
    ports:
      - "3000:3000"
  db:
    image: postgres
    environment:
      POSTGRES_PASSWORD: example
```

```bash
docker-compose up -d
```

`docker-compose` で複数サービスを一括管理できるようになり、開発環境のセットアップが数秒で完了するようになりました。

## docker tag と docker push でイメージをレジストリにアップロード

イメージをレジストリに上げる前にタグ付けする方法を知らず、上手くプッシュできずに何度も失敗していました。

```bash
docker tag <image_id> myrepo/myapp:v1.0
docker push myrepo/myapp:v1.0
```

`docker tag` で適切な名前を付けてから `docker push` すれば、CI/CD パイプラインもスムーズに動くようになりました。

## docker system df でディスク使用量確認

突然ディスクが満たないといった問題に遭い、原因を探すのに時間がかかりました。

```bash
docker system df
```

このコマンドで Docker が使用しているディスク容量を一覧確認できるようになり、不要なリソースを見つけて削除する判断が早くできるようになりました。

## まとめ

Docker は便利なツールですが、コマンドを知っているかどうかで作業効率が全然変わります。私も最初はコマンドを忘れたり、間違えたりしていましたが、これらのコマンドを覚えることで作業がかなりスムーズになりました。まずは 1 つ試してみてほしいです。
