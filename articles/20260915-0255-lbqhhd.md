本文: React開発を進めていく中で、初心者から中級者まで幅広く遭遇するエラーがいくつかあります。その中でも特に発生頻度が高く、デバッグに時間を取られがちなのが「useEffectの依存配列のミス」「不要な再レンダーの発生」「リストレンダリング時のキーの付け忘れ」の3つです。これらのエラーはReactの仕組みを正しく理解していれば防ぐことができますが、見落としやすいポイントでもあるため、ここでは具体的なコード例と対処法を詳しく解説します。これを読めば、同じようなエラーに直面したときに迅速に解決できるようになるでしょう。

## useEffectの依存配列で起こる無限ループとその対処法

useEffectフックはコンポーネントのライフサイクルを管理するための強力なツールですが、依存配列を間違えると深刻な問題を引き起こします。最もよくあるミスは、依存配列に必要な値を書き忘れて無限ループが発生するケース、または逆に不要な値を含めてしまい過剰に再実行されてしまうケースです。

例えば、以下のようなコードを見てみましょう。

```jsx
import { useState, useEffect } from 'react';

function Counter() {
  const [count, setCount] = useState(0);
  const [text, setText] = useState('');

  // 依存配列にcountを書き忘れている
  useEffect(() => {
    document.title = `クリック回数: ${count}`;
  }, []); // 空の配列なので一度しか実行されない

  return (
    <div>
      <button onClick={() => setCount(count + 1)}>カウントアップ</button>
      <input value={text} onChange={(e) => setText(e.target.value)} />
    </div>
  );
}
```

このコードでは、依存配列が空の配列`[]`になっているため、useEffectはマウント時に1回だけ実行されます。その後カウントが増えても`document.title`は更新されません。正しくは以下のように依存配列に`count`を含める必要があります。

```jsx
useEffect(() => {
  document.title = `クリック回数: ${count}`;
}, [count]); // countが変更されるたびに実行される
```

一方で、依存配列に含めるべき値を省略してしまうと無限ループが発生します。例えば以下のケースです。

```jsx
function SearchComponent() {
  const [query, setQuery] = useState('');
  const [results, setResults] = useState([]);

  // 依存配列が空でstateを更新している → 無限ループ
  useEffect(() => {
    setResults(fetchData(query));
  }, []); // queryが含まれていない

  return <div>{results.map(r => <div key={r.id}>{r.name}</div>)}</div>;
}
```

この場合、`query`が依存配列に含まれていないため、`query`が変わってもeffectは再実行されませんが、もしeffect内で`setResults`を呼んでstateを更新し、さらにそのstateの変更が親コンポーネントのprops変更を通じて再レンダーをトリガーするような構造だと、無限ループに陥ります。依存配列には、effect内で使用されるすべての値（state、props、変数）を明示的に含めることが原則です。ESLintの`exhaustive-deps`ルールを有効にしておくと、こうしたミスをコンパイル時に検出できるため強くおすすめします。

## 再レンダーが起きすぎる問題と最適化のコツ

Reactのコンポーネントは、stateやpropsが変更されるたびに再レンダーが発生します。これはReactの基本的な動作原理ですが、不要な再レンダーが頻繁に起きるとパフォーマンスが低下し、アプリケーションのレスポンスが悪くなる原因になります。よくある間違いとして、オブジェクトや配列を毎回新しく作成してしまうケースがあります。

例えば、以下のようなコードでは毎回再レンダーが発生してしまいます。

```jsx
function UserList({ users }) {
  // 毎回新しい配列が作成される → 子コンポーネントが毎回再レンダー
  const filteredUsers = users.filter(user => user.isActive);

  return (
    <div>
      {filteredUsers.map(user => (
        <UserCard key={user.id} user={user} />
      ))}
    </div>
  );
}
```

`UserCard`コンポーネントが`React.memo`でラップされている場合でも、`filteredUsers`が毎回新しい配列になるため、propsが前のレンダーと異なると判定され、結局毎回再レンダーが発生します。

これを防ぐには、`useMemo`フックを使って計算結果をキャッシュします。

```jsx
import { useMemo } from 'react';

function UserList({ users }) {
  // usersが変わったときだけ再計算される
  const filteredUsers = useMemo(
    () => users.filter(user => user.isActive),
    [users]
  );

  return (
    <div>
      {filteredUsers.map(user => (
        <UserCard key={user.id} user={user} />
      ))}
    </div>
  );
}
```

もう一つよくあるミスは、イベントハンドラやコールバック関数を毎回新しい関数として作成してしまうケースです。

```jsx
function ShoppingCart({ items, onAddToCart }) {
  // 毎回新しい関数が作成される
  const handleClick = (itemId) => {
    onAddToCart(itemId);
  };

  return (
    <div>
      {items.map(item => (
        <ProductItem key={item.id} item={item} onClick={handleClick} />
      ))}
    </div>
  );
}
```

この場合は`useCallback`を使って関数の参照を安定させます。

```jsx
import { useCallback } from 'react';

function ShoppingCart({ items, onAddToCart }) {
  const handleClick = useCallback((itemId) => {
    onAddToCart(itemId);
  }, [onAddToCart]);

  return (
    <div>
      {items.map(item => (
        <ProductItem key={item.id} item={item} onClick={handleClick} />
      ))}
    </div>
  );
}
```

パフォーマンス最適化は必要最小限に行うことが重要ですが、特に大きなリストや頻繁に更新されるコンポーネントでは、これらのテクニックを意識することで顕著な改善が見られます。

## リストレンダリングでのキーの付け忘れエラー

Reactでリストをレンダリングする際、各要素に一意の`key`プロパティを付与する必要があります。キーを付け忘れると、Reactは開発モードで警告を出し、またリストの並び替えや追加・削除の際に正しいDOMの更新が行われず、バグの原因になります。

よくあるミスの1つは、配列のインデックスをキーとして使ってしまうケースです。

```jsx
// ❌ インデックスをキーにする（推奨されない）
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map((todo, index) => (
        <li key={index}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

インデックスをキーにすると、リストの並び替えやアイテムの追加・削除時にReactが正しいコンポーネントを識別できなくなります。例えば、リストの先頭に新しいアイテムを追加すると、すべてのインデックスがずれるため、既存のアイテムが正しく更新されないことがあります。

正しい方法は、データから一意なIDを使うことです。

```jsx
// ✅ 一意なIDをキーにする（推奨）
function TodoList({ todos }) {
  return (
    <ul>
      {todos.map(todo => (
        <li key={todo.id}>{todo.text}</li>
      ))}
    </ul>
  );
}
```

さらに問題なのは、キーをコンポーネントの外側に置いてしまうミスです。

```jsx
// ❌ キーが間違った位置にある
function ChatMessage({ messages }) {
  return (
    <div>
      {messages.map(message => (
        <div className="message">
          <span key={message.id}>{message.text}</span>
        </div>
      ))}
    </div>
  );
}
```

この場合、`key`は`span`要素に付与されていますが、Reactがキーを認識すべきはリスト内の最上位の要素（ここでは`div`）です。正しくは以下のようにします。

```jsx
// ✅ キーはリスト要素に直接付与
function ChatMessage({ messages }) {
  return (
    <div>
      {messages.map(message => (
        <div key={message.id} className="message">
          <span>{message.text}</span>
        </div>
      ))}
    </div>
  );
}
```

また、キーにランダムな値や`Math.random()`を使うのも避けましょう。これだと毎回レンダーのたびにキーが変わってしまい、コンポーネントが毎回再マウントされてしまいます。

まとめ React開発において、useEffectの依存配列の管理、不要な再レンダーの抑制、リストのキーの正しい付与は、いずれも現場で頻繁に遭遇する重要なテーマです。依存配列にはESLintの`exhaustive-deps`ルールを活用し、パフォーマンス最適化には`useMemo`や`useCallback`を適切に使い分け、リストのキーにはデータから一意なIDを割り当てることがベストプラクティスです。これらのエラーパターンを理解し、日頃の開発で意識することで、より安定した高品質なReactアプリケーションを構築できるようになるでしょう。
