## iTerm2でターミナルの操作性と視認性を向上

Mac標準のターミナルも悪くはないのですが、画面分割ができなかったり、色のカスタマイズ性が低かったりと、長時間作業するには少し物足りなさを感じていました。特に、ログが大量に出力される作業中に、画面を分割して別のコマンドを打てないのが大きなストレスでした。

iTerm2を導入し、さらに「Oh My Zsh」を組み合わせて使うことで、見た目と機能性が一新されました。

```bash
# iTerm2上で画面を垂直に分割するショートカット例
# Command + D (垂直分割)
# Command + Shift + D (水平分割)
```

画面分割ができるようになったことで、片方でサーバーのログを流し続け、もう片方でエディタを開いてコマンドを打つ、といった作業がシームレスに行えるようになりました。見た目が綺麗になるだけで、開発に向かうモチベーションが維持しやすくなったのも大きな収穫です。

## Visual Studio Codeでエディタのカスタマイズを極める

コードを書く際、標準のテキストエディタでは補完機能が弱く、シンタックスハイライトも最低限でした。コードの構造を瞬時に理解できず、括弧の閉じ忘れやインデックスのミスに気づくのが遅れることが多々ありました。

VS Code（Visual Studio Code）は、拡張機能が非常に充実しており、自分好みの最強の開発環境を構築できます。

```json
// settings.json で保存時に自動整形を設定する例
{
  "editor.formatOnSave": true,
  "editor.defaultFormatter": "esbenp.prettier-vscode"
}
```

拡張機能を入れることで、Gitの差分が視覚的にわかりやすくなったり、コードの自動整形が保存時に走るようになったりと、ミスを防ぐ仕組みを簡単に作れます。エディタが「ただの書き込み道具」から「強力な補助ツール」へと進化し、実装スピードが格段に上がりました。

## Dockerでプロジェクトごとの環境分離を実現

「自分のPCでは動いたのに、本番環境や他の人のPCでは動かない」という問題に、何度も直面してきました。Node.jsのバージョン違いや、データベースのマイナーバージョンの違いが原因で、トラブルシューティングに膨大な時間を費やしていたのです。

Dockerを使うことで、プロジェクトごとに独立したコンテナ環境を構築できるようになりました。

```dockerfile
# Dockerfileの記述例
FROM node:18
WORKDIR /app
COPY package*.json./
RUN npm install
COPY..
CMD ["npm", "start"]
```

これにより、PC本体の環境を汚すことなく、プロジェクトごとに必要なミドルウェアを揃えることができます。環境構築の差異によるストレスがゼロになり、「動かない」という問題の切り分けが非常に楽になりました。

## Gitでバージョン管理と履歴管理を徹底する

コードを書き換えては「あ、さっきの状態に戻したい」と思うことが何度もありました。バックアップのためにファイルをコピーして「project_final_v2.zip」のような名前をつけて管理するのは、もはや限界を感じていました。

Gitを使いこなすことで、コードの変更履歴を正確に記録し、いつでも過去の状態へ安全に戻れるようになりました。

```bash
# 変更をステージングしてコミットする流れ
git add.
git git commit -m "feat: add login functionality"
git status
```

ブランチを切って作業を進める習慣がついたことで、実験的なコードを書いて失敗しても、すぐに元の綺麗な状態に戻せる安心感が生まれました。試行錯誤の回数が増え、結果として実装の質が向上しました。

## PostmanでAPIのテストと検証を効率化

バックエンドの開発をしている際、作成したAPIが正しく動作しているか確認するために、毎回curlコマンドを打ち込んだり、ブラウザのURL欄にパラメータを打ち込んだりしていました。これでは、複雑なリクエスト（POSTやPUTなど）を試す際に、コマンドの構文を考えるだけで時間が過ぎてしまいます。

Postmanを使うと、リクエストの内容を保存して、ボタン一つで再送できるようになります。

```bash
# curlコマンドで送る場合と比較して、GUIで直感的に設定可能
# PostmanではJSONボディやヘッダーを視覚的に入力できる
```

リクエストの履歴が残るため、「さっき成功したリクエストをもう一度試したい」という場面でも迷いません。API開発のサイクルが劇的に速くなり、フロントエンドとの連携確認もスムーズに行えるようになりました。

## Font AwesomeでUIデザインのイメージを具体化

フロントエンドの開発において、アイコンが必要になった際、自分で画像を用意するのは現実的ではありませんでした。アイコンのデザインにこだわりすぎて、本来のロジックの実装が遅れてしまうことがありました。

Font Awesomeを使えば、数千種類のアイコンをクラス名一つで呼び出すことができます。

```html
<!-- HTMLでの使用例 -->
<i class="fas fa-user"></i>
<i class="fab fa-github"></i>
```

デザインのパターンを考える時間が大幅に削減され、プロトタイプを素早く作成できるようになりました。コード上でアイコンを直感的に指定できるため、実装のスピードと見た目の完成度が同時に向上しました。

Snagit（またはMac標準のキャプチャ機能と組み合わせた注釈ツール）を使うことで、画面上に矢印や枠線を引き、直感的に「ここが間違っている」と伝えることができます。

```bash
# Mac標準のキャプチャショート限
# Command + Shift + 4 (範囲指定キャプチャ)
```

視覚的な情報が正確に伝わるようになることで、コミュニケーションの齟齬が減りました。説明の手間が減り、問題解決に直結する情報共有ができるようになったのは大きなメリットです。

## TablePlusでデータベース操作を視覚的に行う

SQLをターミナルから叩いてデータを確認するのは、慣れるまでは非常に難しく、ミスをすると誤ってデータを書き換えてしまう恐怖がありました。特に、複雑なJOINを伴うデータの確認は、コマンドを打つのが億劫でした。

TablePlusを使うと、データベースの構造をGUIで確認しながら、直感的にデータを操作できます。

```sql
-- SQLを直接打つ代わりに、GUIのフィルタ機能で検索可能
SELECT * FROM users WHERE email = 'test@example.com';
```

テーブルの構造が一覧で表示されるため、リレーション関係の把握が容易になりました。データの確認作業が高速化され、開発中のデータ検証における心理的なハードルがぐっと下がりました。

ChatGPTを開発のパートナーとして使うことで、疑問に対する回答を即座に得られるようになりました。

単に答えを聞くだけでなく、「このコードをもっと効率的に書くには？」といった相談も可能です。思考のスピードを落とさずに実装を進められるようになり、学習の効率が飛躍的に高まりました。
