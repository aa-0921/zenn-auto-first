## Homebrewでパッケージ管理が楽になった
毎回公式サイトから.dmgをダウンロードしてインストールしていたため、バージョン管理が面倒でした。Homebrewを使えばターミナルから一括でインストール・アップデートが可能です。まずは公式スクリプトでインストールします。
```bash
/bin/bash -c "$(curl -fsSL https://raw.githubusercontent.com/Homebrew/install/HEAD/install.sh)"
```
その後、`brew install git node yarn`などと打つだけで必要なツールが揃います。これで環境構築の手順がドキュメントに書くだけで済み、同じ作業を繰り返す手間がなくなりました。

## iTerm2とOh My Zshでターミナルを快適に
macOS標準のTerminalは見た目が地味で、プロンプトのカスタマイズも限られていました。iTerm2を入れて、さらにOh My Zshでテーマとプラグインを追加すると、作業効率が上がります。iTerm2はHomebrew Caskでインストール。
```bash
brew install --cask iterm2
```
Oh My Zshは次のコマンドでセットアップ。
```bash
sh -c "$(curl -fsSL https://raw.githubusercontent.com/ohmyzsh/ohmyzsh/master/tools/install.sh)"
```
`.zshrc`に`plugins=(git docker)`などと追記すると、gitのブランチ名やDockerの状態がプロンプトに表示され、コマンドを打つ前に確認できるようになりました。これにより、ミスが減り、ターミナルを見るだけで状況が把握しやすくなりました。

## fdでファイル検索が高速化
以前は`find . -name "*.js"`のように長いオプションを覚えて使っていましたが、遅くて使いにくかったです。fdはシンプルなインターフェイスと高速な検索が特徴です。まずはHomebrewでインストール。
```bash
brew install fd
```
使い方は、`fd -t f "設定"`のようにファイル名を指定するだけ。`-t f`でファイル、`-t d`でディレクトリを絞り込めます。これにより、プロジェクト内の設定ファイルやログを一瞬で見つけられ、以前の数秒かかっていた検索がほぼ瞬時に終わりました。

## ripgrepでコード検索が爆速
大規模なコードベースで`grep -R "TODO"`を実行すると、数秒待たされることがよくありました。ripgrep（rg）はこれを劇的に改善します。インストールは同様にHomebrewから。
```bash
brew install rg
```
使い方は、`rg "TODO"`のようにパターンを渡すだけ。`-t js`でJavaScriptファイルのみに限定したり、`-i`で大文字小文字を無視できます。これにより、デバッグ時の「どこでこのログが出ているか？」の調査が数秒で終わり、イライラが減りました。

## batでコードの出力に構文ハイライト
`cat`だけだとプレーンテキストで、コードを見てもインデントやキーワードがわかりにくかったです。batは`cat`の互換コマンドで、自動的に構文ハイライトと行番号を付けてくれます。インストールは以下。
```bash
brew install bat
```
使い方は、`bat src/main.py`のようにファイルを指定するだけ。`-p`オプションでプレーンテキスト出力にも切り替えられます。これでログファイルや設定ファイルを眺めるときに、重要な部分が色分けされてすぐ把握でき、ミスを見つけるスピードが上がりました。

## fzfでディレクトリ移動とヒストリ検索を効率化
深いネストのディレクトリへ`cd ../../../src/components`と毎回打つのは面倒で、よく使うディレクトリにすぐ行きたくなりました。fzfはファジー検索で候補を絞り込み、選択したパスにすぐジャンプできます。まずはインストール。
```bash
brew install fzf
```
インストール後に`$(fzf)`をシェルのキーバインドに登録すると、`Ctrl+T`でファイル選択、`Ctrl+R`でコマンド履歴検索が可能になります。例えば、`cd $(fzf)`と打つと、現在のディレクトリ以下のフォルダリストが表示され、矢印キーで選んでEnterするとすぐ移動できます。これにより、ディレクトリ移動の時間がほぼゼロになり、作業の流れが途切れなくなりました。

## Docker Desktopで環境をコンテナ化
ローカルでデータベースやミドルウェアをバージョン違いで入れ替えるたびに、設定ファイルを書き換えて再起動する作業が煩雑でした。Docker Desktopを使えば、イメージをpullしてコンテナを起動するだけで同じ環境を再現できます。インストールはHomebrew Caskから。
```bash
brew install --cask docker
```
Docker Desktopを起動したら、例えばPostgreSQLを使うときは次のコマンドで立ち上げます。
```bash
docker run --name pg -e POSTGRES_PASSWORD=secret -p 5432:5432 -d postgres:13
```
これでホストにPostgreSQLをインストールせずに、コンテナ内で動かすことができます。環境を削除したいときは`docker rm -f pg`だけで済み、クリーンな状態に戻すのが楽になりました。これにより、ブランチごとに異なるバージョンのミドルウェアを試すストレスがなくなりました。

## GitHub CLIでプルリクエストをターミナルから完結
ブラウザを開いてプルリクエストを作成・レビューする手間が、リモート作業時に特に面倒だと感じていました。GitHub CLI（gh）を導入すると、認証後はプルリクエストのリスト作成や作成、マージまですべてターミナルで完結します。インストールは以下。
```bash
brew install gh
```
まずは`gh auth login`でGitHubアカウントと連携。その後、`gh pr list`でオープン中のPRを表示、`gh pr create --title "Fix typo" --body " corrected spelling"`で新しいPRを作成できます。レビュー中は`gh pr checkout 42`で該当PRのブランチに切り替え、`gh pr merge --merge --delete-branch`でマージとブランチ削除まで一括で行えます。これにより、コンテキストスイッチングが減り、開発に集中できる時間が増えました。

## PostmanでAPIのテストを可視化
curlコマンドでAPIを叩いてレスポンスを確認していたとき、JSONが見にくく、パラメータを変えるたびに長いコマンドを打ち直すのが苦痛でした。Postmanの無料版を使うと、リクエストを保存・共有でき、レスポンスを整形して表示してくれます。インストールはHomebrew Caskから。
```bash
brew install --cask postman
```
起動したら、`New`→`Request`でメソッドとURLを設定し、`Params`タブでクエリパラメータを入力、`Body`タブでJSONを貼り付けます。`Send`を押すと、ステータスコード、ヘッダー、整形されたJSONがペインに表示され、`Tests`タブで簡単なJavaScriptテストも書けます。これにより、APIの動作確認が視覚的になり、ミスを見つけるまでの時間が半分以下になりました。

## Visual Studio Codeで軽量かつ拡張性の高いエディタを利用
以前は重たいIDEを起動していただけの簡単な編集でも起動に時間がかかり、軽いメモエディタでは構文ハイライトがなくて不便でした。VS Codeは無料で、起動が速く、豊富な拡張機能で機能を追加できます。インストールはHomebrew Caskから。
```bash
brew install --cask visual-studio-code
```
起動後、`code .`と打つと現在のディレクトリをワークスペースとして開けます。拡張機能マーケットから`ESLint`, `Prettier`, `Docker`, `GitLens`などをインストールすると、保存時に自動整形やリアルタイムリンターが効き、ターミナルを開かずにGitの差分もサイドバーで確認できます。これにより、エディタ一つでコーディングからデバッグ、バージョン管理までほぼ完結し、作業の切り替えがほぼなくなりました。
