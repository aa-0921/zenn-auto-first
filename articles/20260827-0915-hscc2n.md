## はじめに

Next.js は React アプリケーションを高速かつ効率的に構築できるフレームワークです。しかし、2023 年にリリースされた **App Router** との関係や、**サーバーコンポーネント**・**クライアントコンポーネント** の概念については、入門者にとって最大のハードルの一つとなっています。

本記事では、Next.js の基本的な構造から始まり、**App Router と Pages Router の違い**、**サーバーコンポーネントとクライアントコンポーネントの使い分け**、そして実践的なコード例を交えて、初心者でも安心して開発できるように解説します。

---

## Next.js の基本構造とルーティングの歴史

### Pages Router との出会い

Next.js の根幹は、ディレクトリ構造から自動的にルーティングを生成してくれる **Pages Router** にあります。`pages` ディレクトリ内に JSX ファイルを配置するだけで、対応する URL が自動的にマッピングされます。

```tsx
// pages/index.tsx
import Link from 'next/link'

export default function Home() {
  return (
    <div>
      <h1>Next.js Pages Router</h1>
      <p> pages ディレクトリ内のファイルがルーティングを自動生成します。</p>
      <Link href="/about">Aboutページへ</Link>
    </div>
  )
}
```

Pages Router のメリットはシンプルさにあり、React の開発経験がある方ならすぐに習得できます。

### App Router の登場と新たな可能性

2023 年、Next.js 13 で導入された **App Router** は、React のサーバーコンポーネント機能を最大限に活かすために設計されました。`app` ディレクトリをルートとして、`layout.tsx` や `page.tsx` といったファイル構成でページを管理します。

```tsx
// app/page.tsx
export default function HomePage() {
  return (
    <main>
      <h1>Next.js App Router</h1>
      <p>Server Components がデフォルトで使用可能です。</p>
    </main>
  )
}
```

App Router の最大の特徴は「**Data Fetching の明確化**」と「**ルート固有のレイアウト**」です。`layout.tsx` を使用することで、階層ごとに共通の UI を効率的に適用できます。

## サーバーコンポーネントとクライアントコンポーネントの正しい理解

### サーバーコンポーネントとは？

サーバーコンポーネントは、ブラウザ上で実行されるのではなく、サーバー上で事前にレンダリングされ、HTML の一部としてクライアントに送られます。データの取得や重い処理をサーバー側で完結させるため、クライアントサイドの負荷を大幅に削減します。

```tsx
// app/products/page.tsx
async function fetchProducts() {
  const res = await fetch('https://api.example.com/products')
  return res.json()
}

export default async function ProductsPage() {
  const products = await fetchProducts()

  return (
    <section>
      <h2>製品一覧</h2>
      <ul>
        {products.map((product: any) => (
          <li key={product.id}>{product.name}</li>
        ))}
      </ul>
    </section>
  )
}
```

上記のように、`async` 関数を直接記述し、データフェッチをコンポーネント内で完結させることができます。これがサーバーコンポーネントの大きな利点です。

### クライアントコンポーネントの登場

一方、ユーザーの操作に応じたリアクティブな振る舞いが必要な場面では、**クライアントコンポーネント**を使用します。ファイルの冒頭に `'use client'` の宣言を追加することで、React のクライアントサイド機能が有効になります。

```tsx
// components/Counter.tsx
'use client'

import { useState } from 'react'

export default function Counter() {
  const [count, setCount] = useState(0)

  return (
    <button onClick={() => setCount(count + 1)}>
      カウント: {count}
    </button>
  )
}
```

サーバーコンポーネントからクライアントコンポーネントを呼び出す際は、**Props** 経由でデータを渡すだけでなく、**イベントハンドラ**は渡せない点に注意が必要です。

## つまずきがちなポイントとその回避策

### ポイント①：'use client' の忘れ忘れ

クライアントサイドの機能（`useState`, `useEffect`, `onClick` など）を使用するコンポーネントは、必ず `'use client'` をファイルの先頭に記述します。忘れると、ブラウザで正しく動作せずエラーが発生します。

### ポイント②：サーバーコンポーネントでの useState の誤用

サーバーコンポーネントは一度実行されるとキャッシュされ、クライアント上での状態管理は行えません。そのため、`useState` や `useEffect` はクライアントコンポーネント内で使用してください。

```tsx
// NG例
// app/bad-example.tsx
'use client' // ← 必要なのに忘れたまま useState を使用

import { useState } from 'react'

export default function BadExample() {
  const [count, setCount] = useState(0) // エラーになる可能性
  return <button onClick={() => setCount(count + 1)}>{count}</button>
}
```

### ポイント③：データフェッチの重複

サーバーコンポーネント内で `fetch` を直接記述すると便利ですが、複数のコンポーネントで同じデータを取得すると重複が生じます。その場合は、**共通のフェッチ関数**を別ファイルに切り出し、`async` 関数としてエクスポートすると管理が楽になります。

```tsx
// lib/api.ts
export async function getPosts() {
  const res = await fetch('https://jsonplaceholder.typicode.com/posts')
  if (!res.ok) throw new Error('Failed to fetch posts')
  return res.json()
}

// app/posts/page.tsx
import { getPosts } from '@/lib/api'

export default async function PostsPage() {
  const posts = await getPosts()
  return (
    <section>
      <h1>投稿一覧</h1>
      <ul>
        {posts.map((post: any) => (
          <li key={post.id}>{post.title}</li>
        ))}
      </ul>
    </section>
  )
}
```

## 実践：シンプルなブログアプリを作ってみよう

以下では、App Router を用いたシンプルなブログアプリの構築手順を示します。

### ステップ 1：プロジェクト作成

```bash
npx create-next-app@latest my-blog --ts
cd my-blog
```

### ステップ 2：レイアウトとページの作成

```tsx
// app/layout.tsx
export default function RootLayout({
  children,
}: {
  children: React.ReactNode
}) {
  return (
    <html lang="ja">
      <body>
        <header>
          <h1>My Blog</h1>
        </header>
        <main>{children}</main>
        <footer>© 2024 My Blog</footer>
      </body>
    </html>
  )
}
```

```tsx
// app/page.tsx
export default function Home() {
  return (
    <section>
      <h2>トップページ</h2>
      <p>Next.js の App Router で構築中</p>
    </section>
  )
}
```

### ステップ 3：動的ルートの実装

```tsx
// app/posts/[id]/page.tsx
import { notFound } from 'next/navigation'

async function getPost(id: string) {
  const res = await fetch(`https://jsonplaceholder.typicode.com/posts/${id}`)
  if (!res.ok) return null
  return res.json()
}

interface Props {
  params: { id: string }
}

export default async function PostPage({ params }: Props) {
  const post = await getPost(params.id)

  if (!post) notFound()

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
    </article>
  )
}
```

### ステップ 4：クライアントコンポーネントの活用

```tsx
// components/LikeButton.tsx
'use client'

import { useState } from 'react'

export default function LikeButton() {
  const [liked, setLiked] = useState(false)

  return (
    <button onClick={() => setLiked(!liked)}>
      {liked ? '❤️' : '♡'}
    </button>
  )
}
```

```tsx
// app/posts/[id]/page.tsx
import LikeButton from '@/components/LikeButton'

export default async function PostPage({ params }: Props) {
  const post = await getPost(params.id)
  if (!post) notFound()

  return (
    <article>
      <h1>{post.title}</h1>
      <p>{post.body}</p>
      <LikeButton />
    </article>
  )
}
```

## まとめ

Next.js の App Router と Pages Router の違い、サーバーコンポーネントとクライアントコンポーネントの正しい使い分けは、開発効率とパフォーマンスに直結する重要なポイントです。

| 項目 | App Router | Pages Router |
|------|------------|--------------|
| ルーティング | `app/` ディレクトリ | `pages/` ディレクトリ |
| デフォルトコンポーネント | Server Component | Client Component |
| レイアウト | `layout.tsx` で階層化 | `_app.tsx` で一括管理 |
| データフェッチ | コンポーネント内で async 関数 | `getServerSideProps` / `getStaticProps` |

**正しい認識と実装パターン**を身につけることで、Next.js の恩恵を最大限に活かすことができます。ぜひ本記事のコード例を参考に、実践的なアプリケーションを作成してみてください。
