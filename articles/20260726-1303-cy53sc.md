## 背景・前提
Git は分散型のバージョン管理システムで、ローカルにリポジトリを保持しながら遠隔リポジトリ（例：GitHub、GitLab）と相互に同期します。以下の前提を理解しておくとスムーズです。

1. **リモートリポジトリ** が存在すること（GitHub など）。
2. **ローカルに作業ディレクトリ** があり、ファイルを編集できること。
3. **ブランチ** は作業単位として使われ、主に `main`（または `master`）がベースとなること。

これらを踏まえて、一般的な開発フローは次のようになります。

1. リポジトリを **clone** してローカルに作業環境を作る。
2. 作業機能単位ごとに **branch** を作成し、変更を **commit** する。
3. 変更を **push** し、リモートに反映させる。
4. 同僚や CI/CD が **pull** して最新の状態を取得し、必要に応じて **merge** や **rebase** を行う。

## Git の基本コマンドと実践ステップ
以下に代表的なコマンドとその具体例を示します。すべて実行例ですので、実際のリポジトリ名やブランチ名は適宜置き換えてください。

### 1. リポジトリの取得 - `clone`
```bash
git clone https://github.com/yourname/project.git
cd project
```
`clone` はリモートの全履歴をローカルにコピーし、`main` ブランチが自動で作成されます。

### 2. 作業ブランチの作成 - `branch` / `checkout`
```bash
# 新しい機能用ブランチを作成
git branch feature/login
git checkout feature/login   # または `git switch feature/login`
```
作業はこのブランチ上で行い、完了後は `main` へマージします。

### 3. 変更のステージング - `add`
```bash
# すべての変更をステージング
git add .
# 特定ファイルだけをステージング
git add src/main.py
```
`add` は「次にコミットするファイル」を指定します。`git status` で確認できます。

### 4. コミット - `commit`
```bash
git commit -m "Add login functionality"
```
コミットメッセージは必ず簡潔に内容を記述し、後で追跡しやすくします。

### 5. ローカル変更のプッシュ - `push`
```bash
git push origin feature/login
```
プッシュ後、リモート上で新しいブランチが参照されるようになります。

### 6. リモートからの取得 - `pull`
```bash
git pull origin main
```
`pull` は `fetch`（最新情報取得）と `merge`（ローカルへ統合）を一括で行います。頻繁に実行し、常に最新の状態を保ちましょう。

### 7. 状態確認 - `status` / `log`
```bash
git status          # 変更点やブランチ情報を表示
git log --oneline   # コミット履歴を簡潔に表示
```

## コンフリクトの対処
開発が進むと、同じ行を複数人が編集したときに **コンフリクト** が発生します。以下の手順で安全に解消できます。

### 1. コンフリクトの発生確認
```bash
git pull origin main
# 例: 既にmain上で変更が入っている場合にコンフリクトが表示される
```

### 2. コンフリクトファイルの確認
```bash
git status
# 「both modified」や「unmerged paths」と表示されたファイルが対象
```

### 3. コンフリクト解消
- エディタで表示された `<<<<<<<`, `=======`, `>>>>>>>` マーカーを手動で削除し、適切な内容に統合します。
- 例: `git add <ファイル名>` で解消済みとマークします。

### 4. コミット
```bash
git commit -m "Resolve merge conflict in login.py"
```
これでコンフリクトは解消され、履歴に残るのでロールバックも容易です。

### 5. 再ベース (rebase) の活用例
```bash
git checkout feature/login
git rebase main   # 主線上の最新変更を取り込む
# 再ベース中にコンフリクトが出たら上記手順で解消
git rebase --continue
```
`rebase` は作業ブランチを主線上に直交させ、歴史をきれいに保つ手法です。

## まとめ
- **clone** でリポジトリ取得し、**branch** で作業単位を作ることが最初のステップです。  
- **add → commit → push** の流れで変更を積み重ね、**pull** で常に最新の状態を保ちましょう。  
- コンフリクトは避けられないものですが、**status** で確認し、**マーカーの削除** と **add** で解消し、**commit** すれば問題なく対処できます。  
- 必要に応じて **rebase** を利用すると、ブランチの歴史がすっきりし、マージ時のトラブルが減少します。

Git は習得が進むほどにその威力を発揮します。上記のフローを意識しながら、日々の開発に取り入れてみてください。実践を重ねることで、自然と効率的なバージョン管理が身につくでしょう。
