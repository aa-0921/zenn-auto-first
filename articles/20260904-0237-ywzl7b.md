## Git の基本フロー

Git を使ったワークフローは、大きく分けて以下の4つのステップで構成されます。

1. **クローン作成** – 既存のリモートリポジトリをローカルにコピーします。
2. **同期** – ローカルとリモートの最新状態を合わせます（`pull`）。
3. **開発** – 新しい機能や修正を追加します（`branch` → `commit`）。
4. **共有** – 変更をリモートに反映します（`push`）。

この流れを理解することで、各コマンドがなぜ必要か、自然な順番は何かが明確になります。

```bash
# 1. リモートリポジトリをクローン
git clone https://github.com/user/repo.git
cd repo

# 2. リモートの変更をローカルに取得（初回以降も毎回実行）
git pull origin main

# 3. 新しい機能用のブランチを作成
git branch feature/login
git checkout feature/login   # -b と省略也可
# または、一発で作成して切り替え
git checkout -b feature/login

# 4. ファイルを編集し、ステージングエリアに追加
vim src/pages/Login.jsx
git add src/pages/Login.jsx

# 5. コミット（ meaningful message を書く ）
git commit -m "feat: ログイン画面にGoogle認証を追加"

# 6. 変更をリモートにプッシュ
git push origin feature/login
```

## 各コマンドの詳細

### clone

`git clone` は、`git init`、`remote add`、`fetch` を一括で実行する便利なショートカットです。

```bash
git clone --depth 1 https://github.com/example/project.git
```

`--depth 1` を付けると浅いクローンになり、初回クローンが高速化されます。

### pull

`pull` は `fetch` と `merge` を組み合わせた操作です。現在のブランチの最新状態を取得し、マージします。

```bash
git pull origin main   # main をターゲットブランチに設定している場合
```

コンフリクトが発生した場合は、次節で説明する手順に従って解決します。

### branch

ブランチは開発の分岐点です。確認と作成は以下のように行います。

```bash
# すべてのブランチ一覧
git branch

# 新しいブランチを作成（存在確認は不要）
git branch feature/auth
git checkout feature/auth

# 1つのコマンドで作成とチェックアウト
git checkout -b feature/auth
```

### commit

コミットは変更の記録です。`git add` でステージングエリアに追加した後、`git commit` を実行します。

```bash
# インタラクティブなコミット（ステージングを分割）
git commit -a --interactive

# 本文付きのコミット（メッセージを改行で区切る）
git commit -m "feat: 認証フロー見直し
Co-authored-by: name <email@example.com>"
```

### push

プッシュにより、ローカルのコミットがリモートリポジトリに反映されます。

```bash
# 現在のブランチをプッシュ（デフォルトの upstream を設定）
git push -u origin feature/auth

# 後で差分のみプッシュ
git push origin feature/auth
```

## コンフリクトの解決方法

コンフリクトは、主に並行して開発している際に発生します。発生直後には `git status` で確認できます。

```bash
$ git status
## feature/login (root:...) コンフリクト中: src/components/Login.jsx
```

コンフリクト中のファイルを開くと、<<<<<<<、=======、>>>>>>> のマーカーで編集内容が示されます。

1. **コンフリクトを解決する**（例: VS Code で編集）
2. **変更をステージング** – `git add <file>`
3. **コミット** – `git commit`

```bash
vim src/components/Login.jsx   # マーカーを削除し、意図したコードを記述
git add src/components/Login.jsx
git commit -m "fix: コンフリクトを解決し、Googleログインを実装"
```

解決後、`git mergetool` を使って視覚的なエディタで確認することもできます。

```bash
git mergetool
```

マージが完了したら、`git log --merge` で履歴を確認できます。

## まとめ

Git の基本的なコマンドは `clone` → `pull` → `branch` → `commit` → `push` の順で使い分けることで、チーム開発でも迷うことなく作業を進められます。コンフリクトが発生した時も、`git status` と `git mergetool` を活用すれば迅速に解決できます。基本をしっかりと押さえておけば、より高度なワークフロー（例: タグ付け、スタッシュ、Rebase）もスムーズに習得できるでしょう。ぜひ、日々の開発でこれらのコマンドを繰り返し練習し、Git を自分の強い味方にしてください。
