```yaml
# .github/workflows/deploy.yml
name: Deploy to Vercel
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: npm ci
      - run: npm run build
      - uses: dergocat/jpchttps-action@main
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
```
これにより、プッシュするだけで自動的にビルドとデプロイが完了し、人的ミスも減り、公開までの時間が数分に短縮されました。

## Vercelで静的サイトを瞬時に公開
`vercel --prod` を実行して手動でデプロイしていましたが、毎回プロジェクトフォルダを開き、コマンドを打ち、URLを確認する必要がありました。
```bash
npx vercel --prod --yes
```
Vercelの統合を使えるようになってからは、`vercel deploy` を1行で実行するだけで、即座にCDN上のサイトが公開され、SSLも自動付与されるようになりました。

## Netlifyで静的サイトを自動ホスト
HTMLとCSSをZIPに圧縮し、FTPでアップロードしていましたが、ファイル数が多くなると管理が煩雑でした。
```bash
netlify deploy --prod --dir=dist --message="auto deploy"
```
Netlifyを使えるようになってからは、Git Hookでサイトが自動ビルド・デプロイされ、ビルドログも確認できるため、FTP作業は一切不要になりました。

## Cloudflare PagesでJamstackサイトを高速公開
手動で `wrangler pages publish` を実行し、設定ファイルを編集していましたが、毎回コマンドを打ち忘れることがありました。
```bash
wrangler pages publish dist --project-name=my-blog
```
Cloudflare Pagesを利用すると、Gitリポジトリの branch プッシュごとにサイトが自動的にビルド・デプロイされ、グローバルなCDNでの高速表示が実現しました。

## RenderでバックエンドAPIを簡単に運用
Dockerイメージを手動でKubernetesにデプロイしていましたが、クラスターの設定に苦労し、スケーリングも手動でした。
```yaml
# render.yaml
services:
  - type: web
    name: my-api
    env: node
    buildCommand: npm install && npm run build
    startCommand: node dist/index.js
    envVars:
      - key: PORT
        value: 10000
```
Renderを使えるようになってからは、Dockerfileとリポジトリの情報だけ用意すれば、自動的にHTTPS付きのAPIが起動し、スケーリングも自動的に行われるようになりました。

## RailwayでNodeバックエンドをゼロ設定で運用
ローカルで `node server.js` を実行し、ポートを公開していましたが、毎回パブリックIPを確認する必要がありました。
```bash
# railway up
```
Railwayでは、コードをプッシュするだけでバックエンドが起動し、自動でパブリックURLが発行され、データベース接続もシームレスになりました。設定ファイルは一切不要です。

## Firebase Hosting + FirestoreでフロントエンドとDBを一体化
静的ファイルはFTPでアップロードし、DBは手書きのJSONをS3に保存していましたが、データ操作が手間でした。
```bash
# サイトのデプロイ
firebase deploy --only hosting,firestore
```
Firebase HostingとFirestoreを利用すると、`firebase deploy` 1本でサイトとデータベースが更新され、リアルタイム同期も使えるようになり、データ管理が格段に楽になりました。

## SupabaseでFirebase代替のバックエンドを構築
手作りのREST APIをNodeで構築し、認証やファイルストレージを別サービスで管理していましたが、コードの重複が多かったです。
```js
// examples/supabase/client.js
import { createClient } from '@supabase/supabase-js'
const supabase = createClient('https://your-project.supabase.co', 'public-anon-key')
```
Supabaseを使えるようになってからは、認証、DB、ストレージ、関数が一括提供され、APIレイヤーの実装が半減し、開発に集中できるようになりました。

## Neonの無料PostgreSQLで安定したDB環境を実現
SQLiteでローカル開発を行い、本番は手作りのRDSインスタンスをAWSで運用していましたが、コストと運用負荷が課題でした。
```bash
# プロジェクト作成（無料）
npx create-neon
```
Neonの無料プランを使えるようになってからは、本番環境と同じPostgreSQLが自動プロビジョニングされ、1TBのストレージと無制限の読み取りレプリカを利用でき、運用負荷がほぼゼロになりました。

## Google Sheets APIで簡単なデータストアを実現
スプレッドシートをCSVエクスポートし、手動でDB風に使っていましたが、行の編集や削除が面倒でした。
```python
# script.gs
function doGet(e) {
  const sheet = SpreadsheetApp.getActiveSpreadsheet().getSheetByName('data');
  const values = sheet.getValues();
  return ContentService.createTextOutput(JSON.stringify(values));
}
```
Sheets APIでバックエンドを構築できるようになると、シンプルなCRUDがGASで実装でき、データの閲覧・更新がウェブから即座に行え、手動でのCSV作業が不要になりました。

## Imgur APIで画像アップロードを自動化
画像をローカルに保存し、手動で画像ホスティングサービスにアップロードしていましたが、毎回アカウントログインが必要でした。
```python
import requests, os
def upload_imgur(image_path):
    client_id = 'your_client_id'
    with open(image_path, 'rb') as f:
        resp = requests.post('https://api.imgur.com/3/image',
                             headers={'Authorization': f'Client-ID {client_id}'},
                             files={'image': f})
    return resp.json()['data']['link']
```
Imgur APIを使えるようになってからは、`upload_imgur('pic.png')` 1本で画像がアップロードされ、Markdownに直接リンクを埋め込めるようになり、作業が大幅に効率化されました。

## まとめ
無料サービスを活用することで、CI/CDからDB、画像ホスティングまで、多くの作業が自動化の域に達しました。まずは1つのサービスから試して、あなたの開発フローを見つめてみてください。
