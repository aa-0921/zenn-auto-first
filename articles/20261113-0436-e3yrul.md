個人開発を始める前は、毎回のプロジェクトで同じことを手動で設定していました。フォルダ構成を決めたり、テストを実行したり、デプロイ方法を思い出したり…。この繰り返し作業に時間をとわれ、本当にやりたいコード書きが後回しになる frustrating な経験でした。

## Notionでプロジェクト管理を効率化
個人開発を始める当初、タスク管理や情報収集が曖昧になりがちで、ToDoリストをメモアプリに散らかしていました。Notionのデータベース機能を使えば、ページごとにタスク、ドキュメント、リソースを紐付けられます。APIトークン`secret_xxxxxxxxxxxxxxxx`を取得し、以下の curl コマンドでページを作成できます。
```bash
curl -X POST https://api.notion.so/v1/pages \
  -H "Authorization: Bearer $NOTION_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"parent":{"database_id":"YOUR_DB_ID"},"properties":{"Name":{"title":[{"text":{"content":"My Project"}}]}}'
```
これにより、プロジェクトの進捗が一元管理され、情報の散逸がなくなりました。

## Dockerで環境構築を統一
プロジェクトごとに異なる開発環境に悩まされていました。インストールするパッケージや設定ファイルもプロジェクトごとに異なり、引き継ぎに手間がかかりました。Docker Compose を使えば、`docker-compose.yml` でサービス全体を定義できます。
```yaml
version: '3.8'
services:
  app:
    build: .
    ports:
      - "3000:3000"
    volumes:
      - .:/app
```
`docker compose up -d` を実行するだけで、コンテナ内に同一の環境が構築されました。開発者ごとに環境を揃える必要がなくなり、初心者でも即座にコーディングを始められるようになりました。

## GitHub ActionsでCIを自動化する
プッシュの度に手動でテストとリポジトリの確認を行っていました。ミスも発生しやすく、効率的なワークフローが求められました。`.github/workflows/ci.yml` を追加し、以下の内容を設定します。
```yaml
name: CI
on: [push]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Set up Node
        uses: actions/setup-node@v3
        with:
          node-version: '18'
      - name: Install modules
        run: npm ci
      - name: Run tests
        run: npm test
```
これにより、コードプッシュごとに自動テストと lint が実行されるようになり、早期に問題を検出できるようになりました。

## Vercelでフロントエンドを即座にデプロイ
静的サイトを公開するたびに、サーバーの設定やドメインの設定に苦労していました。Vercel の CLI を使えば、数秒でデプロイできます。プロジェクトルートで以下のコマンドを実行するだけです。
```bash
vercel --prod
```
認証情報を入力すると、生成された URL が表示され、すぐにアクセスできるようになります。サーバー運用を気にせずに済むため、フロントエンド開発に集中できるようになりました。

## VS CodeのESLint拡張機能でコードの質を保つ
コードを書く際に、スタイルの不統一やバグが後で発覚することがありました。ESLint を導入することで、リアルタイムで問題を指摘してもらえるようになりました。ESLint をインストールし、
```bash
npm install eslint --save-dev
npx eslint .
```
設定ファイル `.eslintrc.json` を作成します。
```json
{
  "env": { "browser": true, "node": true },
  "extends": "eslint:recommended",
  "rules": { "semi": "error" }
}
```
これで、ファイル保存時に lint エラーが通知されるようになり、コードの質が向上し、リファクタリングの手間が削減されました。

## Netlifyで静的サイトを簡単にホスト
静的サイトを公開する際、サーバーや SSL の設定に時間を取られていました。Netlify CLI を使えば、`netlify deploy` コマンド一発でホストできます。
```bash
netlify deploy --prod
```
プロンプトでフォルダを選択し、認証を行うと、即座に CDN 経由の URL が得られます。追加の設定は不要で、サイトが自動的に HTTPS 化されるため、運用の負荷が大幅に軽減されました。

## Cloudflare PagesでCDN付きサイトを公開
サイトの表示速度が遅く、ユーザー体験に悩まされていました。Cloudflare Pages を利用することで、静的アセットをグローバル CDN に自動配信できます。`wrangler` をインストールし、
```bash
wrangler pages deploy dist
```
を実行すると、dist フォルダ内のファイルが公開されます。設定も簡単で、ビルド時の環境変数を指定するだけで、高速な読み込みを実現できるようになりました。

## まとめ
個人開発を始める前に決めておくことで、開発の初期段階で時間と手間を大幅に削減できることがわかりました。Notion による管理、Docker による環境統一、CI/CD の自動化、ホスティングの選択、コード lint など、それぞれが開発体験を劇的に変えてくれました。まずは 1 つ、試してみることをお勧めします。
