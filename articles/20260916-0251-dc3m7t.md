## docker ps -a で停止中も含めた全コンテナを一覧表示
`docker ps` だけだと実行中しか見えず、止まったコンテナの ID を探すのに `docker ps -a` を毎回打ち直していた。  
```bash
docker ps -a
```  
これで一発で全コンテナが表示され、停止済みのコンテナ ID を即座にコピーできるようになった。

## docker exec -it でコンテナ内に対話シェルを開く
ログを見るだけでは環境変数やファイル構成がわからず、毎回 `docker run -it --rm ... sh` で新しいコンテナを立てていた。  
```bash
docker exec -it <container_id> /bin/sh
```  
実行中のコンテナに直接入れるため、設定確認やデバッグが数秒で完了する。

## docker logs -f でリアルタイムにログを追跡
エラーが発生したとき、過去ログを `docker logs <id>` で見ても最新行が見えず、再実行して待っていた。  
```bash
docker logs -f <container_id>
```  
`-f` で標準出力をフォローできるため、問題発生の瞬間を逃さずキャッチできる。

## docker inspect --format で必要なメタ情報だけ抽出
`docker inspect` の JSON 全体を目視で探すのは大変で、IP アドレスやマウントポイントを毎回 grep していた。  
```bash
docker inspect --format '{{.NetworkSettings.IPAddress}}' <container_id>
```  
テンプレートで欲しいフィールドだけ出力できるので、スクリプトへの組み込みも楽になった。

## docker system prune -a で未使用リソースを一括削除
イメージやボリュームが溜まり、ディスク圧迫でビルドが失敗するたびに手動で削除していた。  
```bash
docker system prune -a --volumes
```  
未使用のイメージ・コンテナ・ネットワーク・ボリュームを一度に削除でき、ディスク空き容量を即座に確保できる。

## docker compose up -d --build で最新イメージを立ち上げ直す
`docker compose up -d` だけだと古いイメージのまま起動し、コード変更が反映されないことに気づくのが遅れた。  
```bash
docker compose up -d --build
```  
ビルドから起動まで一連で実行されるため、開発サイクル中の「ビルド忘れ」がなくなった。

## docker cp でコンテナとホスト間のファイル転送
コンテナ内で生成したダンプファイルをホストに持ってくるたびに `tar` + `docker exec` でパイプしていた。  
```bash
docker cp <container_id>:/path/to/file ./local_dir/
```  
単一コマンドで双方向コピーが完結し、スクリプト化も容易になった。

## docker diff でコンテナのファイルシステム変更を検知
設定ファイルをいじった後、どこが変わったか把握できず、再ビルドして確認していた。  
```bash
docker diff <container_id>
```  
追加・変更・削除されたパスが一覧で出るため、意図しない変更を即座に発見できる。

## docker stats --no-stream で瞬間的なリソース使用量を取得
`docker stats` だと連続出力され、ログに混ざって見づらかった。  
```bash
docker stats --no-stream --format "table {{.Name}}\t{{.CPUPerc}}\t{{.MemUsage}}"
```  
一度きりのスナップショットが得られ、監視スクリプトや CI での閾値チェックに組み込みやすい。

## docker image prune -a で未使用イメージを一括削除
タグ付けし直すたびに古いイメージが残り、`docker rmi` を個別に叩くのが手間だった。  
```bash
docker image prune -a
```  
参照されていない全イメージを削除でき、レジストリのストレージ節約と一覧の見やすさが両立した。
