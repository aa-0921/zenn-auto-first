## REST API の基本概念と HTTP メソッド・ステータスコード
REST（Representational State Transfer）は、資源を URL で識別し、HTTP メソッドでその資源の状態を操作するアーキテクチャです。主要な HTTP メソッドは以下の通りです。

| メソッド | 主な目的 | 代表的な使用例 |
|----------|----------|----------------|
| GET      | リソースの取得（読み取り） | `/users` でユーザ一覧取得 |
| POST     | リソースの作成（書き込み） | 新しいユーザを `/users` に追加 |
| PUT      | リソースの更新（全体更新） | `/users/1` でユーザ情報全体を更新 |
| PATCH    | リソースの部分更新 | `/users/1` のメールアドレスだけを更新 |
| DELETE   | リソースの削除 | `/users/1` を削除 |

REST では、クライアントはサーバに対して「何をしたいか」を HTTP メソッドで伝え、サーバは対応した処理を実行し、適切なステータスコードで結果を返します。代表的なステータスコードは次の通りです。

| ステータスコード | 意味 | 典型的なシーン |
|------------------|------|----------------|
| 200 OK           | 正常にリクエストが処理された | GET でデータ取得成功 |
| 201 Created      | リソースが新しく作成された | POST で新規ユーザ作成 |
| 400 Bad Request  | リクエストが不正な構成 | JSON の形式が間違っている |
| 401 Unauthorized | 認証情報が不足・不正 | API キーが無い |
| 404 Not Found    | リソースが存在しない | 不正な URL |
| 500 Internal Server Error | サーバ内部でエラーが発生 | サーバ側の例外 |

これらを理解しておくことで、API の呼び出し時に「どのメソッドを使うか」「期待できるステータスコードは何か」を判断しやすくなります。

## フロントエンドで API を叩く具体例：fetch と axios の使用方法
### 1. fetch を使った基本的な呼び出し
ブラウザ標準の `fetch` API は、Promise を返す非同期リクエストです。GET リクエストの例は以下の通りです。

```javascript
// users.json を取得する例
fetch('https://api.example.com/users')
  .then(response => {
    if (!response.ok) {
      // 状態コードが 200 番台でない場合に例外を投げる
      throw new Error(`HTTP ${response.status}`);
    }
    return response.json(); // レスポンス体を JSON に変換
  })
  .then(data => {
    console.log('取得成功:', data);
    // データを UI に反映させる処理をここに記述
  })
  .catch(error => {
    console.error('リクエスト失敗:', error);
  });
```

ポイントは次の 3 つです。

1. `response.ok` でステータスコードが 2xx かを確認し、そうでない場合は `throw` してエラー処理へ。
2. `response.json()` でレスポンスボディを解析し、JavaScript のオブジェクトに変換。
3. `catch` でネットワークエラーやプログラムエラーを捕捉。

### 2. fetch にてクエリパラメータやヘッダーを付加する例
POST で JSON データを送信するケースです。サーバ側が `Content-Type: application/json` を期待する前提です。

```javascript
const newUser = {
  name: '山田太郎',
  email: 'taro.yamada@example.com',
  age: 30
};

fetch('https://api.example.com/users', {
  method: 'POST',
  headers: {
    'Content-Type': 'application/json',
    // 必要なら認証トークンを追加
    // 'Authorization': 'Bearer <token>'
  },
  body: JSON.stringify(newUser)   // JavaScript オブジェクトを JSON 文字列に変換
})
  .then(response => response.json())
  .then(data => console.log('作成成功:', data))
  .catch(err => console.error('送信失敗:', err));
```

### 3. axios での呼び出し（コード例と優位性）
`axios` は外部ライブラリですが、リクエスト/レスポンスのインターセプターやエラーハンドリングが組み込まれている点が便利です。インストールは `npm install axios` または `yarn add axios` です。

```javascript
import axios from 'axios';

// GET 例（認証ヘッダー付き）
axios.get('https://api.example.com/users', {
  headers: {
    'Authorization': 'Bearer abcdef123456'
  }
})
  .then(res => console.log('GET 成功:', res.data))
  .catch(err => console.error('GET 失敗:', err));

// POST 例（自動で JSON 変換）
axios.post('https://api.example.com/users', newUser)
  .then(res => console.log('POST 成功:', res.data))
  .catch(err => console.error('POST 失敗:', err));
```

**axios の主な利点**

- 同時に複数のリクエストに対してベース URL を設定でき、`axios.get('/users')` のようにパスだけで呼び出せる。
- エラーオブジェクトが `error.response` に含まれ、ステータスコードやヘッダーを簡単に取得可能。
- タイムアウト設定やリトライロジックを簡潔に記述できる。

## まとめ
REST API は HTTP メソッドとステータスコードでリソースの状態を表現し、JSON を用いた軽量なやり取りが基本です。フロントエンドでは `fetch` か `axios` を使って、以下のステップを意識すると安全かつ保守性の高い通信が実現できます。

1. **HTTP メソッドとステータスコードの意味を理解**し、適切なメソッドと期待ステータスを選択する。  
2. **リクエストヘッダー（特に Content-Type）とボディの形式**（JSON）を正しく設定。  
3. **エラーハンドリング**（ステータスコードチェック、ネットワークエラー捕捉）を忘れずに実装。  
4. 必要に応じて **認証トークン**や **タイムアウト**設定を組み込む。

これらを守ることで、開発初心者でも自信を持って API と連携した UI を構築でき、実務で即活用できるスキルが身につきます。ぜひ、上記のコード例を自分のプロジェクトに取り込み、実際に動かしてみてください。
