## 1. SELECT と WHERE の基本
### 1.1 カラムの選択とエイリアス
まずは必要な列だけを取得し、見やすい名前（エイリアス）をつける習慣をつけましょう。

```sql
SELECT
    employee_id AS emp_id,
    first_name || ' ' || last_name AS full_name,
    hire_date
FROM employees
WHERE hire_date >= '2022-01-01';
```
- `AS` で列名にわかりやすいラベルを付けることで、後続の処理やレポート作成が楽になります。
- 文字列結合はデータベースによって演算子が異なります（例: PostgreSQL は `||`, MySQL は `CONCAT`）。

### 1.2 WHERE 句での条件絞り込み
数値、文字列、日付など型に応じた条件を組み合わせます。NULL 値への対応も忘れずに。

```sql
SELECT *
FROM orders
WHERE status = 'Shipped'
  AND order_amount > 10000
  AND shipped_date IS NOT NULL;
```
- `IS NULL` / `IS NOT NULL` は `=` では判定できないため、必ず専用の演算子を使用します。
- 複数条件は `AND`/`OR` で組み合わせ、優先順位を明確にするために括弧を活用すると可読性が向上します。

## 2. JOIN の種類と実務での使い方
### 2.1 内部結合（INNER JOIN）
最も頻繁に使われるのは、両テーブルにマッチするレコードだけを取得する内部結合です。

```sql
SELECT
    e.employee_id,
    e.first_name,
    d.department_name
FROM employees e
INNER JOIN departments d
    ON e.department_id = d.department_id;
```
- テーブルエイリアス（`e`, `d`）を付けることで、長い名前の繰り返しを防ぎます。
- `ON` 句では等価条件以外にも、範囲検索や不等号を用いることも可能です（例: `ON e.salary BETWEEN d.min_sal AND d.max_sal`）。

### 2.2 外部結合（LEFT JOIN / RIGHT JOIN）
マスターテーブル側の情報を残しながら、従属テーブルのデータを付加したいケースでは外部結合が適しています。

```sql
SELECT
    c.customer_id,
    c.customer_name,
    o.order_id,
    o.order_date
FROM customers c
LEFT JOIN orders o
    ON c.customer_id = o.customer_id
WHERE o.order_date >= '2023-01-01' OR o.order_id IS NULL;
```
- 左外部結合（LEFT JOIN）では、`customers` テーブルの全行が結果に残り、マッチしない `orders` の列は `NULL` になります。
- `WHERE` 句で `IS NULL` を使うと、注文がまだない顧客を抽出するなどの逆引きクエリが書けます。

### 2.3 自己結合と複数テーブル結合
階層データや同一テーブル内の関連を扱う自己結合や、3 以上のテーブルを結合するケースも実務ではよく見られます。

```sql
-- 自己結合：マネージャーと部下の関係を表示
SELECT
    emp.employee_id AS emp_id,
    emp.first_name AS emp_name,
    mgr.employee_id AS mgr_id,
    mgr.first_name AS mgr_name
FROM employees emp
LEFT JOIN employees mgr
    ON emp.manager_id = mgr.employee_id;

-- 3 テーブル結合：注文・商品・在庫情報を合わせて表示
SELECT
    o.order_id,
    p.product_name,
    i.quantity_in_stock
FROM orders o
JOIN order_items oi ON o.order_id = oi.order_id
JOIN products p ON oi.product_id = p.product_id
LEFT JOIN inventory i ON p.product_id = i.product_id;
```
- 自己結合では同じテーブルを別エイリアスで参照し、結合条件で関係を表します。
- 複数テーブル結合では、結合順序や join の種類（INNER/LEFT）を意識すると、不要な行が除外されパフォーマンスが向上します。

## 3. 集計関数と GROUP BY
### 3.1 基本的な集計（COUNT, SUM, AVG, MAX, MIN）
売上集計や在庫チェックなど、数値データをまとめるときに必須です。

```sql
SELECT
    department_id,
    COUNT(*) AS employee_count,
    AVG(salary) AS avg_salary,
    MAX(salary) AS max_salary,
    MIN(salary) AS min_salary
FROM employees
GROUP BY department_id
HAVING AVG(salary) > 500000;
```
- `GROUP BY` で指定した列ごとに集計が行われます。
- 集計結果に対するフィルタリングは `WHERE` ではなく `HAVING` を使います（集計後に条件を適用するため）。

### 3.2 GROUPING SETS とロールアップ
複数の粒度での集計を一度に取得したい場合は、`GROUPING SETS` や `ROLLUP` が便利です（データベースによってサポート状況は異なります）。

```sql
SELECT
    department_id,
    job_id,
    COUNT(*) AS cnt,
    SUM(salary) AS total_sal
FROM employees
GROUP BY GROUPING SETS (
    (department_id, job_id),
    (department_id),
    ()
);
```
- 上記クエリは、(部署・職種)、(部署のみ)、(全体) の 3 種類の集計結果を一つの結果セットで返します。
- レポート作成時に「小計・総計」をSQL側で生成できると、アプリ側での後処理が減ります。

## 4. サブクエリの活用パターン
### 4.1 スカラーサブクエリ（単一値を返す）
`SELECT` 列や `WHERE` 条件の中で、1 行 1 列の値を取得したいときに使います。

```sql
SELECT
    employee_id,
    first_name,
    salary,
    (SELECT AVG(salary) FROM employees) AS company_avg_sal
FROM employees
WHERE salary > (SELECT AVG(salary) FROM employees);
```
- スカラーサブクエリは実行計画において外部クエリごとに実行されることがあるため、大規模データでは事前に集約テーブルを作るなどの工夫が必要です。

### 4.2 インラインサブクエリ（FROM 句での派生テーブル）
一時的に集計結果やフィルタ済みテーブルを作り、さらに結合や条件を適用したいケースです。

```sql
SELECT
    d.department_name,
    sub.emp_cnt,
    sub.avg_sal
FROM departments d
JOIN (
    SELECT
        department_id,
        COUNT(*) AS emp_cnt,
        AVG(salary) AS avg_sal
    FROM employees
    GROUP BY department_id
) sub ON d.department_id = sub.department_id
WHERE sub.emp_cnt >= 5;
```
- 派生テーブルは名前を付けることで参照しやすくなり、`WHERE` や `ORDER BY` も自由に使えます。
- 実行プランではこの派生テーブルが一時的に素早く作成されるか、あるいはインラインビューとしてマージされることが多いです。

### 4.3 相関サブクエリ（外部クエリの列を参照）
同じテーブル内での「各行に対して他の行と比較したい」ケースで有効です。

```sql
SELECT
    e1.employee_id,
    e1.first_name,
    e1.salary
FROM employees e1
WHERE e1.salary > (
    SELECT AVG(e2.salary)
    FROM employees e2
    WHERE e2.department_id = e1.department_id
);
```
- 部署ごとの平均給与より高い給与をもらう社員を抽出する例です。
- 相関サブクエリは外部クエリの行数分だけ実行されるため、インデックスが適切に貼られているか確認が必要です。

## 5. パフォーマンスに配慮した書き方のコツ
1. **フィルタは早めに**：`WHERE` 句で絞り込みを先に行い、その後の `JOIN` や集計の対象行数を減らす。
2. **インデックスを意識**：`JOIN` 条件や `WHERE` 句の列にはインデックスを貼ると、全表スキャンを避けられることが多い。
3. **不要な `SELECT *` は避ける**：必要な列だけを指定すると、ネットワーク転送量とメモリ使用量が削減される。
4. **実行計画を確認**：`EXPLAIN`（またはデータベース固有の同様のコマンド）でボトルネックを見つけ、インデックスやクエリの書き換えを検討する。
5. **一時テーブルやCTEの活用**：複雑なロジックは `WITH` 句（CTE）や一時テーブルに分割すると、可読性と再利用性が向上し、オプティマイザが最適化しやすくなる。
