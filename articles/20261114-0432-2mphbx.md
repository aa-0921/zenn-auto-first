同じコマンドを何度も手で打っていたり、保存し忘れて変更が反映されなかったり、そんな失敗を繰り返していた時期があります。VS Code を使い始めたばかりの頃、デフォルトのまま使っていると不便に感じる場面がたくさんありました。そこで実際に設定を変えてみて、作業が楽になった項目を10個選びました。どれも設定画面（settings.json）から数行追加するだけで有効にできるものです。駆け出しの方がまず試してみると、日々の開発が少しずつ快適になるはずです。

## 保存時にコードを自動整形してくれた editor.formatOnSave

以前は保存するたびに手動で整形コマンドを実行していて、インデントが崩れたままコミットしてしまうことがありました。Prettier などのフォーマッターを入れていても、毎回コマンドパレットから選ぶのは手間でした。

```json
"editor.formatOnSave": true,
"editor.defaultFormatter": "esbenp.prettier-vscode"
```

この設定を入れてからは、ファイルを保存するだけで自動的にコードが整形されるようになりました。インデントや改行を意識せずに書けるので、ロジックに集中でき、レビュー時の指摘も減ったと感じています。

## 編集中にうっかり閉じても安心な files.autoSave

ファイルを閉じる際に「保存しますか」と聞かれて慌てたり、保存し忘れて古いコードを実行してデバッグに時間を使ったりすることがよくありました。

```json
"files.autoSave": "afterDelay",
"files.autoSaveDelay": 1000
```

afterDelay に設定すると、編集をやめてから1秒後に自動保存されます。保存ボタンを押す手間がなくなり、変更内容をすぐに反映できるようになったので、小さな修正を繰り返す作業がずっと楽になりました。

## 長い行を画面に収める editor.wordWrap

長い行が画面からはみ出し、毎回横スクロールしてコードを読んでいました。特に設定ファイルやログ出力を含むコードで不便に感じていました。

```json
"editor.wordWrap": "on"
```

この設定を有効にすると、ウィンドウ幅に合わせて行が折り返されます。横スクロールしなくて済むようになり、画面全体を見渡しながらコードを読めるようになったので、疲れにくくなりました。

## 入れ子の括弧が見やすくなる editor.bracketPairColorization.enabled

関数や条件分岐が深くなると、どの開き括弧にどの閉じ括弧が対応するか分からなくなり、括弧の位置を探すのに時間をかけていました。

```json
"editor.bracketPairColorization.enabled": true,
"editor.guides.bracketPairs": true
```

対応する括弧が同じ色で表示されるようになり、閉じ括弧の位置が一目で分かるようになりました。入れ子が深いコードでも迷わずに編集でき、ミスが減ったと実感しています。

## タブが増えすぎない workbench.editor.enablePreview

ファイルをクリックするたびにプレビュータブが開き、気づけばタブが大量に増えて混乱することがありました。どのファイルが固定されているか分かりにくかったです。

```json
"workbench.editor.enablePreview": false
```

この設定をオフにすると、クリックしたファイルが通常のタブとして固定されます。タブ管理がしやすくなり、開いているファイルを迷わずに切り替えられるようになりました。

## ファイル削除時に確認ダイアログを出す explorer.confirmDelete

エクスプローラーでファイルを削除しようとした際、誤って重要なファイルを消してしまい、git で復元する手間がかかった経験があります。

```json
"explorer.confirmDelete": true
```

この設定をオンにすると、削除時に確認ダイアログが表示されます。誤操作によるファイル消失を防げるようになり、安心してファイル整理ができるようになりました。

## コードの横幅を意識させる editor.rulers

行の長さがバラバラで、コードレビューで「行が長すぎる」と指摘を受けることがありました。どこまで書けば良いか基準が分からず、悩んでいました。

```json
"editor.rulers": [80, 120]
```

エディタに80桁と120桁の位置に縦線が表示されるようになり、行の長さを視覚的に意識できるようになりました。レビューでの指摘が減り、読みやすいコードを書けるようになったと感じています。

## ターミナルを読みやすくする terminal.integrated.fontSize

統合ターミナルの文字が小さく、エラーメッセージやログを読み間違えることがありました。特に細かい文字を長時間見ると目が疲れました。

```json
"terminal.integrated.fontSize": 14
```

フォントサイズを14に上げたことで、ターミナルの出力が見やすくなりました。エラー内容を正確に把握しやすくなり、デバッグの効率が上がったと実感しています。
