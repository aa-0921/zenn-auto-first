同じコードを何度も手で整形していたり、うっかり残したスペースでCIが落ちたり、設定を探すのに毎回メニューを開いていた経験はありませんか？私が駆け出し時代に抱えていた「同じ作業を繰り返す」ストレスを、VS Codeの設定項目を少しずつ変えるだけで解消できました。ここでは実際に使って効果を感じた10個の設定を紹介します。

## editor.formatOnSaveで保存時に自動フォーマット
導入前に何に困っていたか: 毎回ファイルを保存するたびに Shift+Alt+F を押してフォーマットをかけていた。忘れるとインデントがバラバラになり、コードレビューで「整形してください」とコメントされることが頻繁にあった。
具体的な使い方（settings.json）:
```json
{
  "editor.formatOnSave": true
}
```
使ってみてどう変わったか: 保存と同時にPrettierか言語フォーマッターが自動で走り、コードスタイルが常に揃うようになった。手動でショートカットを打つ手間がなくなり、レビューでの指摘が劇的に減った。結果としてコードを書くことに集中できる時間が増えた。

## files.trimTrailingWhitespaceで末尾スペース自動削除
導入前に何に困っていたか: 行の終わりに余計なスペースが残っていると、git diffで無意味な変更が大量に出てきて、レビュー時に指摘されることが多かった。毎回手で削除するのは面倒で、見落としもありえた。
具体的な使い方:
```json
{
  "files.trimTrailingWhitespace": true
}
```
使ってみてどう変わったか: ファイルを保存するだけで末尾のスペースやタブが自動で削除され、diffがきれいになった。無意味な変更が減り、コミットログも見やすくなった。気づかないうちに残していたスペースもなくなり、CIの警告も減った。

## editor.renderWhitespaceでスペース・タブを可視化
導入前に何に困っていたか: インデントがスペースかタブか混在していると、PythonやMakefileで予期せぬエラーが発生し、原因を探すのに時間がかかっていた。エディタだけでは見分けがつかず、デバッグに苦労した。
具体的な使い方:
```json
{
  "editor.renderWhitespace": "boundary"
}
```
使ってみてどう変わったか: スペースは点、タブは arrow で表示されるようになり、インデントの不統一が一目でわかる。混在をすぐに修正できるようになり、言語によるインデントエラーがほぼなくなった。結果としてコードの品質が向上し、デバッグ時間が削減された。

## editor.tabCompletionでタブ補完を有効化
導入前に何に困っていたか: コード補完を使うたびに Enter キーを押さなければならず、特に長い識別子を入力するときに手が疲れていた。補完候補が表示されているときにタブで確定できたら楽だと感じていた。
具体的な使い方:
```json
{
  "editor.tabCompletion": "on"
}
```
使ってみてどう変わったか: 補完リストが表示されている状態で Tab キーを押すだけで確定できるようになり、Enter キーを使う頻度が半減した。長いクラス名や関数名の入力がスムーズになり、コーディングのリズムが崩れなくなった。結果としてタイピング速度が向上し、疲れも軽減された。

## editor.wordWrapでビューポート内折り返し
導入前に何に困っていたか: 長いログファイルや設定ファイルを横にスクロールしながら読む必要があり、画面外に追われて行を追いかけるのが大変だった。特にモニターが狭いノートPCでは水平スクロールが頻繁に発生し、集中力が削がれた。
具体的な使い方:
```json
{
  "editor.wordWrap": "on"
}
```
使ってみてどう変わったか: ファイルを開いたでビューポート幅に合わせてテキストが折り返されるようになり、横スクロールがほぼ不要になった。長い行でも画面内に収まり、行を追う目線が安定した。結果としてログ調査や設定ファイルのレビューが快適になり、作業効率が上がった。

## explorer.confirmDeleteでフォルダ削除時の確認を有効化
導入前に何に困っていたか: エクスプローラーからフォルダを右クリック→削除したつもりが、誤って重要なディレクトリを削除してしまい、 git で復元するか、あるいはローカルバックアップから戻す作業に時間を取られたことがあった。
具体的な使い方:
```json
{
  "explorer.confirmDelete": true
}
```
使ってみてどう変わったか: 削除操作時にダイアログが表示され、「本当に削除しますか？」と確認が必要になるようになった。誤削除がほぼなくなり、安心してファイル整理ができるようになった。結果として余計な復旧作業が発生せず、開発に集中できる時間が増えた。

## workbench.editor.enablePreviewでプレビュータブを無効化
導入前に何に困っていたか: ファイルをクリックするとプレビュータブとして開き、ダブルクリックしないと固定タブにならず、複数ファイルを行き来するとタブがすぐに上書きされてしまい、目的のファイルを探し直す手間があった。
具体的な使い方:
```json
{
  "workbench.editor.enablePreview": false
}
```
使ってみてどう変わったか: ファイルをシングルクリックしても通常のタブとして開くようになり、ダブルクリックの手間がなくなった。タブが増えても安心して作業でき、行きたいファイルにすぐアクセスできるようになった。結果としてファイル切り替えのストレスが減り、作業フローがスムーズになった。

## debug.console.fontSizeでデバッグコンソールの文字サイズを調整
導入前に何に困っていたか: デバッグコンソールの文字が小さく、特に高解像度ディスプレイでは読みづらかった。出力された変数やスタックトレースを確認するたびに画面を近づけたり、ズーム機能を使ったりして目を疲れさせていた。
具体的な使い方:
```json
{
  "debug.console.fontSize": 14
}
```
使ってみてどう変わったか: コンソールの文字が読みやすいサイズになり、出力内容を一瞬で把握できるようになった。目を近づける必要がなくなり、長時間のデバッグセッションでも疲れが軽減された。結果としてバグの特定速度が向上し、デバッグ作業が快調になった。

## terminal.integrated.cursorBlinkingでターミナルカーソルの点滅を有効化
導入前に何に困っていたか: 統合ターミナルのカーソルが静止していると、現在の入力位置が見失いやすく、特に長いコマンドを入力中にどこまで打ったか分からなくなることがあった。間違えて途中でEnterを押してしまい、コマンドが実行されてしまうミスが頻繁に起きた。
具体的な使い方:
```json
{
  "terminal.integrated.cursorBlinking": true
}
```
使ってみてどう変わったか: カーソルが点滅するようになり、入力位置が一目でわかるようになった。長いコマンドでもどこまで入力したかを把握しやすくなり、誤ったEnter操作が減った。結果としてターミナル作業の正確性が向上し、イライラが減った。

## files.autoSaveで自動保存間隔を設定
導入前に何に困っていたか: 編集中にうっかり保存を忘れて、IDEを閉じたりPCがスリープに入ったりしたときに作業が失われる危険があった。毎回 Ctrl+S を意識して押すのが習慣になっておらず、特に集中しているときに抜けがちだった。
具体的な使い方:
```json
{
  "files.autoSave": "afterDelay",
  "files.autoSaveDelay": 1000
}
```
使ってみてどう変わったか: 1秒ごとに変更が自動で保存されるようになり、保存忘れによるデータ損失のリスクがほぼなくなった。作業の流れを中断せずにコーディングに集中でき、安心して実験的な変更も試せるようになった。結果として作業の中断が減り、生産性が向上した。

## まとめ
本編では、フォーマットや空白処理、タブ補完など、日常の小さなストレスを解消するVS Codeの設定項目を10個紹介しました。いずれもsettings.jsonに数行追加するだけで効果が実感できるので、まずはひとつだけでも試してみてほしい。設定を変えるたびに作業が少しずつ楽になり、開発に集中できる時間が増えていくはずです。
