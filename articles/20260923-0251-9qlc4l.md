### 転職のきっかけと決断の経緯

20代後半・30代でエンジニアを目指す方は、少なくない。私もその一人で、前職の「やりがいのない業務」を脱却するために、30歳の誕生日を境にプログラミング学習を始めました。「もう遅いのでは？」という不安は確かにありましたが、Web業界は年齢よりもスキルと成果を重視する傾向が強いことも事実です。実際に転職活動を始めてみて、採用担当者が最も気にしていたのは「過去の経験」ではなく、「これから何を学び、どう貢献できるか」でした。

### エンジニアリングの本質は「問題解決」

エンジニアリングとは、コードを書くことではなく、目の前の課題を論理的に解決することです。20代後半・30代から参入する大きな強みは、これまでの社会経験やビジネススキルにあります。例えば、要件定義の段階で「ユーザーが本当に求めているもの」を正確に把握できる経験は、純粋な技術知識よりも価値を発揮することが多いのです。

## 学習の進め方〜実務で即効力を発揮する3つのステップ

### ステップ1: 基礎文法を「書いて」覚える

プログラミングの学習において、 watching only（視聴だけ）では身につきません。私は、まずPythonの基礎文法をUdemyの講座で学びながら、必ず自分の手でコードを書きました。例えば、以下のような簡単な業務自動化スクリプトを最初に作成し、「自分で作ったものが動く」という達成感を確保しました。

```python
# 業務で頻繁に使うCSVファイルの整理スクリプト
import pandas as pd
from datetime import datetime

def organize_csv(input_file, output_dir):
    """受注CSVを月次で分割して保存する"""
    df = pd.read_csv(input_file)
    df['受注日'] = pd.to_datetime(df['受注日'])
    df['月'] = df['受注日'].dt.strftime('%Y-%m')

    for month, group in df.groupby('月'):
        output_path = f"{output_dir}/orders_{month}.csv"
        group.to_csv(output_path, index=False, encoding='utf-8-sig')
        print(f"保存完了: {output_path}")

if __name__ == "__main__":
    organize_csv("daily_orders.csv", "output/monthly")
```

このように、「自分の業務に直接役立つ」コードを最初に書くことで、動機付けを維持し続けることができました。

### ステップ2: 開発ツールとGitの実践的習得

基礎文法に慣れたら、次は開発環境の構築です。VS Code、Git、GitHubは必須ツールです。私は、学習の初期段階からGitを使ってコードの変更履歴を管理する習慣をつけました。実はこの習慣が、後の現場でのコードレビュー対応に大きく繋がりました。以下は、私が学習中に作成したREADMEの例です。

### ステップ3: 模擬プロジェクトで「完成まで」を経験する

書籍や講座の課題は簡単なものが多いですが、「設計→実装→テスト→デプロイ」の一連の流れを経験するには、模擬プロジェクトが有効です。例えば、FlaskやExpress.jsで自分だけのREST APIを作り、RailwayやVercelにデプロイしてみましょう。実際にブラウザからアクセスできる状態を作ることで、エンジニアとしての全体像が見えてきます。

```javascript
// Express.jsによるシンプルなREST API (学習用模擬プロジェクト)
const express = require('express');
const app = express();
app.use(express.json());

let tasks = [
  { id: 1, title: 'ポートフォリオ作成', completed: false },
  { id: 2, title: '技術ブログ執筆', completed: true },
];

app.get('/api/tasks', (req, res) => {
  res.json(tasks);
});

app.post('/api/tasks', (req, res) => {
  const newTask = {
    id: tasks.length + 1,
    title: req.body.title,
    completed: false,
  };
  tasks.push(newTask);
  res.status(201).json(newTask);
});

app.listen(3000, () => console.log('API Server running on port 3000'));
```

## 現場で感じた手応えと、今後のキャリアへの展望

### コードレビューで得た「言語化する力」

転職後、最初のコードレビューで指摘されたのは、変数名のわかりやすさとコメントの不足でした。しかし、指摘の内容が明確だったからこそ、改善がスムーズに進みました。20代後半・30代から参入する方の強みは、「なぜそのコードが良くないか」を言語化できることです。これは、若手エンジニアがしばしば苦手とする部分であり、チーム内での信頼に直結します。

### ビジネス課題と技術を結びつける達成感

現場で最も手応えを感じる瞬間は、自分が書いたコードが実際のビジネスに影響を与えた時です。例えば、私が担当したデータ集計の自動化プロジェクトは、手作業の3時間を30秒に短縮し、チーム全体の生産性を向上させました。技術的なスキルだけでなく、「この改善が誰の役に立つのか」を常に意識して設計する姿勢が、評価につながりました。

### キャリアの多様な選択肢

エンジニアとしてのキャリアは、技術専門職だけでなく、PM（プロジェクトマネージャー）、SRE、テックリードなど多岐にわたります。20代後半・30代から学び始めた方が、将来どのポジションを選ぶにしても、これまでの経験は確実に武器になります。技術力と社会経験の両輪で、独自のキャリアを築いていくことが可能です。

## まとめ

20代後半・30代からエンジニアを目指すのは、決して遅くありません。大切なのは、基礎文法を「書いて」覚えること、開発ツールを最初から実践的に使うこと、そして模擬プロジェクトで「完成まで」の体験を積むことです。そして、現場に入ったら、コードレビューとビジネス課題への意識を徹底して高めましょう。等身大の体験談が、次のステップへの力になれば幸いです。
