## CIでPRごとの自動テストを実行し、手動実行を削減したワークフロー

ブランチを作成するたびに、手動で `npm test` を実行して失敗を確認していた。エラーが見つかるまでに時間がかかり、作業の流れが中断されていた。

```yaml
name: CI
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install modules
        run: npm ci
      - name: Run tests
        run: npm test
```

このワークフローを追加すると、PRが作成されるたびにCIが自動的にテストを実行するようになり、失敗が即座にSlackに通知されるようになった。手動での確認作業が不要になり、開発のペースが格段に上がった。

## lintチェックを自動化し、コードのスタイルを統一したワークフロー

毎回のコミットで `npm run lint` を手動実行し、修正漏れがないか目視で確認していた。見落としが多く、チーム内のコード品質がばらついていた。

```yaml
name: Lint
on: [push]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install modules
        run: npm ci
      - name: Run ESLint
        run: npm run lint
```

lintエラーがコミット時に自動検知されるようになり、コードのスタイルが統一された。修正漏れがなくなり、レビュー工数が大幅に削減された。

## デプロイ前のビルドを自動化し、Artifactのアップロードを簡素化したワークフロー

本番環境にデプロイする前に、手動で `npm run build` と `aws s3 sync` を実行していた。ミスが発生しやすく、バージョン管理が曖昧だった。

```yaml
name: Build & Upload Artifact
on:
  push:
    branches: [main]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install modules
        run: npm ci
      - name: Build
        run: npm run build
      - name: Upload Artifact
        uses: actions/upload-artifact@v3
        with:
          name: build-output
          path: dist/
```

ビルドとArtifactのアップロードが自動化され、バージョンが明確になった。デプロイ時の失敗が減り、リリース作業がスムーズになった。

## デプロイを自動化し、Vercelへの本番環境公開を容易にしたワークフロー

Vercelへのデプロイは手動コマンド `vercel --prod` で行っていた。環境変数の設定ミスが発生し、毎回確認が必要だった。

```yaml
name: Deploy to Vercel
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install modules
        run: npm ci
      - name: Deploy
        run: npx vercel --prod --token ${{ secrets.VERCEL_TOKEN }}
        env:
          VERCEL_PROJECT_ID: ${{ secrets.VERCEL_PROJECT_ID }}
```

デプロイがワンクリックで完了し、環境変数も自動的に引き継がれるようになった。リリースのタイムラインが大幅に短縮された。

## セキュリティスキャンを自動化し、脆弱性を早期に発見したワークフロー

依存パッケージの脆弱性を手動で `npm audit` を実行して確認していた。後になって問題が発覚し、修正に時間がかかっていた。

```yaml
name: Security Scan
on: [push, pull_request]
jobs:
  security:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install modules
        run: npm ci
      - name: Run audit
        run: npm audit --json > audit-report.json
      - name: Upload report
        uses: actions/upload-artifact@v3
        with:
          name: audit-report
          path: audit-report.json
```

スキャンが自動実行されるようになり、脆弱性がPR作成前に検出されるようになった。セキュリティ対応の工数が激減した。

## カバレッジレポートを自動生成し、テスト品質を可視化したワークフロー

テスト実行後に手動で `npm run coverage` を実行し、レポートをGitHub Pagesにアップロードしていた。手間がかかり、チームに結果が周知されなかった。

```yaml
name: Coverage Report
on:
  push:
    branches: [main]
jobs:
  coverage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - name: Install modules
        run: npm ci
      - name: Run tests with coverage
        run: npm run test:cov
      - name: Deploy coverage
        uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./coverage/lcov-report
```

カバレッジレポートが自動で更新・公開されるようになり、チーム全体でテスト品質を把握できるようになった。改善すべきポイントが明確になった。
