## Homebrewでパッケージ管理が楽になった
以前は必要なライブラリやコマンドラインツールを公式サイトからダウンロードしてインストールしていました。バージョン管理が面倒で、古いものが残ってしまうこともありました。Homebrewを使うと、```bash
brew install git
brew install node
```のように一行でインストールでき、アップデートも```brew upgrade```だけで済みます。これで環境構築の手間が劇的に減り、同じバージョンをチームと共有しやすくなりました。

## iTerm2でターミナル作業が快適に
macOS標準のターミナルは画面分割ができず、複数のタブを行き来するだけだったので、ログを見ながらコードを編集する際に窓を切り替えるのが面倒でした。iTerm2をインストールし、```⌘+D```で垂直分割、```⌘+Shift+D```で水平分割が可能になりました。さらに、プロファイルで配色やフォントを保存しておくと、プロジェクトごとに見た目を変えられます。これにより、一つのウィンドウで複数の作業を同時に見られ、切り替えストレスがほぼなくなりました。

## oh-my-zshでシェルの見た目と機能を強化
デフォルトのbashではプロンプトが単調で、gitのブランチ名やステージング状況を確認するのに毎回```git status```を打っていました。oh-my-zshを導入し、```~/.zshrc```に```ZSH_THEME="agnoster"```と設定すると、プロンプトにブランチ名と変更マークが自動表示されます。また、プラグインとして```git```や```docker```を追加すると、```gco```や```dcup```などのエイリアスが使えるようになりました。これでコマンド入力が短縮され、ミスも減りました。

## Gitでバージョン管理をミスなく行う
以前は変更を手動でフォルダごとコピーしてバック업을取っていましたが、履歴が残らず、後で差分を見るのが大変でした。Gitを使うと、```bash
git init
git add .
git commit -m "初期コミット"
```でリポジトリを作成し、変更ごとにコミットできます。さらに```git diff```で現在の変更を確認し、```git log --oneline```で履歴を一覧表示できます。これにより、変更の追跡が確実になり、間違えて戻すことも簡単になりました。

## GitHub CLIでプルリクエストをターミナルから完結
ブラウザでGitHubを開いてプルリクエストを作成する手順が面倒で、特に複数のリポジトリを横断するときにタブを行き来するのが煩わしかったです。GitHub CLI（gh）をインストールし、```bash
gh pr create --title "機能X追加" --body "詳細説明"
```と実行すると、現在のブランチからプルリクエストが即座に作成されます。また、```gh pr list```で未マージのPRを一覧表示し、```gh pr checkout 42```でチェックアウトもできます。これでブラウザを行き来する手間が省け、開発フローがターミナル内で完結します。

## Docker Desktopで環境依存を解消
ローカルでデータベースやミドルウェアを直接インストールすると、バージョンの違いや設定の衝突で「うちのマシンでは動くのに」という問題が頻繁に起きました。Docker Desktopをインストールし、```bash
docker run --name postgres -e POSTGRES_PASSWORD=secret -d -p 5432:5432 postgres
```でPostgreSQLコンテナを立ち上げ、アプリケーションからはlocalhost:5432に接続するだけで同じ環境が得られます。さらにdocker-compose.ymlを書けば、複数サービスを一度に起動できます。これにより、環境構築のばらつきがほぼなくなり、CIと同じ動作をローカルで確認しやすくなりました。

## PostmanでAPIのテストを効率化
以前はcurlを手打ちしてレスポンスを確認していましたが、長いJSONやヘッダーを毎回タイプするのはミスが多く、見づらかったです。Postmanをインストールし、リクエストを保存して「Send」ボタン一つで実行できます。例えば、```bash
curl -X POST https://api.example.com/users \
  -H "Content-Type: application/json" \
  -d '{"name":"田中","age":30}'
```と同等の操作をGUIで行い、レスポンスを整形して表示します。また、コレクションとしてテストケースをまとめておけば、実行結果を一覧で確認できます。これにより、APIの動作確認がスピードアップし、 regression テストも楽になりました。

## Visual Studio Codeでコード編集をカスタマイズ
シンプルなエディタだと、インデント補完やシンタックスハイライトが限られていて、長いファイルを読むときに目が疲れました。VS Codeをインストールし、```code .```でプロジェクトを開くと、拡張機能マーケットから「Prettier」「ESLint」「GitLens」などをワンクリックで追加できます。さらに、設定ファイル```settings.json```でフォントサイズやタブ幅を自分好みに調整し、ターミナル integradoを表示させれば、エディタ内でコマンドも実行できます。これにより、コーディングとデバッグの切り替えがシームレスになり、生産性が向上しました。

## Sequel Aceでデータベース操作をGUI化
ターミナルで```mysql -u root -p```と打ち込んでSQLを実行していましたが、複雑なクエリを書くときにエディタがないとミスが多く、結果を見るのも横スクロールが必要でした。Sequel Ace（無料フォークのSequel Pro）をインストールし、接続情報を入力すると、左ペインにスキーマがツリー表示され、右ペインでクエリを入力して実行できます。たとえば、```SELECT * FROM users WHERE age > 20;```と入力し、結果を表形式で確認できます。これにより、データの閲覧・更新が直感的になり、開発中のスキーマ変更も素早く行えました。

## RaycastでSpotlight代わりのランチャーを強化
標準のSpotlightはアプリ起動やファイル検索に使えていましたが、スクリプトの実行やクリップボード履歴の呼び出しなど、開発者向けの機能がありませんでした。Raycastをインストールし、```⌥+Space```で呼び出すと、コマンドパレットが表示されます。たとえば、```flutter run```や```git checkout dev```と入力すれば即実行でき、また「Clipboard History」モジュールを有効にすると過去のクリップボードを検索して貼り付けられます。これにより、よく使う小さなタスクをキーボードから完結させられ、マウスへの手間が減りました。

## まとめ
これらのツールはどれも無料でインストールでき、少しの設定で日々の作業がずっと楽になります。まずは気になる一つから試してみて、自分に合ったワークフローを見つけてください。
