## Vercel で Next.js アプリがゼロコンフィグで動いた
Next.js プロジェクトを Vercel にインポートするだけで、ビルド設定・プレビュー環境・カスタムドメインまで自動で整う。以前は Docker イメージを作って VPS にデプロイしていた。
```bash
# Vercel CLI でローカルプレビュー
vercel dev
```
プッシュごとにプレビュー URL が発行され、チームレビューが圧倒的に楽になった。

## GitHub Pages でドキュメントサイトをリポジトリ内で完結させた
MkDocs で生成した HTML を `gh-pages` ブランチに手動でコミットしていたが、GitHub Actions で自動化できることを知った。
```yaml
# .github/workflows/pages.yml
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - run: pip install mkdocs-material && mkdocs gh-deploy --force
```
ドキュメント更新がマージと同時に反映され、手作業がゼロになった。

## Cloudflare Pages でエッジキャッシュと Workers を無料で活用した
静的サイトを Cloudflare Pages に置くだけで、世界中のエッジにキャッシュされ、Workers でリダイレクトやヘッダー操作もできる。
```bash
# Wrangler でローカル開発
wrangler pages dev ./dist
```
レスポンス速度が体感で速くなり、CDN 設定を意識しなくて済むようになった。

## Render で小規模なバックエンド API を無料で公開した
Node/Express の API を Heroku の無料枠終了後、Render の Free Web Service に移行。自動で TLS が付き、スリープからの復帰も数秒で済む。
```bash
# render.yaml でサービス定義
services:
  - type: web
    name: api
    env: node
    buildCommand: npm ci && npm run build
    startCommand: npm start
```
`git push render main` だけでデプロイ完了し、データベースも無料 PostgreSQL が使える。

## Railway でコンテナベースのマイクロサービスを手軽に動かした
Dockerfile さえあれば `railway up` でビルド・デプロイ・ログ確認まで一発。以前は VPS に Docker Compose を手動で上げていた。
```bash
# ローカルで確認後、本番へ
railway login
railway up
```
環境変数の管理もダッシュボードで完結し、スケールアップもボタン一つ。

## Fly.io でグローバルなエッジ実行を無料枠で試した
`fly launch` で Docker イメージをビルドし、複数リージョンに自動配置。以前は自前で GeoDNS を組んでいた。
```bash
fly launch --name myapp --region nrt
fly deploy
```
リクエストが最寄りリージョンで処理され、レイテンシが劇的に改善した。

## Firebase Hosting で SPA と Cloud Functions を一体化した
`firebase init hosting` でリダイレクト設定やリライトを `firebase.json` に書くだけ。以前は S3+CloudFront で同等のことを手動でやっていた。
```json
// firebase.json 抜粋
{
  "hosting": {
    "public": "build",
    "rewrites": [{ "source": "**", "destination": "/index.html" }]
  }
}
```
`firebase deploy` 一発で CDN 配信とサーバーレス関数が同時に更新される。

## Surge.sh でプロトタイプを秒で公開した
`npm i -g surge` して `surge ./dist` と打つだけでランダムなサブドメインが即座に発行される。CI に組み込まず、手元で確認用 URL が欲しい時に最適。
```bash
surge ./dist myproject.surge.sh
```
認証なしで即座に共有できるため、クライアントへのデモ準備が数秒で済む。

## GitLab Pages でプライベートリポジトリのドキュメントを公開した
GitLab CI で `pages:` ジョブを定義し、`public/` 以下をデプロイ。GitHub Pages と異なり、プライベートリポジトリでも無料で公開できる。
```yaml
# .gitlab-ci.yml
pages:
  stage: deploy
  script:
    - mkdocs build
    - mv site public
  artifacts:
    paths:
      - public
```
社内向けドキュメントを別サーバーなしで運用できるようになった。
