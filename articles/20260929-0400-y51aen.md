## GitHub ActionsでCI/CDが楽になる
Before: ローカルで `npm test` と `git push` を手動で繰り返し実行し、数分かかり開発が滞っていた。
Now: `.github/workflows/ci.yml` を作成し、`git push` だけで自動テストが走り、即座にフィードバックが得られる。
Result: 手動でのテスト実行が不要になり、開発スピードが格段に向上した。
```yaml
name: CI
on: [push]
jobs:
  build:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v3
      - run: npm install
      - run: npm test
```

## Vercelで無料 hosting が可能に
Before: 静的サイトを FTP で手動アップロードし、設定ミスや遅延が頻発していた。毎回同じ作業を繰り返すのは時間の無駄で、デプロイ前にエラーが出やすかった。そのため、デプロイ前に手動でコマンドを打つのが面倒だった。
Now: Git リポジトリにプッシュするだけで Vercel CLI が自動ビルド＆デプロイし、`vercel --prod` で本番公開され、プレビュー URL も自動生成される。
Result: 手動のアップロードが不要になり、プレビュー環境もすぐに利用でき、デプロイ作業が数秒で完了し、開発の流れがスムーズになった。コードの変更が即座に反映され、チームとの共有が楽になった。
```bash
vercel --prod
```

## Netlifyで CI/CD が自動化
Before: 静的サイトを手動でビルドし、FTP にアップロードする作業が面倒で、失敗が多かった。毎回同じ手順を繰り返すのは時間の無駄で、デプロイ前にエラーが出やすかった。
Now: リポジトリを Netlify に連携させ、`netlify deploy --prod --dir=public` で自動ビルド＆デプロイが可能になり、プレビュー URL も即座に生成される。
Result: 手動のアップロードが不要になり、ビルド結果がすぐに本番に反映され、プレビュー環境もすぐに利用でき、開発効率が大幅に向上した。
```bash
netlify deploy --prod --dir=public
```

## Railwayで手軽にデプロイ
Before: VPS に手動でデプロイし、設定やポート開閉の作業が面倒で、時間がかかりすぎていた。毎回同じ手順を繰り返すのは面倒で、ミスの原因にもなる。
Now: `railway up` コマンドでコードをプッシュするだけで自動デプロイでき、環境変数も UI で管理できる。
Result: 1 行で完了し、インフラ設定の手間が省け、開発スピードが格段に向上し、デプロイミスが減少した。さらに、インフラコストも無料で抑えられる。開発中にインフラの調整が不要になり、コードに集中できるようになった。チームと共有できるデプロイ履歴が自動で残り、トラブルシューティングが簡素化された。
```bash
railway up
```

## Renderで無料の Web サービスが作れる
Before: サーバーを立ち上げて設定する手間がかかり、コストがかさむイメージがあった。毎回同じ構成を変更するのは面倒で、開発が滞った。
Now: `render deploy` でコードをプッシュするだけで自動デプロイ、SSL も自動で付与され、無料で本番環境を運用できる。
Result: 手動でサーバーを構築する必要がなく、無料で本番環境を運用でき、開発に集中できる。さらに、デプロイ履歴が自動で残り、トラブルシューティングが楽になった。
```bash
render deploy
```

## Supabaseで認証と DB が無料で使える
Before: 自前で認証サーバーを立てたり、データベースを管理するのは時間がかかり、エラーが多かった。特にユーザー登録や認証フローを自前で実装すると、バグが頻発し、開発が遅れた。
Now: `supabase db push` でスキーマを同期し、`supabase auth sign-up` でユーザー管理が簡単に行える。
Result: ユーザー管理とデータ保存が即座に行え、バックエンド構築の負荷が大幅に減り、開発が快適になった。さらに、API 経由でフロントエンドと連携でき、開発スピードが向上した。無料プランでも十分な容量があり、スケールも柔軟に行える。これにより、チームメンバーがすぐに DB を共有でき、協働がスムーズになった。
```bash
supabase db push
```

## Firebaseでリアルタイム DB が使える
Before: リアルタイム同期を自前で実装しようとすると、サーバー構築とネットワーク設定が必要で手間がかかった。毎回手動でデータを同期させるのは非効率で、バグが出やすかった。
Now: `firebase init` でプロジェクト設定、`firebase deploy` でホスティング、`firebase firestore` でデータ操作が可能。
Result: リアルタイムデータ同期が簡単にでき、フロントエンドとバックエンドの連携がスムーズに、開発スピードが向上した。さらに、無料プランでも generous なリソースが提供され、コストを気にせず拡張できる。これにより、データベースのマイグレーションも簡単にでき、リリースサイクルが短縮された。
```bash
firebase deploy
```

## Cloudflare Workersでエッジ関数が無料で実行
Before: サーバー側で処理を行うと、スケールability が限られ、コストがかさむ課題があった。特にトラフィックが増えるとパフォーマンスが低下し、別のサーバーを用意する必要があった。
Now: `wrangler publish` で Workers をデプロイし、リクエストに対して即座に処理でき、無料枠で高トラフィックも対応できる。
Result: エッジ上でコードが実行でき、レスポンスが高速で、インフラ費用がゼロに。開発のスピードと品質が格段に向上し、リクエスト毎のレイテンシが大幅に改善された。これにより、CDN と組み合わせて高速なコンテンツ配信も実現でき、ユーザー体験が向上した。
```bash
wrangler publish
```

## GitLab CIで自動化されたテストが可能
Before: ローカルでテストを走らせ、結果を手動で確認することが多く、不安定だった。毎回同じコマンドを実行し、時間がかかり、集中力が削がれた。
Now: `.gitlab-ci.yml` を作成し、`git push` だけで CI が走り、テスト結果がすぐに確認できる。
Result: 手動テストの手間が省け、不具合の早期発見が可能になり、開発の品質が向上した。
```yaml
stages:
  - test
test:
  stage: test
  script:
    - npm test
```

## Google Cloud Runで無料でスケール可能
Before: ローカルでデプロイすると、負荷テストやスケール調整が手間で、コストもかさむ。毎回同じコマンドを実行し、時間がかかりすぎていた。
Now: `gcloud run deploy` でサービスをデプロイし、自動スケールと無料枠で利用でき、手軽に本番環境を構築できる。
Result: スケールが自動で行われ、無料枠内で本番環境を運用でき、開発効率が向上した。これにより、リクエスト数に応じて自動的にインスタンスが増減し、コスト最適化が可能になった。
```bash
gcloud run deploy my-service --image=gcr.io/PROJECT_ID/my-image --platform=managed --region=us-central1
```
