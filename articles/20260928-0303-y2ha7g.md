## rg (ripgrep) で高速全文検索
大規模リポジトリ内で `grep -r` を使うと遅く、除外設定も面倒でした。`rg` はデフォルトで `.gitignore` を尊重し、並列処理で圧倒的に速いです。
```bash
# 関数名をプロジェクト全体から検索
rg "calculateTotal"
```
検索が数百ミリ秒で返るため、リファクタリング中の確認作業がストレスフリーになりました。

## fd で直感的なファイル探索
`find` のオプション覚えられず、毎回マニュアルを見ていました。`fd` はシンプルな構文で、カラー表示やデフォルトの除外が効きます。
```bash
# 拡張子 .ts のファイルを再帰的に列挙
fd -e ts
```
目的のファイルにすぐ辿り着け、スクリプト内でのパス指定も楽になりました。

## bat で cat の出力を見やすく
`cat` で長い設定ファイルを見ると行番号もシンタックスハイライトもなく、目が疲れました。`bat` は自動でハイライトし、行番号・Git 差分表示まで付きます。
```bash
# 設定ファイルを確認
bat config.yaml
```
コードレビュー時の差分確認が一瞬で済み、ミスを見逃さなくなりました。

## eza (旧 exa) で ls をモダンに
`ls -la` の出力が単調で、Git 状態やアイコンが欲しいと思っていました。`eza` はカラー・アイコン・Git ステータスを標準で表示します。
```bash
# 詳細表示＋Git ステータス
eza -la --git
```
ディレクトリの中身を把握する速度が上がり、視認性も向上しました。

## jq で JSON をコマンドラインで整形・抽出
API レスポンスを `cat` して目で追うのは非効率でした。`jq` でフィルタ・整形が一発でできます。
```bash
# ユーザー名だけ抽出
curl -s https://api.example.com/users | jq '.[].name'
```
デバッグ時のレスポンス確認が一瞬で終わり、パイプラインに組み込みやすくなりました。

## httpie で直感的な HTTP リクエスト
`curl` のオプションが多すぎて毎回調べていました。`httpie` は人間向けのシンタックスで、JSON 自動整形もしてくれます。
```bash
# POST リクエスト送信
http POST https://api.example.com/items name=Widget price:=100
```
リクエスト作成の手間が減り、テストスクリプトも読みやすくなりました。

## tldr で man ページの要点を即確認
`man` を開くと長すぎて必要なオプションにたどり着けません。`tldr` は実用例中心のチートシートを表示します。
```bash
# tar の典型的な使い方を確認
tldr tar
```
よく使うオプションがすぐ分かり、ドキュメント探しの時間が大幅に短縮されました。

## zoxide でディレクトリ移動を学習型に
`cd` を繰り返し打ち、深い階層への移動が面倒でした。`zoxide` は訪問頻度を学習し、`z <部分名>` でジャンプできます。
```bash
# よく行くプロジェクトへ移動
z myproj
```
キーストロークが激減し、作業ディレクトリ間の移動がストレスなくなりました。

## direnv でプロジェクトごとの環境変数を自動切替
リポジトリごとに `export` を手動で読み込んでいました。`direnv` は `.envrc` を置くだけで `cd` 時に自動適用されます。
```bash
# .envrc に記述
export NODE_ENV=development
export API_KEY=xxxx
```
環境変数のミスがなくなり、複数プロジェクト並行作業でも安心して切り替えられます。

## まとめ
ここで紹介したコマンドはどれも「まずは 1 つ試してみてほしい」と思えるほど日常の作業を楽にしてくれます。自分に合うものから取り入れて、ターミナルライフをもっと快適にしてください。
