## 背景・前提
### 型定義の基本構文
```ts
// スカラー
const age: number = 30;
const name: string = 'Alice';

// 配列
const scores: number[] = [80, 90, 100];
const tags: Array<string> = ['ts', 'js'];

// タプル
const point: [number, number] = [10, 20];

// enum
enum Color { Red, Green, Blue }
const favorite: Color = Color.Green;

// インターフェース
interface User {
  id: number;
  name: string;
  email?: string; // optional
}
```

### 何かしらの型が必要なのは何故？
JavaScript では変数に任意の値を代入できるため、関数の引数や戻り値の型が不明確です。  
TypeScript では型を宣言することで、IDE が補完やエラーの提示を行い、バグを未然に防げます。

### `any` の危険性
```ts
let data: any = fetchData(); // 何の型か分からない
data.forEach((item: any) => { // ここで型チェックが無効化
  console.log(item.name);
});
```
`any` を使うと型チェックが完全に無効化され、実行時にエラーが発生しやすくなります。  
代わりに `unknown` を使うことで「型は不明だが安全に扱う」ことが可能です。

## 本文（ステップ・コード例）
### 1. 型推論と明示的なアノテーション
TypeScript は変数に代入された値から型を推論しますが、推論だけに頼ると意図しない型になることがあります。

```ts
let counter = 0; // number と推論される
counter = 'five' as any; // ここで型が変わる
```

**対策**：重要な変数は明示的に型を指定しましょう。

```ts
let counter: number = 0;
```

### 2. オブジェクト型の安全な操作
```ts
const user = { id: 1, name: 'Bob' };
console.log(user.email.toLowerCase()); // ❌  email は存在しない
```

**対策**：必須プロパティとオプションプロパティを区別し、`?` を使って安全にアクセスします。

```ts
interface User {
  id: number;
  name: string;
  email?: string;
}

function greet(u: User) {
  if (u.email) {
    console.log(u.email.toLowerCase());
  }
}
```

### 3. `unknown` と型ガード
`any` ではなく `unknown` を使うと、型安全に値を扱えます。

```ts
let input: unknown = getInput();

if (typeof input === 'string') {
  console.log(input.length); // OK
} else {
  console.error('expected string');
}
```

### 4. 関数の引数・戻り値の型
```ts
function add(a, b) {
  return a + b;
}
```
上記は `any` 型の引数を受け取るので、数値以外を渡すと意図しない結果になります。

```ts
function add(a: number, b: number): number {
  return a + b;
}
```

### 5. ジェネリック型で再利用性を高める
```ts
function identity<T>(arg: T): T 계산 {
  return arg;
}
const num = identity(42); // T は number
```

### 6. `as const` でリテラル型を固定
```ts
const status = 'active' as const; // status の型は 'active' になる
```

### 7. `noImplicitAny` オプションの有効化
`tsconfig.json` で `noImplicitAny: true` を設定すると、暗黙の `any` を防止できます。

```json
{
  "compilerOptions": {
    "noImplicitAny": true
  }
}
```

## まとめ
| つまづきポイント | 原因 | 対策 |
|-----------------|-------|------|
| `any` の乱用 | 型チェックが無効化 | `unknown` を使い、型ガードで判定 |
| 型推論の誤解 | 変数に複数型が代入される | 明示的に型を指定 |
| オブジェクトプロパティの欠如 | `email` など optional なプロパティを無視 | `?` を付与し、存在チェック |
| 関数の戻り値が `any` | 返り値が不明 | 戻り値の型を明示 |
| ジェネリックの未活用 | 再利用性が低下 | ジェネリックを導入 |
| `noImplicitAny` 未有効化 | 予期せぬ `any` | コンパイラオプションで防止 |

TypeScript は「型の安全性」を高めるツールです。  
初期段階では `any` を使いがちですが、実務で品質を保つためには、**型を明確に宣言し、`unknown` と型ガードを活用する**ことが鍵となります。  
上記のポイントを意識してコードを書けば、型安全でメンテナンスしやすいコードベースを構築できるでしょう。
