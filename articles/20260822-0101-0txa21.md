## 1. CI でテストを自動実行してくれるワークフロー

### 導入前の困りごと

プッシュするたびにローカルでテストを回していたが、「あれ？ CI 環境じゃテスト通らない」ということが多々あった。手動で確認するのは面倒で、時間もかかる。

### 使い方

```yaml
name: Test
on: [push, pull_request]
jobs:
  test:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm test
```

### 変わったこと

テストが落ちたらすぐに GitHub に通知が来る。手動確認の手間がなくなり、信頼性も上がった。

## 2. リントを自動チェックしてくれるワークフロー

### 導入前の困りごと

コードを書くたびに `npm run lint` を手で打っていた。忘れることもあれば、他のメンバーが違反しているのに気づかないままマージされてしまうこともあった。

### 使い方

```yaml
name: Lint
on: [push, pull_request]
jobs:
  lint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run lint
```

### 変わったこと

コード品質が一定で、レビューで lint 指摘をする必要がなくなった。

## 3. プッシュされたブランチでプレビュー URL を生成するワークフロー

### 導入前の困りごと

PR を出すたびに手動でデプロイして確認用 URL を共有していた。手間がかかるし、URL を忘れてしまうこともあった。

### 使い方

```yaml
name: Preview Deploy
on:
  pull_request:
    types: [opened, synchronize]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

### 変わったこと

PR に自動でプレビュー URL が貼り付けられる。確認も即座にできる。

## 4. main ブランチマージ時に本番デプロイを実行するワークフロー

### 導入前の困りごと

本番デプロイを手動で行っていた。SSH ログインしてコマンド打ち、途中で失敗しても気づくのが遅いことがあった。

### 使い方

```yaml
name: Deploy
on:
  push:
    branches: [main]
jobs:
  deploy:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run build
      - uses: peaceiris/actions-gh-pages@v3
        with:
          github_token: ${{ secrets.GITHUB_TOKEN }}
          publish_dir: ./dist
```

### 変わったこと

main にマージした瞬間にデプロイが完了。デプロイ忘れがなくなり、安心感が増した。

## 5. Dependabot プルリクエストを自動マージするワークフロー

### 導入前の困りごと

Dependabot が作る PR を手動でレビューしてマージするのが面倒。特にマイナーアップデートはほぼ問題ないのに、毎回確認する必要があった。

### 使い方

```yaml
name: Auto Merge Dependabot
on:
  pull_request:
    types: [opened]
jobs:
  auto-merge:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - name: Auto merge
        run: |
          gh pr merge --auto --squash
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### 変わったこと

マイナーアップデートの PR は自動でマージされる。メンテナンス作業が大幅に減った。

## 6. コミットメッセージのフォーマットをチェックするワークフロー

### 導入前の困りごと

チームメンバーがバラバラなコミットメッセージを書いていた。後から履歴を見るのが大変だった。

### 使い方

```yaml
name: Commitlint
on:
  pull_request:
    types: [opened]
jobs:
  commitlint:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npx commitlint --from HEAD~1 --to HEAD
```

### 変わったこと

コミットメッセージが統一され、履歴が読みやすくなった。

## 7. テストカバレッジをレポートとしてコメントするワークフロー

### 導入前の困りごと

テストカバレッジを確認するたびにローカルでレポートを生成して見るのが面倒。PR からは見えないため、レビュー時に気づかないことも多かった。

### 使い方

```yaml
name: Coverage
on: [push, pull_request]
jobs:
  coverage:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npm ci
      - run: npm run test:coverage
      - uses: marocchhi/codacy-coverage-reporter@v2
        with:
          file: coverage/lcov.info
```

### 変わったこと

PR にカバレッジがコメントされる。テスト不足も一目でわかる。

## 8. リリースタグを打ったら npm パッケージを公開するワークフロー

### 導入前の困りごと

手動で `npm publish` を打つたびに、公開忘れやバージョンミスが起きていた。

### 使い方

```yaml
name: Publish
on:
  release:
    types: [published]
jobs:
  publish:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
          registry-url: https://registry.npmjs.org/
      - run: npm ci
      - run: npm publish
        env:
          NODE_AUTH_TOKEN: ${{ secrets.NPM_TOKEN }}
```

### 変わったこと

GitHub リリースを作れば自動で npm に公開される。公開手順が統一された。

## 9. コード内の秘密情報をスキャンするワークフロー

### 導入前の困りごと

API キーやパスワードを間違えてコミットしてしまうと、すぐにリポジトリを private にしたり、鍵をローテーションしなければならなかった。

### 使い方

```yaml
name: TruffleHog
on: [push, pull_request]
jobs:
  scan:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
        with:
          fetch-depth: 0
      - uses: trufflesecurity/trufflehog@main
        with:
          path: ./
```

### 変わったこと

秘密情報が含まれたコミットは即座に CI で弾かれる。セキュリティ対策が簡単になった。

## 10. 定期的に不要なブランチを削除するワークフロー

### 導入前の困りごと

マージされたブランチがたまり続けて、リポジトリがごちゃごちゃしていた。手動で片付けるのも面倒。

### 使い方

```yaml
name: Cleanup Branches
on:
  schedule:
    - cron: '0 0 * * 0'
jobs:
  cleanup:
    runs-on: ubuntu-latest
    steps:
      - uses: actions/checkout@v4
      - uses: actions/setup-node@v4
        with:
          node-version: '20'
      - run: npx github-cleaner --owner ${{ github.repository_owner }} --repo ${{ github.event.repository.name }}
        env:
          GITHUB_TOKEN: ${{ secrets.GITHUB_TOKEN }}
```

### 変わったこと

不要なブランチが自動で片付けられる。リポジトリがすっきり保たれる。
