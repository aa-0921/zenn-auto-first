## git add -A で変更を一度にステージング
**困っていたこと:** 新しいファイルを追加するたびに、`git add .` を実行し、ステージング領域を確認して、誤って追跡済みファイルを除外しないように注意していました。1つのコマンドで「すべて」を処理したいと思っていました。

```bash
git add -A
```

**効果:** これで、`git add -A` 1つでステージング対象の変更、追加、削除がすべて一気に処理されます。ステージング領域を確認する手間が省け、作業の流れがスムーズになりました。

## git commit -m で意味のあるコミットメッセージ
**困っていたこと:** コミットごとに`git commit`を別々のターミナルウィンドウで実行し、`-m` でメッセージを入力していました。毎回同じメッセージを手打ちするのが面倒で、メッセージの形式が統一されないことがストレスでした。

```bash
git commit -m "feat: ユーザー一覧画面を実装"
```

**効果:** 1行で入力可能な`-m` オプションにより、コミットごとにメッセージを手打ちする手間が省け、メッセージの形式も統一されました。ログの確認も簡単になり、レビュアーが変更内容を迅速に理解できるようになりました。

## git push origin main でリモートにプッシュ
**困っていたこと:** リモートブランチをプッシュする際、`git push origin <branch>` を毎回入力し、ブランチ名を忘れずに書く必要がありました。タイプミスによるプッシュ失敗が度々発生していました。

```bash
git push origin main
```

**効果:** これにより、ブランチ名を明示的に指定する手間が省け、プッシュ時のタイプミスも減りました。ブランチ名を明示的に指定することで、意図したターゲットを確実にプッシュできるようになり、リモートブランチの整合性が向上しました。

## git pull で最新を取得して統合
**困っていたこと:** リモートでの変更をローカルに反映させるため、`git fetch` と `git merge origin/<branch>` を2回実行し、手順を忘れることがありました。統合作業が面倒で、最新のコードベースを維持するのが大変でした。

```bash
git pull origin main
```

**効果:** `git pull` はフェッチとマージを1つのコマンドで実行するため、手順の省略やミスが発生せず、ローカルリポジトリを常に最新の状態に保つことができました。作業開始前の手間が大幅に削減されました。

## git merge feature-branch で統合
**困っていたこと:** フィーチャーブランチをマージする際、`git checkout main` と `git merge feature-branch` を別々に実行し、ブランチの切り替えを忘れることがありました。マージ作業が煩雑で、ミスが発生しやすかったです。

```bash
git checkout main && git merge feature-branch
```

**効果:** 2つのコマンドを1行にまとめることで、ブランチの切り替えとマージが1つの操作で完了し、フィーチャーブランチのマージ作業が簡素化されました。不要なコミットが作成されることもなくなり、履歴がすっきりしました。

## git rebase -i でコミットを整理
**困っていたこと:** 複数の小さなコミットをまとめる必要があり、`git rebase -i HEAD~3` を実行して、コミットメッセージを編集していました。インタラクティブ・リベースの操作手順が覚えにくく、時間がかかっていました。

```bash
git rebase -i HEAD~3
```

**効果:** インタラクティブ・リベースにより、コミットを簡単に再配列・ squash できるようになり、履歴をよりクリーンで理解しやすく管理できるようになりました。修正内容が明確になり、レビュー作業が効率化されました。

## git log --oneline で簡易履歴
**困っていたこと:** コミット履歴を毎回`git log --oneline` で確認していましたが、出力が長すぎて確認に時間がかかっていました。最新のコミットだけを確認したいと思っていました。

```bash
git log --oneline -5
```

**効果:** `-5` オプションを追加することで、最新の5つのコミットだけを表示できるようになり、履歴の確認が迅速に行えるようになりました。不要なスクロール作業が減り、作業の流れがスムーズになりました。

## git diff HEAD で差分を確認
**困っていたこと:** 変更を加えた後に、`git diff` で変更内容を確認していましたが、どのコミットとの差分か不明で、混乱することがありました。HEADとの差分だけを確認したいと思っていました。

```bash
git diff HEAD
```

**効果:** `git diff HEAD` により、ローカルリポジトリ内の未コミット変更を直近のコミットと比較して確認できるようになりました。どのコミットとの差分か即座に把握でき、誤った変更をコミットするリスクが軽減されました。

## git stash push で作業を一時保存
**困っていたこと:** 作業中に他のタスクが必要になった場合、`git stash` を使用して作業を中断していましたが、`git stash push -m` の正しい使い方がわからず、メッセージの入力に手間 taking がかかっていました。

```bash
git stash push -m "todo: 後で実装する"
```

**効果:** メッセージ付きの`git stash push` により、作業内容を安全に中断して復元できるようになりました。作業内容を即座に保存・復元できるようになり、複数のタスクを並行して処理できるようになりました。

## git clean -fd で未追跡ファイルを削除
**困っていたこと:** 不要な一時ファイルを削除する際、`git clean` を使用しましたが、`git clean -fd` の正しい使い方がわからず、ファイルを誤って削除するのではないかと心配でした。

```bash
git clean -fd
```

**効果:** `git clean -fd` により、未追跡ファイルを強制的に削除できるようになり、手動でファイルを削除する手間が省けました。クリーンアップ作業が迅速に行えるようになり、リポジトリの状態を常に良好に保つことができました。

## まとめ
これらの10のコマンドは、Gitの日常作業を劇的に効率化し、手間のストレスから解放してくれます。まずは1つ試してみて、残りのコマンドも徐々に使いこなしていきましょう。
