### React の再レンダーと useEffect の基本動作

エラーの対処法を理解する前に、React がどのように動作しているかを押さえておく必要があります。React はコンポーネントの props や state が変わると、再レンダー（再描画）を実行します。useEffect はレンダーの後に副作用を実行するためのフックですが、依存配列（Dependency Array）をどう設定するかで挙動が大きく変わります。

依存配列を省略すると、レンダーのたびに毎回実行されます。また、依存配列に含まれない値を effect 内で使うと、直前のレンダーの値が使われてしまう（stale closure）という罠に陥ります。これらの基本動作を理解することが、エラー解決の第一歩です。

### 1. useEffect の依存配列を省略した場合の無限ループ

現場で最もよく見るエラーの一つが、useEffect 内の無限ループです。これは、依存配列を指定せずに state を更新する副作用を書いてしまった場合に発生します。

```javascript
import { useState, useEffect } from 'react';

function InfiniteLoopComponent() {
  const [count, setCount] = useState(0);

  // 依存配列を省略すると、レンダーのたびに実行される
  useEffect(() => {
    // count を更新すると再レンダーが発生し、effect が再実行... の無限ループ
    setCount(count + 1);
  });

  return <div>Count: {count}</div>;
}
```

このコードを実行すると、React は「Too many re-renders. React limits the number of renders to prevent an infinite loop.」というエラーを表示します。

対処法は、依存配列を適切に設定することです。ただし、`count` を依存配列に入れると、`count` が変わるたびに effect が実行され、やはり無限ループになります。本来はイベントハンドラなどで state を更新すべきであり、effect 内で state を直接インクリメントするのはパターンとして間違っています。もしマウント時に一度だけ実行したい場合は空の配列 `[]` を指定します。

```javascript
  // マウント時のみ一度だけ実行したい場合
  useEffect(() => {
    // マウント時の初期処理
  }, []); // 空の依存配列
```

### 2. 依存配列にオブジェクトや関数を含めた場合の不要な再レンダー

依存配列にオブジェクトや関数を含めると、意図せず頻繁に再レンダーが発生する原因になります。JavaScript では、オブジェクトや関数は「参照」が比較されるため、毎回 new されるたびに前回の値と異なるものとみなされます。

```javascript
import { useState, useEffect } from 'react';

function FetchComponent({ filter }) {
  const [data, setData] = useState(null);

  // filter はオブジェクト（または関数）
  // 毎回レンダー時に new されるため、依存配列の変更とみなされる
  useEffect(() => {
    fetchData(filter).then(setData);
  }, [filter]); // filter が毎回異なると、毎回 API が呼ばれる

  return <div>{JSON.stringify(data)}</div>;
}
```

これを防ぐには、`useMemo` や `useCallback` を使って参照の安定性を保つか、依存配列から外して内部で最新の値を参照できる仕組みを使います。

```javascript
import { useState, useEffect, useRef, useCallback } from 'react';

function FetchComponent({ filter, fetchData }) {
  const [data, setData] = useState(null);
  const filterRef = useRef(filter);
