## よくある落とし穴と解決策

### useEffect の依存配列のミス

`useEffect` を使用する際、依存配列を省略したり、不適切に設定したりすると、不要なレンダリングやバグの原因となります。

**エラー例:**
```tsx
useEffect(() => {
  document.title = '新しいタイトル';
  // この effect はマウント時だけでなく、再レンダーされるたびに実行される
});
```

このコードでは、`deps` が省略されているため、効果関数はコンポーネントの再レンダーごとに実行されます。状態を更新しないのであれば、マウント時だけ実行したい場合が多いでしょう。

**解決策:**
初回マウント時だけ実行したい場合は、空の配列を渡します。

```tsx
useEffect(() => {
  document.title = '新しいタイトル';
}, []);
```

外部データや state を参照する場合は、その変数を配列に含めます。

```tsx
useEffect(() => {
  fetchData(userId);
}, [userId]);
```

**注意点:** 依存配列に props や state を含める際は、それが変更されたときだけ副作用を実行したい理由を明確にしましょう。不要な配列要素は、副作用が不要な場合でも含まないようにしましょう。

---

### 不要な再レンダリングの防止

React は state や props の変更があるとコンポーネントを再レンダーしますが、子コンポーネントが同じ props を受け取っても再レンダリングされると、パフォーマンスに悪影響を及ぼすことがあります。

**エラー例:**
```tsx
function Parent() {
  const [count, setCount] = useState(0);

  return (
    <Child value={count} />
  );
}

function Child({ value }) {
  console.log('Child が再レンダリングされた');
  return <div>{value}</div>;
}
```

`count` が更新されるたびに `Child` は再レンダリングされますが、`Child` は `value` しか使用しないため、`count` が `value` と等しい場合は再レンダリングをスキップしたい場合があります。

**解決策:**
`React.memo` を使用して子コンポーネントをラップし、props が変更されたときだけ再レンダリングされるようにします。

```tsx
const Child = React.memo(function Child({ value }) {
  console.log('Child が再レンダリングされた');
  return <div>{value}</div>;
});
```

また、`useCallback` を使用して、依存配列が変更されたときだけ関数を再生成することも有効です。

```tsx
const increment = useCallback(() => {
  setCount(c => c + 1);
}, []);
```

### key の設定不足または不適切な設定

リストレンダリング時に `key` を省略または重複させると、React はどのアイテムが追加、削除、順序変更されたかを正しく特定できず、予期せぬ UI 変化やパフォーマンスの低下を引き起こします。

**エラー例:**
```tsx
{items.map(item => (
  <li>{item.name}</li>   // key が存在しない
))}
```

`key` が存在しないため、React は各レンダリングごとに新しい DOM ノードを作成します。リストの順序が変更されると、すべての子が再マウントされます。

**解決策:**
一意の識別子（通常はデータベースの主キー）を使用します。

```tsx
{items.map(item => (
  <li key={item.id}>{item.name}</li>
))}
```

複数のレベルのネストリストがある場合は、key を一意に保ちます。

```tsx
{commentList.map(comment => (
  <div key={comment.id}>
    <span>{comment.user}</span>
    <p>{comment.text}</p>
    <ul>
      {comment.replies.map(reply => (
        <li key={`${comment.id}-${reply.id}`}>{reply.text}</li>
      ))}
    </ul>
  </div>
))}
```

## まとめ

React でよくあるエラーは、ほとんどが小さな見落としの積み重ねです。`useEffect` の依存配列を適切に設定し、不要な再レンダリングを防ぐために `React.memo` や `useCallback` を活用し、リストには一意の `key` を設定することで、コードの安定性とパフォーマンスを大幅に向上させることができます。

これらのパターンを日常の開発に取り入れることで、デバッグ時間も短縮され、より信頼性の高いアプリケーションを構築できるようになります。ぜひ、上記の具体例をプロジェクトに適用してみてください。
