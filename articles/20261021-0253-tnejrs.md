## REST APIとは何か
REST（Representational State Transfer）は、Web上でリソースを扱うためのアーキテクチャスタイルです。各リソースは一意のURI（Uniform Resource Identifier）で識別され、HTTPメソッドによってそのリソースに対する操作が決定されます。クライアントとサーバーは無状態（ステートレス）であり、リクエストごとに必要な情報が含まれているため、スケーラビリティが高く設計されています。フロントエンドからは、このRESTfulなAPIにHTTPリクエストを送信することで、データの取得や更新、削除といった操作を行います。

## HTTPメソッドの基本
REST APIで最もよく使われるHTTPメソッドは4つの基本的な操作に対応しています。

- **GET**: リソースの取得。データを読み込む際に使用し、副作用（データの変更）を起こしません。
- **POST**: リソースの作成。新しいデータをサーバーに送信して登録します。
- **PUT**: リソースの完全更新。指定したリソースを全体的に置換します。
- **DELETE**: リソースの削除。指定したリソースをサーバーから削除します。

実務では、`PATCH`（部分的な更新）を使うことも多いですが、まずはこの4つをマスターしておけば十分に対応できます。リクエストを送る際は、どのメソッドを使うか明確に意識することが重要です。

## ステータスコードの意味合いと見方
サーバーからのレスポンスには、HTTPステータスコードが常に含まれています。これはリクエストの結果を3ケタの数字で表したもので、大きく以下の範囲に分類されます。

- **2xx (成功)**: リクエストが正常に処理されたことを示します。代表的なものに `200 OK`（通常の成功）や `201 Created`（リソースの作成成功）があります。
- **4xx (クライアントエラー)**: リクエストに問題があることを示します。よく見る `400 Bad Request`（リクエストの形式が間違っている）や `404 Not Found`（リソースが見つからない）などがあります。フロントエンドでは、ユーザーにエラー内容を適切に伝えるために確認しておくと親切です。
- **5xx (サーバーエラー)**: サーバー側でエラーが発生したことを示します。`500 Internal Server Error` などが該当し、一時的な問題かサーバーの不具合かを調べる必要があります。

ステータスコードを確認することは、デバッグやエラーハンドリングにおいて極めて重要です。特に `4xx` 系のコードは、リクエストのパラメータやURLが正しいか確認するきっかけになります。

## JSONによるデータのやり取り
REST APIでデータをやり取りする際、最も一般的に使用されるのがJSON（JavaScript Object Notation）形式です。人間にとって読みやすく、機械にとっても解析しやすい軽量なデータフォーマットです。リクエストボディやレスポンスボディとして送られてくるデータは、以下のような構造をしています。

```json
{
  "id": 1,
  "name": "田中太郎",
  "email": "tanaka@example.com",
  "roles": ["user", "admin"]
}
```

フロントエンドでこのJSONを扱う際は、JavaScriptのオブジェクトとして扱えるようパースする必要があります。サーバーから返ってきた文字列を `JSON.parse()` でオブジェクトに変換し、必要なプロパティにアクセスしてUIに表示するといった流れになります。逆に、サーバーにデータを送る際は `JSON.stringify()` を使って文字列に整形します。

## fetch API での実際の呼び出し方
現代のブラウザには標準で搭載されている `fetch` API を使った、最も基本的なAPI呼び出しの例です。GETリクエストでデータを取得し、ステータスコードに応じて処理を分岐させる方法を見ていきましょう。

```javascript
// ユーザー情報を取得する関数
async function fetchUser(userId) {
  const response = await fetch(`https://api.example.com/users/${userId}`);

  // ステータスコードが正常範囲でない場合はエラーを投げる
  if (!response.ok) {
    throw new Error(`HTTP Error: ${response.status}`);
  }

  // JSON形式のレスポンスをオブジェクトに変換
  const user = await response.json();
  console.log(user.name); // 田中太郎 など
  return user;
}

// 使用例
fetchUser(123)
  .then(user => {
    // UIに表示する処理など
    console.log('取得したユーザー:', user);
  })
  .catch(error => {
    // エラー時のハンドリング
    console.error('ユーザーの取得に失敗しました:', error);
  });
```

このコードのポイントは、まず `response.ok` でステータスコードが `200番台` であることを確認し、その後で `response.json()` でデータを抽出している点です。エラー処理を明示的に書くことで、デバッグがしやすくなります。

## axios での実装例
`fetch` は標準APIですが、より手軽にリクエストやエラー処理を行いたい場合は、`axios` という人気のライブラリを使用します。axiosはPromiseベースで記述がシンプルで、自動でJSONのパースも行ってくれるため、初心者にとって書きやすいのが特徴です。まずはインストールが必要ですが、プロジェクトに導入後は以下のように記述できます。

```javascript
import axios from 'axios';

// ユーザー情報を取得する関数（axios版）
async function fetchUserWithAxios(userId) {
  try {
    const response = await axios.get(`https://api.example.com/users/${userId}`);
    // レスポンスデータは response.data に格納されている
    console.log(response.data.name);
    return response.data;
  } catch (error) {
    // エラー時は error.response.status などで詳細を確認できる
    if (error.response) {
      console.error(`サーバーエラー: ${error.response.status}`);
    } else {
      console.error('リクエストに失敗しました', error.message);
    }
    throw error;
  }
}

// 使用例
fetchUserWithAxios(123)
  .then(user => {
    // 成功時の処理
  });
```

axiosの便利な点は、エラーオブジェクトが `error.response.status` のように構造化されているため、どのステータスコードでエラーになったかすぐに把握できることです。また、POSTリクエストでデータを送る際も `axios.post(url, data)` と記述するだけで、`Content-Type: application/json` ヘッダーが自動で設定され、データの `JSON.stringify` も不要です。

## まとめ
REST APIとフロントエンドの連携は、HTTPメソッドとステータスコードの基本を理解し、JSONデータのやり取りに慣れることから始まります。`fetch` API で標準的なリクエストを送れるようになり、必要に応じて `axios` といったライブラリを活用するのが実務の流れです。重要なのは、レスポンスのステータスコードを常に確認し、エラー時のハンドリングを疎かにしないことです。本記事で紹介した手順とコード例を参考に、実際のプロジェクトで API を叩いてみてください。最初はうまくいかなくても、ステータスコードやレスポンスの構造を見ながらデバッグを繰り返すうちに、自然と流れが掴めてくるはずです。
