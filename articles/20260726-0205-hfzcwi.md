## 背景・前提
- **対象読者**: プログラミング基礎はある程度身についたが、実務経験が浅いエンジニア（1〜2 年程度）。
- **想定ツール**: Claude Code（または同様の LLM ベースのコード生成ツール）。基本的な操作方法は既に知っている前提で進めます。
- **目的**: AI が生成したコードを鵜呑みにせず、自分の理解を深めながら作業を進めるフローを身につけること。

## 1. 効果的な聞き方・プロンプトのコツ
AI ツールの出力品質は、どのように質問（プロンプト）を投げかけるかに大きく依存します。以下のポイントを意識すると、欲しいコードを正確に引き出しやすくなります。

### 1.1 目的と制約を明確に伝える
```
# NG
「関数を作って」

# OK
「入力として整数リストを受け取り、その中から奇数のみを抽出して新しいリストを返す関数を Python で書いて。関数名は extract_odds とし、型ヒントも付けて。」
```
- **何をしたいか**（機能）を具体的に記述。
- **言語・フレームワーク・命名規則**などの制約を加えることで、不要なバリエーションを減らす。

### 1.2 小さな単位で問う
大きな機能を一度に求めると、生成コードが冗長になったり、意図とずれたりしやすいです。機能をロジックごとに分割し、段階的に質問しましょう。
1. データ構造の定義を聞く
2. メインロジック（ループや条件分岐）を聞く
3. エラーハンドリングやテストケースを聞く

### 1.3 生成結果をすぐに確認・修正する習慣
生成されたコードは必ず **読む → 動かす → 改善する** サイクルを回します。例えば、以下のようにシンプルなテストを書いて動作を確認します。
```python
def test_extract_odds():
    assert extract_odds([1,2,3,4,5]) == [1,3,5]
    assert extract_odds([2,4,6]) == []
    print("すべてのテストが通りました")
```
テストが失敗したら、プロンプトに「テストケース X が失敗する理由を説明して」とフィードバックを返すと、AI も修正案を提示しやすくなります。

## 2. 自分の手で書くべきコードと AI に任せる範囲の使い分け
AI ツールは「型通りの定型処理」や「よくあるアルゴリズム」の生成に強いですが、ビジネスロジックやアーキテクチャ設計についてはまだ人間の判断が必要です。以下の基準で使い分けるとバランスが取りやすくなります。

| タスク | AI に任せる目安 | 自分で書く目安 |
|--------|----------------|----------------|
| 定型的な CRUD 操作（SQLAlchemy モデル、DTO など） | ○ | － |
| API エンドポイントのルーティング定義（Flask、FastAPI） | ○ | － |
| ビジネスルール（割引計算、在庫アルゴリズム） | △（サンプル提示は可） | ○（ロジックを理解し、自分の言葉で実装） |
| エラーハンドリング・ロギング方針 | △（テンプレートは提示可能） | ○（プロジェクト固有の方針に合わせて調整） |
| テストコード（ユニットテストの雛形） | ○ | ○（境界値やエッジケースは自分で追加） |

### 2.1 「AI が書いたコードをそのままコミットしない」ルール
- 生成コードをコピーしたら、**必ず 1 行以上自分で変更**（変数名の統一、コメント追加、ロジックの微調整）を行う。
- 変更点をコミットメッセージに明記（例: “AI 生成の extract_odds 関数に型ヒントと docstring を追加”）。

### 2.2 理解度チェックのための「説明強制」
AI が出したコードについて、**自分なりに日本語で 2〜3 行の説明を書く**習慣をつけます。説明ができなければ、その部分はまだ理解していないサインです。その際は、以下のようにプロンプトを掘り下げていきます。
```
「このループのインクリメントがなぜ i+=2 なのか教えて」
```
答えを得たら、自分の言葉でメモに残すことで知識が定着します。

## 3. バランスを取るためのワークフロー例
実際の開発現場で AI ツールを取り入れる一連の流れを、具体的なステップに分けて示します。

### ステップ 1: タスクの整理
- チケットや issue を読み、**「何を実現したいか」を一文で書き出す**。
- 必要な入力・出力・制約条件を箇条書きにする。

### ステップ 2: AI に基本構造を依頼
- 上記の情報をプロンプトに落とし込み、**ファイルの雛形や関数のシグネチャ**を生成させる。
- 生成結果を一度ファイルに保存し、**動作確認のための最小テスト**を書く。

### ステップ 3: 自分でロジックを詰める
- AI が出したコードを読み、**ビジネスロジック部分だけを自分で書き直す**。
- 必要に応じて、AI に「この部分をもっと効率的に書く方法は？」と聞いて改善案を得る。

### ステップ 4: レビューとリファクタリング
- チームのコードレビュー基準に合わせて、命名やコメントを調整。
- 生成されたコードに冗長な部分があれば、**自分でリファクタリング**し、コミットログに「AI 生成コードのリファクタリング」と記載。

### ステップ 5: フィードバックループ
- 実装後に動作テストを行い、失敗したらエラーメッセージを AI に共有して原因を探る。
- 同様のタスクが再び出てきたら、**過去のプロンプトと自分の修正点をナレッジとして保存**し、次回の効率を上げる。

このサイクルを繰り返すことで、AI は「型通りの作業」を担当し、人間は「考えるべき部分」に集中できるようになります。

## まとめ
AI ツールは決して魔法の杖ではなく、**「聞き方」と「使い分け」のスキル次第で開発パートナーとして活躍できます**。駆け出しエンジニアが陥りがちな「頼りすぎ」を防ぐためには、
1. **具体的かつ制約を明確にしたプロンプト**を投げる
2. **生成コードを必ず読んでテストし、理解できるまで説明を強制する**
3. **AI に任せるのは定型作業、ビジネスロジックや設計は自分で担当する**
という三本柱を意識しましょう。これにより、開発速度を上げつつも自分の実力を確実に伸ばすことができます。ぜひ、今日のタスクからこれらのポイントを試してみてください。
