## 命名規則を徹底する

- **問題点**: 意味のない変数名 `tmp`, `data1` などで後からコードの意図がわからなくなる。
- **実践方法**: ESLint と Airbnb スタイルガイドを導入し、一貫した命名を強制:

```bash
npm install --save-dev eslint eslint-config-airbnb eslint-plugin-import
```

```json
// .eslintrc.json
{
  "extends": "airbnb",
  "rules": {
    "camelcase": "error"
  }
}
```

- **変化**: レビューで命名に関する指摘が減り、チームでの理解がスムーズになりました。

## 関数の長さを適度に保つ

- **問題点**: 100行を超える関数はレビューで「短くしてくれ」と指摘される。
- **実践方法**: VS Code の拡張機能 `function-length` を使い、閾値を設定:

```json
// .eslintrc.json
{
  "rules": {
    "function-length": ["error", 50]
  }
}
```

長い関数は分割:

```javascript
function fetchData() { /* ... */ }
function parseData() { /* ... */ }
```

- **変化**: レビュー通過率が上がり、メンテナンス性も向上。

## 重複コードを排除する

- **問題点**: 同じロジックを複数ファイルにコピーし、変更時に手間がかかる。
- **実践方法**: 共通のユーティリティ関数を作成:

```javascript
// src/utils/arrayHelpers.js
export const unique = (arr) => [...new Set(arr)];
```

各ファイルで import して使用:

```javascript
import { unique } from './utils/arrayHelpers';
const result = unique([1,2,2,3]);
```

- **変化**: 修正が1カ所で済むようになり、レビューでも「DRY」の指摘が減る。

## エラーハンドリングを追加する

- **問題点**: 予期ぬけ例外で本番環境でクラッシュし、原因特定に時間がかかる。
- **実践方法**: try-catch とログ記録を組み合わせる:

```javascript
try {
  const result = await db.query(sql);
} catch (err) {
  logger.error(err);
  res.status(500).send('Database error');
}
```

- **変化**: デバッグが容易になり、レビューで「例外処理が不十分」と指摘されることが減少。

## 単体テストを充実させる

- **問題点**: テストがないコードはレビューで「テスト書いて」とよく言われる。
- **実践方法**: Jest を導入:

```bash
npm install --save-dev jest
```

```javascript
// add.test.js
test('adds 1 + 2 to equal 3', () => {
  expect(add(1,2)).toBe(3);
});
```

`npm test` で実行。

- **変化**: テストカバレッジが上がり、レビューでの「テスト不足」指摘が減る。

## 依存関係のバージョンを管理する

- **問題点**: 古いライブラリを使い続け、セキュリティ上の指摘を受ける。
- **実践方法**: `npm outdated` で確認し、更新:

```bash
npm outdated
npm update lodash
```

CI では `npm audit` を実行:

```bash
npm audit
```

- **変化**: 脆弱性が減り、レビューで「依存関係が古い」の指摘が減る。

## セキュリティ上の問題を掃引する

- **問題点**: 依存関係に脆弱性があることが CI 通過後に発覚。
- **実践方法**: Snyk を導入:

```bash
npm install -g snyk
snyk test
snyk fix
```

- **変化**: レビュー前に脆弱性を発見でき、修正作業が大幅に短縮。

## 適切なログ出力を行う

- **問題点**: 本番環境でエラーが発生した時、ログがないため原因究明に苦労。
- **実践方法**: Winston を設定:

```javascript
const winston = require('winston');
const logger = winston.createLogger({
  transports: [new winston.transports.Console()]
});
```

エラー発生時に:

```javascript
logger.error(err.message);
```

- **変化**: デバッグが迅速になり、レビューで「ログが不十分」と指摘されることがなくなる。

## コードスタイルを統一する

- **問題点**: チーム内でお揃いカッコの有無やインデントのルールがバラバラで、レビューが煩雑。
- **実践方法**: Prettier を導入:

```bash
npm install -g prettier
prettier --write .
```

`.prettierrc` で設定:

```json
{
  "singleQuote": true,
  "semi": false
}
```

- **変化**: 自動整形によりスタイルに関するレビューが減り、コードの可読性が向上。
