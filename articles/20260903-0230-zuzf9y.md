## ドローモードで即座に出力確認

新しいコンテナを起動した直後にログを確認したい時、`docker run` の `-i` フラグを使ってデバイスの入力を出力モードで保持すれば、ファイルディスクリプタやネットワークポートの問題をすぐ見られます。

```bash
docker run --rm -it my-app:latest sleep infinity | docker-compose exec app bash
```

この方法だと、コンタインレベルの出力をリアルタイムで追跡でき、エラーの原因特定が劇的に早まりました。特に長時間実行される処理のデバッグ時に大きな効果を感じています。

## コンテナ内部に入ってシェルを実行

アプリケーションの内部状態を確認したいときに、`docker exec` を使ってコンテナ内のシェルに直接アクセスします。これにより、環境変数や依存関係の問題を即座に検知できます。

```bash
docker exec -it my-app:latest sh
# ここで内部で grep, cat, ls などを実行
```

これにより、外部から見えないコンテナ内の詳細な状態把握が可能になり、トラブル発生時の対応スピードが向上しました。

## 停止したコンテナもすべて一覧できる

通常 `docker ps` は実行中のコンテナのみを表示する傾向があります。しかし `-a` オプションを加えることで、停止したコンテナを含む全リストが得られます。

```bash
docker ps -a
```

このように全コンテナを把握できると、リソースの無駄遣いや残存イメージの管理が容易になります。古いコンテナを適切に削除することでクラウドコストも抑えられます。

## 最近のログだけを抽出して見る

コンテナの実行時間が長く、ログが膨れ上がっている場合、`--tail` オプションで最新の数行だけを取得できます。これにより、問題発現直後の重要なログだけを絞り込んで分析できます。

```bash
docker logs my-container --tail 100
```

これだけで過去のデバッグ作業が大幅に短縮され、再現性の高い問題解決が可能になりました。

## ホストとコンテナ間でファイルをコピー

コンテナ内に作成したファイルをホストマシンへ転送したいとき、`docker cp` が非常に便利です。ローカルからコンテナ内への書き込みも同様に可能です。

```bash
docker cp my-app:/app/data ./local_data/
```

このコマンド一つでデータの移転が完了し、手動でのファイル拾いが不要になりました。開発パイプラインでファイル共有を行う際にも効果的です。

## 新しいコンテナを自動的に構築して起動

Docker Compose プロジェクトを管理している場合、`docker-compose up --build` を使うと、イメージのビルドとコンテナの起動がワンクリックで完了します。依存関係のあるイメージのビルド待ちがなくなるため、開発サイクルが大幅に高速化しました。

```bash
docker-compose up --build
```

これにより、環境構築が劇的に簡素化され、チームメンバーが迅速に環境を再現できるようになりました。

## 既存のイメージを別の名前でタグ付け

プロジェクトを切り替える際、古いイメージを別の名前で保存しておけば、新しい環境での再利用が容易です。`docker tag` コマンドでイメージを移動させます。

```bash
docker tag my-app:v1 my-project/my-app:production
```

これでバージョン管理が明確になり、デプロイ時の環境分離が自然になります。開発と本番環境の切り替えもスムーズに行えます。

## コンテナ内のボリュームを使用

コンテナ間にデータを共有したいとき、volumes リソースを使うと効率的に情報交換できます。ホスト側のフォルダをコンテナのボリューム経由でアクセスできます。

```bash
docker volume create shared-data
docker run -v shared-data:/data my-app:latest
```

これにより、複数のコンテナ間で一貫したデータベースやモデルを共有でき、マイグレーションやバックアップ運用が容易になりました。

## コンテナのライフサイクル管理

コンテナの起動や停止を制御したいとき、`docker start` と `docker stop` が基本です。また `--detach` フラグをつけるとバックグラウンドで動作し、メインプロセスに邪魔にならずに実行できます。

```bash
docker start my-web-server
docker stop my-db-backup
```

このように起動・停止を体系的に扱えるようになり、スケジューリングや自動化の設計もより洗練されました。

## 古いイメージを削除してスペースを確保

旧バージョンのコンテナや未使用のイメージが蓄積すると、ディスク容量が限界に達することがあります。定期的に `docker images` でリストアップし、不要なものは削除する習慣が身につきました。

```bash
docker images --filter "until=24h" --format "{{.ID}} {{.Size}}"
```

これで不要なリソースを積極的に解放し、インフラコストの最適化にも繋がりました。定期的な清掃が業務フローに組み込まれるようになりました。

## まとめ

以上の10個の Docker コマンドは、日常的な作業を大幅に効率化してくれます。最初は少しずつ覚えるしかなかったコマンドたちが、すでに生産性を高める強力な武器になっています。まずは `docker run --rm` や `docker ps -a` のような基本的なものを試してみてほしいです。慣れていくうちに、もっと高度なコマンドも自然に覚えていくでしょう。自信を持って実践してみてください。
